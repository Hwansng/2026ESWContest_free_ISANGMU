## 2. ACT 추론 지연 벤치마크 — 결과

더미 가중치, lerobot 0.6.0 기준. 카메라 2대(wrist/front) 관측 구성 가정, `chunk_size=100`.

| 해상도 | 평균 지연 | P95 | `get_throttled` | 판정 |
|---|---:|---:|---|---|
| 640×480 | 2.391초 | 2.444초 | `0x0` | ⚠ **RPi 성능 부족 확정** (전원 탓 아님) |
| 224×224 | 0.509초 | 0.557초 | `0x0` | ✅ **합격 확정, 재측정 불필요** |

- 정책 2개 동시 상주 시 메모리(RSS) 증가분: **약 201.5MB** (문서상 예상치 414MB보다 적음, 8GB RAM 기준 여유 충분)
- 🔵 **결론: 224×224 해상도로 확정하면 별도 최적화(ONNX/양자화) 없이 목표(<1초) 달성.**
  단, 해상도 하향은 성공률과 트레이드오프이므로 학습된 정책 확보 후 성공률과 함께 재확인 필요
- 5V 3A 어댑터 상태에서 측정, `throttled=0x0`이므로 문서 §2-1 해석 매트릭스상 **두 해상도 모두 결론이 이미 남 — 12V 확보 후 재측정 불필요**

## 3. NoIR 빨강/노랑 HSV 분리 테스트 — 결과

임의의 빨강/노랑 물체로 1차 진행 (문서 지침대로 실물 조달 기다리지 않음).

```
빨강: H 161~170 (평균 165.4), S 146~252, V 86~122
노랑: H 36~71   (평균 49.6),  S 19~58,   V 149~176
H채널 겹침 비율: 0.00 (완전 분리)
```

- **판정: 분리 됨 ✅ (잠정)**
- 문서 §2-2 해석 기준상 정색 웹캠 추가 구매는 **현재 불필요**로 잠정 결론
- 🔴 남은 절차: 실제 시연 물체(적색 강체·황색 변형체) 조달 후 재확인 필요, 최종 임계값은 **촬영 조명 아래에서** 확정해야 함 (지금 값은 코드에 고정하지 않음)
- 형상 특징값(면적·채움률·원형도)은 1차 테스트 범위 밖 — 실물 조달 후 별도 측정

## 4. ROS2 노드 구현 — 변경 사항

### 4-1. 신규 패키지

| 패키지 | 역할 | 상태 |
|---|---|---|
| `sensor_bridge` (TCP:5002) | ENV 보드 전용 경로. `amr_bridge` 프로토콜 구조(체크섬·하트비트타임아웃) 재사용 | ✅ 뼈대 완성, 실물 미연결 |
| `arm_act_node` | ACT 추론 노드. `arm_bridge`(5001)는 수정 없이 재사용, 클라이언트만 `arm_controller`→`arm_act_node`로 교체 | ✅ 완성, **현재 더미 모드** (정책 체크포인트 없음 → dummy grip sequence로 폴백) |

> 🔴 `amr_bridge`와 `sensor_bridge`의 실제 역할 분담(어느 프로토콜이 DRIVE용/ENV용인지)은 **팀 확인 필요**. 임의로 재배치하지 않음.

### 4-2. 기존 패키지 수정

| 패키지 | 변경 내용 |
|---|---|
| `arm_controller` | **포즈 테이블 수준으로 축소.** 정밀 IK 제거 (파지는 arm_act_node가, 놓기만 이 노드가 담당). `/arm/place_request` 구독 → 프리셋 포즈(`OVERPACK_DRUM`, `HAZMAT_STORAGE`)로 이동 |
| `vision_node` | `/camera/image_raw` 구독 유지 + **형상 특징값(원형도·채움률) 추가**, **ROI를 작업공간 높이로 제한**(바닥 오검출 차단), **색·형상 불일치 시 소프트 모드 폴백** 추가. `ObjectClass` 개명 반영 |
| `mission_orchestrator` | 아래 4-3 참조 (가장 큰 변경) |
| `hazardbot_dashboard` | §5 참조 |
| `hazard_detector` | ❌ **이번 라운드 미반영.** `ZoneId`/개명 아직 안 들어감 |

### 4-3. mission_orchestrator — 주요 변경 (오늘 발견/수정한 버그 포함)

**신규 기능**
- GRIP(파지)/TRANSPORT(놓기) 요청 분리: `/arm/grip_request`(→arm_act_node), `/arm/place_request`(→arm_controller)
- 색상→분류→목적지 매핑 반영: `COLOR_TO_CLASS_MISSION`, `DESTINATION_BY_CLASS`, `GRIP_THRESHOLD_BY_CLASS`
- **하트비트 기반 정지 로직** (문서 §5 원칙 반영) — 상세 아래
- **EMERGENCY 수동 복귀** — `/mission/reset`, `confirm: "SAFE_TO_RESUME"` 필드 요구
- `publish_state()`에 `zone_display` 필드 추가 (대시보드 라벨용)

**오늘 발견한 버그 (초기 반영본에 있었음, 수정 완료)**
```
🔴 pub_grip_retry 미생성 → 재시도 로직 호출 시 AttributeError로 노드 다운
   (실제 재현 테스트로 확인 후 수정)
🔴 battery_cb가 String 타입으로 잘못 구독 (amr_bridge는 Float32로 발행)
🔴 TRANSPORT 상태에 place_request 발행 로직 자체가 빠져있었음
🔴 GRIP_THRESHOLD_BY_CLASS 정의만 되고 실사용 안 됨 (하드코딩된 조건문 잔존)
```

### 4-4. 하트비트 기반 정지 로직 상세

```
문서 §5 원칙: 계층2(RPi) 정지는 'STOP' 명령이 아니라 하트비트.
RPi가 0.3초 주기로 /mission/heartbeat 발행 → DRIVE는 신호 끊기면 스스로 정지
```

- `HEARTBEAT_INTERVAL = 0.3초` (진우가 결정한 값. 타임아웃 1초 예정 기준 1/3 이하)
- EMERGENCY 진입 시 하트비트 발행 중단 (`heartbeat_active = False`)
- `amr_bridge`에 `/mission/heartbeat` 구독 + DRIVE로 `<HB,CS>` 전달 로직 추가 (뼈대만, 실물 DRIVE 미연결)
- **실측 검증 완료**: `ros2 topic hz /mission/heartbeat` → 평균 3.334Hz (0.3초 주기) 안정적 확인, FLAME 이벤트 시 하트비트 발행 중단 확인
- 🔲 DRIVE 펌웨어 쪽 "HB" 수신·타임아웃 로직은 **승환 담당, 미구현**
- 🔲 하트비트 프로토콜명("HB")은 진우가 임의로 정한 것 — 승환과 합의 필요
- 🔲 `RPI_TIMEOUT` 실측값(3초→1초)은 승환이 확정

### 4-5. 전체 FSM 시나리오 검증 (Mock)

```
✅ PATROL → DETECTED → CLASSIFY → APPROACH → GRIP → TRANSPORT (정상 파지)
✅ GRIP 파지 실패 → 재시도(1/3) → 노드 다운 없이 정상 처리 (버그 수정 후 재검증)
✅ FLAME 감지 → EMERGENCY 즉시 전이 → 하트비트 중단
✅ EMERGENCY 상태에서 confirm 없는 reset 요청 → 거부 확인
✅ EMERGENCY 상태에서 confirm 포함 reset → PATROL 복귀 + 하트비트 재개 + 감지정보 초기화
✅ TRANSPORT 전이 시 색상별 목적지 매핑 확인 (yellow → HAZMAT_STORAGE)
```

## 5. 대시보드 — 변경 사항

- `sensor_bridge`(ENV 보드) 토픽 구독 추가: `/env/gas`, `/env/temp`, `/env/battery`, `/env/state`
- **구역 표시 이름** 반영 (`zone_display` — 일반구역/취급구역/위험구역)
- 🆕 **"구역별 판정 — 같은 값, 다른 판정" 매트릭스 표** 신설
  - 같은 가스 원시값을 세 구역 임계값에 각각 대입해 판정을 나란히 표시
  - 현재 구역 행을 시각적으로 강조(배경색+outline)
- Mock 데이터로 실동작 확인: 가스 400 입력 시 일반구역=🔴격리실패, 취급구역=🟢정상, 위험구역=🟢정상범위로 **동시에 다르게 표시되는 것 확인**

**트러블슈팅 기록**: 최초 반영 시 `<script>` 삽입 위치 안내 실수로 `data is not defined` JS 오류 발생 → `socket.on('update', ...)` 콜백 전체 재작성으로 해결

## 6. RPi5 부하/전원 관련 관찰

- 전체 10개 노드(camera_ros 포함) + 대시보드 동시 구동 시 **SSH 세션 렉 발생**
