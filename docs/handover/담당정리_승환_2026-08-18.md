## 1.3 수집 게이트 — 상세

### ① 그리퍼 골무 부착

| | |
|---|---|
| 목적 | 🔴 **파지력.** 완충이 아니다 — 테이퍼 쐐기(종이컵) 미끄러짐을 잡는다 |
| 함정 | 🔴 **수집 전에 끼운다.** 나중에 끼우면 두께만큼 개구가 줄어 **적색 데이터까지 무효** |
| 함께 | 🔴 **그리퍼 최대 개구 실측을 골무 낀 상태로** 한다 |

> 무게추는 8/8 에 **삭제**됐다 (컵이 단단하고 무거워 불필요). 폼 패드도 **골무로 대체**됐다.
> 압착 대책의 주체는 이제 **Load 클램프 40%** 다.

### ② 차체 통과 10/10 · 그리퍼 진입

소구획이 **관통형**(라인이 셀을 가로지른다)이라 기준이 그리퍼가 아니라 **차체**다.

- 🟠 개구부 **400mm 내외** (차체 260 + 산포 ±30 + 여유)
- 🔴 **10회 중 10회 통과.** 한 번이라도 걸리면 개구부를 넓힌다
- 셀 안에서 **그리퍼가 물체에 닿는가** — 막히면 **수집한 데이터가 통째로 무의미**해진다

### ②-1 격리함 뚜껑 3항목

| | 확인 | 못 지키면 |
|---|---|---|
| 높이 | 물체가 **어떤 자세로 앉아도 뚜껑 아래** | 뚜껑이 걸린다 = **봉쇄 실패.** 파지 실패보다 나쁘다 |
| 경로 | **열린 뚜껑이 투입 동선을 막지 않는다** | 넣는 동작이 뚜껑에 걸린다 |
| 각도 | **백스톱으로 열림 각도가 매번 같다** | 접촉 지점이 흔들려 재현이 안 된다 |

🔴 뚜껑은 **「닫는다」가 아니라 「넘어뜨린다」** — 수직을 조금 넘겨 손을 떼면 끝점 하드스톱이 사라진다.
🔴 **당기기 금지.** 담당 구간은 **프리셋**이다 (격리함이 고정이라 변수가 없다).

### ③ 캘리브레이션 재조정 (화각 좌측 편향)

- ⚠ **먼저 확인** — 치우침의 원인이 **카메라 브래킷이 돌아간 것**이면 브래킷을 돌리는 편이 싸다.
  캘리브레이션은 아래 연쇄를 끌고 온다
- 🔴 **연쇄** — `check_home.py` 기준 재저장 → `wrist_roll` 안전 범위 재설정
- 🔴 **`teleop.ps1` 실행 중 프롬프트에서 `c` 를 누르지 말 것.** 엔터만.
  절차는 `로봇암_구축기록.md` §6 을 따른다 (§5-1 래핑 · §5-2 영점 불일치 재발)
- 🔴 **수집 후에 바꾸면 데이터 전량 무효**

### ⑤ 정지 산포 ×10

- 정지점 1·2 에서 각 **10회**, 🔴 **θ(yaw) 우선**
- 이 값이 **수집 범위를 정한다** — 모르면 어디까지 놓아도 되는지를 모른 채 수집하게 된다
- 🔴 **VGR 보정 범위의 근거**이기도 하다

# 2. 🔴 DRIVE 펌웨어 — 가장 큰 미구현 덩어리

**§4 의 안전 계층이 RPi 쪽만 있고 DRIVE 쪽이 비어 있다.**

## 2.1 구현 목록 (정본 §8.2)

| # | 항목 | 규모 |
|---|---|---|
| 1 | 🔴 **TCP 클라이언트 전체** — `WiFiClient` 신설. 현재 WiFi 는 OTA 전용 | **대** |
| 2 | `<HB,CS>` 수신 + `RPI_TIMEOUT` 감시 | 중 |
| 3 | `<MOVE,L,R>` 수신 → 모터 구동 | 중 |
| 4 | `<SENS>` 송신 (battCv · state · action · fault) | 중 |
| 5 | `<STOP,CS>` 수신 → 즉시 정지 | 소 |

## 2.2 하트비트 — 「명령」이 아니라 「생존 신호」다

🔴 **`STOP` 을 보내서 세우는 방식으로 만들면 안 된다.** 그 명령이 유실되거나 보낸 쪽이 죽으면 정지가 안 된다.

> **RPi 가 주기적으로 하트비트를 보내고, DRIVE 는 그것이 끊기면 선다.**

이러면 **RPi 사망 · WiFi 두절 · ENV 사망**(→ RPi 가 하트비트를 끊음)이 **하나의 메커니즘으로** 정지된다.

| 값 | 현재 | 비고 |
|---|---|---|
| `HEARTBEAT_INTERVAL` | **0.3초** | EMERGENCY 시 발행 중단 |
| `RPI_TIMEOUT` | 🔲 **3초 → 1초 전후로 좁힐 것** | 주행 중 3초면 상당 거리를 간다. 단 **짧으면 WiFi 오작동 정지(nuisance trip)** — 이 긴장이 실제 설계 문제다 |

🔴 **`RETURN` 과 `EMERGENCY` 는 하트비트 처리가 반대다.**
- `EMERGENCY`(정지형) — 하트비트 **중단** → DRIVE 가 타임아웃으로 정지
- `RETURN`(복귀형) — 하트비트 **유지** → 주행 능력이 살아 있어야 후진 이탈이 된다

## 2.3 4계층 정지 — DRIVE 단독 권한

| 계층 | 주체 | 조건 | 경로 | 시간 상수 |
|---|---|---|---|---|
| 0 | 하드웨어 | ESP32 사망·리셋 | **STBY 10k 풀다운** | 즉시 |
| 1 | **DRIVE 로컬** | ToF 장애물 · 라인 이탈 · 배터리 저전압 | 자체 배선 | ms |
| 2 | RPi | 미션 정지 · E-Stop · ENV 폴트 중계 | WiFi TCP | 100ms~ |
| 3 | 사람 | XT60 수동 분리 | 물리 | — |

🔴 **모터를 멈추는 것은 DRIVE 뿐이다.** ENV 도 RPi 도 「요청」만 한다.
🔴 **ToF 는 계층 ① 에서 거리를 보는 유일한 수단**이다 — NoIR 은 RPi 에 붙어 있어 대체 불가.

## 2.4 DRIVE 핀 배정 (배선 정본 §2.2)

| 신호 | 핀 | 신호 | 핀 |
|---|---|---|---|
| PWMA | G25 | S1 | G13 |
| AIN1 | G26 | S2 | G18 |
| AIN2 | G27 | S3 | G19 |
| PWMB | G14 | S4 | G23 |
| BIN1 | G16 | S5 | G32 |
| BIN2 | G17 | VL53L1X SDA | G21 |
| STBY | G4 | VL53L1X SCL | G22 |
| 배터리 분압 | G39 (40k/10k = ×5.0) | | |

🔴 **라인센서 VCC 는 3V3 전용.** 5V 를 주면 출력도 5V 가 되어 ESP32 GPIO 가 손상된다.
🔴 **VL53L1X 는 논블로킹 읽기 필수** — 블로킹이면 라인 PID 주기가 무너진다.

# 3. 🔵 전력 계통 — 2026-08-18 이관받음

**`3S LiPo → XT60 분기점 → DFR0753 → RPi` 전 구간과 공용 전력 버스가 전부 승환 담당이 됐다.**
~~8/3 의 「분기점까지 강희 / 이후 진우」~~ 분담은 폐기다.
v5 §7 · `_진우_전달_2026-08-03.md` §1 의 경계선 서술은 **현행이 아니다.**

## 3.1 계통도

```
  3S LiPo ── XT60 분기점 ─┬─ 12V 터미널 ──── TB6612 VM (DRIVE)
                          │
                          ├─ XL4015 #A ──── 🔴 7.4V ── 리더암 서보 6개
                          │
                          ├─ XL4015 #B ──── 5V ──┬── SS34 ── ESP32 VIN (DRIVE)
                          │                       └── 🔴 별도 한 쌍 ── MQ-135 / MQ-2 VCC (ENV)
                          │
                          └─ DFR0753 ────── RPi 5
```

## 3.2 🔴 되돌릴 수 없는 확인 — 통전 전

| # | 확인 | 안 하면 |
|---|---|---|
| ① | 🔴 **XL4015 `#A` 출력 = 7.4V** 멀티미터 확인 | **12V 를 물리면 리더암 서보 6개 전멸** (₩178,315, **복구 불가**) |
| ② | **트리머는 통전 전에 돌려놓는다** | 부하를 물린 뒤 조정하면 순간 과전압이 나간다 |
| ③ | **MQ 5V 는 XL4015 #B 에서 별도 한 쌍** (데이지체인 금지) | 히터 상시 ~330mA 가 DRIVE 5V 를 흔든다 → 브라운아웃 |
| ④ | **배터리 분압 40k/10k = ×5.0 → G39** 멀티미터 보정 | 저전압 정지가 엉뚱한 값에서 걸린다 |
| ⑤ | **라인센서 VCC = 3V3** | ESP32 GPIO 손상 |

🔴 **③은 지금 강희가 납땜 중인 부분이다.** 급전점을 어디서 뽑을지는 **전력 담당인 승환의 결정**이고,
실제로 붙이는 것은 강희다 — **완성 전에 말을 맞춘다.**
🔴 **`GAS_THRESHOLD` 실측보다 먼저 정리한다** — 급전점이 바뀌면 가스 기준선이 바뀌어 임계값이 무효다.

## 3.3 🔴 전원 통합 실측 (진우와)

**서보 6개 동시 기동 시 RPi 가 버티는가.** 이게 안 되면 **촬영 중에 RPi 가 죽는다.**

| 측정 | 조건 |
|---|---|
| RPi 브라운아웃 | **ACT 추론 + 카메라 + 서보 동시 동작 상태로 10분** |
| `get_throttled` | 진우가 RPi 에서 읽는다 — **0 이 아니면 전원 부족** |
| 서보 기동 순간 전압 강하 | 멀티미터로 XL4015 출력 관찰 |

## 3.4 하드웨어 페일세이프 — 이미 들어가 있다

만능기판 설계에 **`STBY` 10kΩ 풀다운**이 있다. TB6612 의 STBY 는 내부 풀다운이 없어 플로팅이면 불확정인데,
이 저항 때문에 **ESP32 가 죽거나 리셋되면 G4 가 하이임피던스 → 풀다운이 STBY 를 LOW 로 → 모터 정지**한다.

🔵 **이건 우연이 아니라 설계된 것**이고, 「정지를 DRIVE 에 두는」 결정(4계층 §0)을 뒷받침한다.

# 4. 데이터 수집 (8/19 목표)

## 3.1 구성

- **두 물체를 한 데이터셋에** — 데이터셋 키는 `observation.images.wrist` **하나뿐**
- **10 에피소드씩 나눠 녹화** — 50~100개를 한 번에 돌리다 90번째에서 끊기면 그때까지가 날아간다
- 🔴 **뚜껑 닫기까지 전부 녹화** (에피소드당 +3~4초).
  학습에 넣을지(A) 잘라낼지(B) 는 **8/21 판정 후에** 정한다
  → 🔴 **지금 안 찍으면 나중에 못 찍는다.** 잘라내는 건 스크립트 작업이지만 **안 찍은 건 전량 재수집**이다
- 적색은 **정방향 배치** — 변동은 **위치(x·y)만**. 🔴 **자로 정렬하지 말 것**
  (손으로 놓는 자연 오차가 차체 yaw 흡수 여유다)

## 3.2 🔴 명령 플래그 — 기본값이 전부 위험하다

```powershell
# 녹화
lerobot-record  ... --dataset.push_to_hub=false

# 학습
& "C:\Users\sehi5\miniconda3\envs\lerobot\Scripts\lerobot-train.exe" `
  --dataset.repo_id=local/<이름> --dataset.root="<경로>" `
  --policy.type=act --policy.device=cuda --policy.push_to_hub=false `
  --output_dir="<출력경로>" --job_name=<이름> `
  --steps=100000 --batch_size=8
```

🔴 **`push_to_hub` 는 녹화·학습 **양쪽 모두** 기본값이 `True` 다.**

## 3.3 수집 중 함정

| 함정 | 대응 |
|---|---|
| **단일 시리얼 글리치에 세션이 통째로 죽는다** (`after 1 tries` — 재시도 없음) | `streaming_encoding` 사용 신중히. 켤 경우 짧게 시험 먼저 |
| 이미지 라이터 스레드 경합 | `--dataset.num_image_writer_threads_per_camera` 4 → 2 |
| **카메라 인덱스가 하루에도 바뀐다** | 🔴 **녹화 전 매번 확인.** 손목 0 / 내장 1. **해상도로 구분하지 말 것** — 내장도 1080p 다 |

| | |
|---|---|

## 🟠 8/21 판정 기준 — **물체별 10회 중 8회**

| 결과 | 조치 |
|---|---|
| 둘 다 8/10 이상 | 🔵 그대로 진행 (적색·황색 둘 다 ACT · 정책 1개) |
| 황색만 미달 | 황색 프리셋 + VGR (적색 ACT 유지) |
| **적색만 미달** | **8/4 구성으로 하강** — 적색 프리셋 + VGR |
| 둘 다 미달 | 전량 프리셋 + VGR. ACT 는 **데이터셋·학습 곡선을 연구 성과로** 발표 |

🔴 **폴백은 공짜가 아니다.** 프리셋으로 내려가면 **VGR 소비 구현 + 오프셋 캘리브레이션**이라는
새 작업 갈래가 열린다 (`center_x`/`center_y` 는 발행만 되고 소비처가 없다).
