## 1. 배경 — 무엇이 비어 있는가

v5 §5.9 는 환경 구성(색·라벨·소품)을 **산업 안전표지 규격 기반으로 잘 잡아놨다.** 그건 그대로 둔다.

비어 있는 건 **구역 자체의 정의**다.

| 문서 | ZONE 관련 기술 |
|---|---|
| v5 §9.1 큐시트 | ZONE1 센서퓨전 / ZONE2 파지 ×2 / ZONE3 컨텍스트·화염 |
| v5 §5.9 계층3 | 위험구역 경계 = 검정/흰색 사선 |
| v5 산출물 목록 1175행 | "센서 퓨전 (5종·3단계, MQ 비율 + **구역 컨텍스트**)" |

- 「같은 값 다른 판정」(큐시트 10s 구간)이 **왜 다르게 판정되는지** 설명할 근거가 없다
- 심사에서 *"왜 같은 수치인데 판정이 다릅니까?"* 를 받으면 답할 말이 없다
- 로봇이 구역을 어떻게 아는지도 미정이었다 → 별도로 정리함 (`docs/06_firmware/구역_마커_설계.md`)

## 2. 제안 ① — ZONE 재정의

가스 위험 구역에는 이미 **"Zone"이라는 이름의 국제 분류 체계**가 있다 (IEC 60079-10 / ATEX). HazardBot 이 MQ 센서로 다루려는 대상과 정확히 같다.

| 등급 | 정의 |
|---|---|
| Zone 0 | 폭발성 가스 분위기가 **상시 또는 장시간** 존재 |
| Zone 1 | **정상 운전 중 발생 가능** |
| Zone 2 | 정상 시엔 없고, 발생해도 **단시간** |
| 비위험 구역 | 가스가 있어서는 안 되는 구역 |

### 대응

| 현재 | 제안 | 로봇의 임무 |
|---|---|---|
| ZONE 1 | **일반 구역** (비위험) | 순회 점검. 여기서 가스 검출 = **격리 실패** |
| ZONE 2 | **취급 구역** (Zone 2 상당) | 위험물 용기 회수 — 파지 작업 |
| ZONE 3 | **위험 구역** (Zone 1 상당) | 가스 상시 존재 전제. **점화원 감시** |

> **🔵 번호 정렬은 하지 않는다 〔확정 2026-08-04〕**
>
> *"우리 ZONE 순서를 IEC 순서(숫자가 작을수록 위험)에 맞추면 설득력이 오르지 않나"* 를 검토했고,
> **코드 수정 비용을 0으로 놓아도 결론은 유지**였다.
>
> - **비위험 구역은 Zone 2 가 아니다.** 위 정의표의 4번째 행이며 Zone 2 와 나란히 놓인 별개 항목이다.
>   Zone 2 도 폭발위험장소라 방폭 기기(EPL Gc)를 요구한다. 일반구역을 Zone 2 에 대응시키면
>   *"단시간 발생은 정상"* 이 되어 **§3 의 「일반구역 가스 = 격리 실패」 경보가 근거를 잃는다.**
>   이번 재정의를 한 이유 자체를 지우는 대응이다.
> - **Zone 0 은 로봇이 들어가는 곳이 아니다.** 대개 탱크·용기 내부의 밀폐 체적이고, 기기에 EPL Ga
>   (독립된 보호 2중)를 요구한다. 브러시 DC 모터로 굴러가는 AMR 은 원리적으로 대상이 아니다.
> - **정렬은 「참고」를 「주장」으로 바꾼다.** Zone 1 이라고 쓰는 순간 누출원 등급·환기 유효성·로봇의
>   EPL 로 평가받는다. 우드락 세트에서 답이 없다. 반면 "위험구역"은 우리 어휘라 **떨어질 규격이 없다.**
> - 심사는 녹화 영상이고, 자막·나레이션은 §5 표현 제한에 따라 **일반/취급/위험구역**이다.
>   즉 번호는 **심사 산출물에 등장하지 않는다.** 정렬해도 쌓이는 곳이 없다.
>
> 표준 이해도는 번호가 아니라 **§3 의 뒤집힌 판정 방향**이 증명한다. 번호는 누구나 3분이면 맞춘다.

**Q&A 대비 — 한계를 아는 쪽이 강하다.**

> "로봇은 **1종 장소 상당까지만** 진입하도록 설계했습니다.
>  0종은 대개 용기 내부이고 EPL Ga 가 필요해서 이동로봇의 대상이 아닙니다."

*"Zone 0 에 간다"* 보다 **"왜 Zone 0 에는 가지 않는지 안다"** 가 이해도를 더 잘 증명한다.
국내 실무 용어는 `Zone 0/1/2` 가 아니라 **0종·1종·2종 장소**이므로, 한국어로 말할 때는 이쪽을 쓴다.

## 3. 제안 ② — 「같은 값 다른 판정」의 논리

위 정의를 깔면 큐시트의 ZONE3 두 비트가 **하나의 논리로 연결된다.** 지금은 따로 노는 장면이다.

```
가스 수치 상승 (동일한 MQ-2 값)
 ├─ 일반 구역 → 🔴 경보.     가스가 있으면 안 되는 곳 = 격리 실패
 └─ 위험 구역 → 🟢 정상 범위. 이 구역은 가스 존재를 전제로 설계됨

화염 검출 (동일한 KY-026 값)
 ├─ 일반 구역 → 🟠 화재 경보
 └─ 위험 구역 → 🔴🔴 EMERGENCY. 폭발 위험 → 즉시 후퇴
```

**핵심은 방향이 직관과 반대라는 점이다.** 위험 구역에서 가스는 정상이고, 일반 구역에서 가스는 비상이다. 위험 구역의 안전 개념 전체가 *"가스는 있다고 가정하고 점화원을 제거한다"* 이기 때문.

→ *"가스는 봐줬는데 불꽃은 못 봐준다 — 여기가 위험 구역이라서"* 로 설명이 닫힌다.
**심사에서 가장 설명하기 좋은 구간이 된다.**

## 4. 제안 ③ — 구역별 로봇 행동

실제 플랜트 순회 점검 로봇(석유화학·변전소·터널)의 동작을 대입.

| 구간 | 행동 | 구현 비용 |
|---|---|---|
| 구역 경계 진입 | **감속** (실제 AMR 의 speed zone) | 몇 줄. **정지 위치 산포까지 같이 개선** |
| 위험구역 진입 전 | **진입 조건 확인** — 가스 수치 임계 미만일 때만 진입 | ~10줄. 작업허가 절차의 축소판 |
| 위험구역 내부 | 점화원 감시 우선, 가스 임계 완화 | 판정 테이블 분기 |
| 임무 종료 | **안전구역 복귀 + 순회 점검 리포트** | 이미 계획됨. 명칭만 정정 |

감속은 이미 `docs/06_firmware/구역_마커_설계.md` §6 에 2단 정지로 들어가 있다 — **이 안건이 부결돼도 감속 자체는 진행된다** (정지 정확도 때문에 필요).

## 5. 🔴 검토 필요 — 기존 팀 규칙과의 긴장

`docs/03_scenario_demo/demo_video_scenario.md` §12 에 이미 **정직성 규칙**이 있고, 이 제안과 부딪힌다.

> - 검정 주행 라인은 로봇 센서를 위한 공학적 경로이며 **법정 안전통로 색상이라고 설명하지 않는다.**
> - 파지 대상이 실제 화학물질이 아니라면 **법적 GHS 분류를 임의로 주장하지 않는다.**

**이 규칙은 옳고, 유지해야 한다.** 따라서 제안을 다음과 같이 제한한다.

| ❌ 하면 안 되는 것 | ✅ 해도 되는 것 |
|---|---|
| "이 구역은 **Zone 0 입니다**" | "방폭 구역 등급 개념을 **참고해** 구역을 설계했습니다" |
| 규격 준수·인증을 시사 | 판정 로직의 **설계 근거**로 인용 |
| 화면에 `ATEX Zone 0` 표기 | 자막·나레이션은 **일반구역 / 취급구역 / 위험구역** |
| 실제 방폭 표지(Ex 육각형) 부착 | 자체 제작한 구역 표지 |

즉 **개념은 근거로 쓰되, 등급을 주장하지 않는다.** §12 의 정신과 일치한다.

> 판단이 필요한 지점: 이 선이 충분한가? 더 보수적으로 가려면 ATEX 언급 없이
> **"구역별 위험 특성이 다르다"** 수준으로만 설명해도 논리는 성립한다 (설득력은 약해짐).

## 5.5 구역 경계 = 우드락 〔승환 결정 2026-08-03〕 — ✅ 반영 완료

경계를 **바닥 사선 테이프 → 우드락 수직 구조물**로 변경. **결정·문서 반영 모두 완료됐다. 회의에서는 공유만 하면 된다.**

**얻는 것**: 사선 테이프가 주행 라인을 가로지르면 라인센서가 가짜 마커로 읽는 문제가 **원천 제거**된다.
그리고 「로봇이 읽는 것(바닥 가로선) ↔ 사람이 보는 것(수직 경계·명판)」이 분리돼 설계 원칙이 깨끗해진다.

**제약** (상세는 `docs/06_firmware/구역_마커_설계.md` §8)

- 🔴 **바닥에 우드락을 깔지 말 것** — 5T 가 라인센서 높이를 5mm 바꿔 검출이 깨진다 (동작 범위 3~10mm)
- 🔴 **게이트 개구부 ≥800mm** — 좁으면 ToF 가 기둥을 장애물로 읽고 정지한다. 세트 §4.1 의 400mm 이격 기준과 일치
- 상단 가로대 없이 **양쪽 기둥만**, 높이 300~400mm — 저각 촬영(400~600mm) 시야 확보
- 자립 받침 필요 (우드락은 단프라보다 가볍다), 절단면 테이프 처리
- **사선 무늬는 기둥 표면에** — v5 의 시각적 의도 유지, HSV 충돌 없음

         테이크가 날아간다.** 그런데 화면상으로는 "아무 일도 안 일어나는" 장면이라 얻는 게 없다
      4. 안전 계층이 이미 넷이다 (하드웨어 STBY 풀다운 / DRIVE 로컬 / RPi 하트비트 / 수동 XT60)

> 🔴 **사유 ①②가 해소됐어도 보류는 유지한다.** ③ 이 단독으로 결정적이기 때문이다 —
> **얻는 것(화면상 아무 일도 안 일어남) 대비 잃는 것(테이크 손실)이 크다.**
> 기술적으로 막혀서 미룬 것이 아니라 **촬영 손익으로 미룬 것**이라는 점을 발표에서 구분해 말할 것.
      → **발표에서는 「구역별 판정 임계 차등화까지 구현, 진입 차단은 확장 항목」으로 답한다.**
        v5 §5.9 가 GHS 픽토그램을 다루는 방식과 같다
      → 여력이 생기면 **연속 촬영이 아니라 별도 클립**으로 (E-Stop 장면과 같은 취급)
