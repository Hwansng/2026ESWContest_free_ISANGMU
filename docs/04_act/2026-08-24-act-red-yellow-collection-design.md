# 적색·황색 단일 ACT 데이터셋 수집 환경 설계

## 1. 목적과 범위

이 문서는 HazardBot의 적색 물체와 황색 종이컵 조작을 하나의 ACT 정책으로 학습하기 위한 수집 환경을 정의한다. 2026년 8월 16일 Claude Artifact의 시나리오를 최신 정본으로 사용한다. 이전 문서의 “적색은 프리셋, 황색은 ACT” 구상보다 본 설계의 “적색·황색 모두 ACT, 단일 정책” 원칙이 우선한다.

현재 노트북의 역할은 데이터 수집, 품질 검사, 진행 이력 관리, 다른 노트북으로의 안전한 전송까지다. ACT 학습, CUDA 설치, GPU 학습 환경 구축은 포함하지 않는다. 데이터는 Hugging Face Hub에 업로드하지 않고 로컬에 보관한다.

## 2. 고정된 수집 목표

- 데이터셋 경로: `output/act_red_yellow_v1`
- LeRobot 식별자: `local/hazardbot_red_yellow_act_v1`
- 작업 문장: `Pick up the hazardous object, place it in the isolation bin, and close the lid.`
- 프레임률: 30 FPS
- 카메라: `observation.images.wrist` 한 대, 640×480
- 수량: 총 100개 성공 에피소드
- 색상 균형: 적색 50개, 황색 50개
- 위치 균형: 색상별로 중앙, 앞왼쪽, 앞오른쪽, 뒤왼쪽, 뒤오른쪽을 각각 10회
- 배치: 10개 배치, 배치당 적색 5개와 황색 5개
- 각 배치는 2색×5위치 조합을 한 번씩 포함하며 실행 순서만 무작위로 섞는다.
- 촬영자는 100개 모두 동일한 한 명으로 고정한다.
- 격리함, 카메라 위치와 각도, 조명, 작업면, 홈 자세는 전체 수집 동안 고정한다.

현재 확인된 장치는 리더암 COM6, 팔로워암 COM7, 카메라 인덱스 1이다. 실행 스크립트는 이 값을 기본 프로필로 제공하지만, 장치 관리자의 포트가 바뀐 경우 사용자가 명시적으로 새 값을 지정해야 한다. 포트를 추측하여 자동 선택하지 않는다.

## 3. 에피소드 정의

한 에피소드는 다음 순서만 기록한다.

1. 팔로워암이 고정 홈 자세에 있고 그리퍼가 준비 상태에 있다.
2. 지정된 색상의 물체 한 개만 지정 위치에 놓여 있다.
3. 격리함은 비어 있고 힌지 뚜껑은 완전히 열려 있다.
4. 물체에 접근하여 잡는다.
5. 물체를 격리함으로 운반한다.
6. 격리함 안에 놓고 그리퍼를 해제한다.
7. 힌지 뚜껑을 완전히 닫는다.
8. 닫힌 상태를 1초 유지한 뒤 에피소드를 종료한다.

팔을 홈 자세로 되돌리고, 물체를 회수하고, 뚜껑을 다시 여는 과정은 기록하지 않는다. 한 에피소드에는 대상 물체 한 개만 보이게 한다. 지점 번호나 색상별 작업 문장은 정책 입력으로 사용하지 않는다.

동작 시간은 20~30초를 목표로 하며 최대 35초로 제한한다. 급가속 없이 일정하고 자연스러운 속도로 수행한다. 1초 이상의 불필요한 정지, 불필요한 왕복, 동작 중 되돌리기나 수정은 실패로 취급한다.

## 4. 성공과 실패 판정

다음 조건을 모두 만족한 에피소드만 저장한다.

- 목표 물체를 첫 시도에 안정적으로 잡는다.
- 충돌이나 물체 낙하 없이 격리함으로 옮긴다.
- 물체가 격리함 안에 정상적으로 놓인다.
- 그리퍼를 정상적으로 해제한다.
- 뚜껑을 완전히 닫고 1초 유지한다.
- 전체 동작이 최대 35초 안에 자연스럽게 끝난다.

놓침, 충돌, 낙하, 불완전한 뚜껑 폐쇄, 1초 이상의 불필요한 정지, 되돌리기, 중간 수정 중 하나라도 발생하면 실패다. 실패 시 `R` 또는 왼쪽 화살표를 눌러 현재 에피소드 버퍼를 폐기하고 같은 수집표 순번을 다시 촬영한다. 성공 시 뚜껑을 닫고 1초 유지한 다음 `N` 또는 오른쪽 화살표를 눌러 저장한다. 전체 녹화의 정상 종료에는 `Q` 또는 `Esc`를 사용하며, `Ctrl+C`는 통신 이상이나 물리적 위험이 있는 비상 상황에만 사용한다.

## 5. 데이터셋 생성과 재개

데이터셋은 한 폴더에 누적한다. 첫 성공 배치를 만들 때는 신규 생성 모드로 실행하고 `--dataset.no_stamp=true`를 사용하여 식별자에 날짜가 자동으로 붙지 않게 한다. 이후 실행은 같은 `repo_id`와 `root`에 `--resume=true`를 전달한다.

수집 실행기는 다음 상태 규칙을 지킨다.

- 대상 폴더가 없거나 비어 있으면 신규 데이터셋만 생성한다.
- `meta/info.json`이 있는 정상 데이터셋이면 재개만 허용한다.
- 파일은 있지만 정상적인 LeRobot 메타데이터가 없으면 실행을 거부한다.
- 기존 데이터셋의 식별자, FPS, 로봇 특성 또는 카메라 특성이 현재 프로필과 다르면 실행을 거부한다.
- 이미 완료된 배치는 다시 녹화하지 않는다.
- 중단된 배치는 아직 기록되지 않은 수집표 순번만 이어서 촬영한다.
- 실행 전후 에피소드 수 차이만큼 수집표의 다음 `pending` 행을 `recorded`로 변경한다.

LeRobot 0.6.1의 재촬영은 실패 버퍼를 저장하지 않으므로, 재촬영 횟수와 관계없이 성공한 에피소드만 전역 인덱스를 하나씩 차지한다.

## 6. 균형 수집표와 이력

수집표는 고정 시드 `20260816`으로 생성한다. 각 배치에는 다음 10개 조합이 정확히 하나씩 들어간다.

- `red`: `center`, `front_left`, `front_right`, `rear_left`, `rear_right`
- `yellow`: `center`, `front_left`, `front_right`, `rear_left`, `rear_right`

배치 안에서만 순서를 섞는다. 수집표에는 `batch`, `slot`, `color`, `position`, `status`, `episode_index`, `recorded_at`, `note`를 기록한다. `status`는 `pending` 또는 `recorded`이며, 성공 저장 뒤에만 `recorded`로 바뀐다. 수집표와 프로토콜 스냅샷은 데이터셋 내부의 `collection/` 폴더에 두어 데이터와 함께 전송한다.

## 7. 실행 흐름

각 배치는 다음 절차로 실행한다.

1. 사용자가 배치 번호를 지정한다.
2. 실행기가 하드웨어 프로필, 저장 공간, 홈 자세, 양팔 정렬, Goal Position, 카메라를 검사한다.
3. 실행기가 해당 배치의 남은 순서와 조작 키를 화면에 표시한다.
4. 사용자는 표시된 색상과 위치에 맞춰 환경을 준비하고 녹화를 수행한다.
5. 성공하면 `N`, 실패하면 `R`을 누른다.
6. 성공 에피소드 뒤에는 최대 60초의 비기록 재설정 시간이 시작된다.
7. 사용자는 팔 복귀, 물체 회수, 뚜껑 열기, 다음 물체 배치를 마친 뒤 `N`으로 재설정 시간을 조기 종료한다.
8. 배치가 종료되면 자동 검사를 실행하고 실제 증가한 에피소드만 수집표에 반영한다.

두 배치, 즉 성공 에피소드 20개가 모이면 전체 수집을 잠시 멈춘다. 이 샘플을 학습 노트북으로 복사하여 LeRobot 데이터 로더가 열 수 있는지만 확인한다. 이 노트북에서는 학습을 실행하지 않는다. 로딩 확인 후 나머지 80개를 수집한다.

## 8. 자동 품질 검사

검사 도구는 읽기 전용으로 동작하며 데이터셋을 자동 수정하지 않는다. 다음을 검사한다.

- `meta/info.json`과 LeRobot 필수 구조 존재
- 식별자, 로봇 종류, 30 FPS, 총 에피소드 수
- `observation.images.wrist`, 관절 상태, 액션 특성 존재
- 에피소드별 인덱스와 타임스탬프의 연속성·단조 증가
- 에피소드 길이가 0초보다 크고 35초 이하인지 여부
- 각 에피소드의 처음, 중간, 마지막 샘플에서 카메라 프레임이 실제로 해독되는지 여부
- 빈 파일과 누락 파일
- 수집표의 `recorded` 행 수와 데이터셋 에피소드 수 일치
- 전체 100개 완료 시 적색·황색 50:50 및 위치별 10회 균형

검사 결과는 사람이 읽는 요약과 기계가 읽는 JSON 보고서로 남긴다. 오류가 하나라도 있으면 다음 배치 재개와 전송 준비를 실패로 끝낸다.

## 9. 비정상 종료와 안전

정상 중단은 항상 `Q` 또는 `Esc`를 사용한다. 비정상 종료가 발생하면 즉시 재개하지 않고 검사 도구로 메타데이터, 저장된 에피소드 수, 마지막 영상 해독 여부를 확인한다. 검사에 실패한 데이터셋은 자동 복구하거나 덮어쓰지 않는다. 문제 파일과 마지막 정상 인덱스를 보고한 뒤 사람이 복구 방법을 결정한다.

팔 주변에 사람이 있거나 통신이 불안정하면 녹화를 시작하지 않는다. 녹화 종료 뒤 토크 해제가 확인되지 않거나 COM 포트가 사라지면 팔로워암 전원을 끄고 원인을 확인한다. 스크립트가 비정상 종료된 상태에서 자동으로 모터 명령을 다시 보내지 않는다.

## 10. 전송

100개 완료 후 먼저 전체 품질 검사를 통과해야 한다. 전송 준비 도구는 데이터셋의 모든 파일을 대상으로 SHA-256 목록을 만들되 체크섬 파일 자체는 제외한다. 동영상은 압축 효율이 낮으므로 ZIP으로 다시 압축하지 않고 폴더 구조를 그대로 복사한다.

전송 단위에는 다음을 포함한다.

- LeRobot 데이터와 영상
- `collection/` 수집표와 프로토콜 스냅샷
- 최종 JSON 검사 보고서
- SHA-256 체크섬 목록
- 학습 노트북용 한글 확인 절차

복사 후 대상 폴더에서 체크섬을 다시 계산하여 원본과 모두 일치해야 전송 성공으로 판정한다.

## 11. 구현 단위

- `record_act.ps1`: 안전 검사, 신규/재개 판정, 배치 실행, 사후 검사 조정
- `tools/act_collection_plan.py`: 고정된 균형 수집표 생성·조회·상태 반영
- `tools/check_act_dataset.py`: LeRobot 구조, 샘플, 영상, 균형 검사와 JSON 보고서 생성
- `prepare_act_transfer.ps1`: 전체 검사, 체크섬 생성, 폴더 복사, 복사본 검증
- `tests/act_collection/`: PowerShell DryRun과 Python 단위·통합 테스트
- `docs/04_act/ACT_수집_다른컴퓨터_가이드.md`: 이 노트북에서의 수집과 학습 노트북으로의 인계 절차

## 12. 검증 기준

하드웨어를 움직이지 않는 자동 검증은 다음을 통과해야 한다.

- 신규 데이터셋에는 `--dataset.no_stamp=true`가 있고 `--resume=true`가 없다.
- 정상 기존 데이터셋에는 `--resume=true`가 있다.
- 비어 있지 않은 비데이터셋 폴더는 녹화를 거부한다.
- 모든 배치가 색상별 5회, 위치별 2회이며 전체가 색상별 50회, 색상·위치 조합별 10회다.
- 중단된 배치는 남은 `pending` 행 수만 녹화한다.
- 검사 도구가 누락 메타데이터, 잘못된 FPS, 잘못된 수량, 손상 샘플, 수집표 불일치를 실패로 판정한다.
- 전송 도구가 원본과 복사본의 체크섬 불일치를 실패로 판정한다.

자동 검증을 통과한 뒤 실제 하드웨어에서는 1개 시험 에피소드만 기록하고 즉시 검사한다. 이 시험이 정상일 때만 첫 10개 본 배치를 시작한다. 실제 100개 수집은 환경 구축과 별도의 사용자 주도 작업이다.
