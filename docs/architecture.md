# HazardBot 아키텍처 개요

> 계획 정본(`HazardBot_계획변경_및_개선안_v5`)은 팀 내부 문서라 저장소에 두지 않는다.
> 이 문서는 그 요약이며, 충돌하면 v5 와 각 영역 정본 문서가 이긴다.

## 2계층 + 제어 PC

```
        ┌──────────────────────────────────┐      ┌────────────────────────────┐
        │      Raspberry Pi 5 (8GB)        │      │   학습·제어 PC (Win 11)    │
        │      Ubuntu 24.04 + ROS2 Jazzy   │      │   LeRobot 0.4.4 · ACT      │
        │  vision_node · hazard_detector   │      │                            │
        │  mission_orchestrator            │      │   USB 반이중 어댑터 ×1     │
        │  amr_bridge · arm_bridge         │      │            │               │
        │  sensor_bridge · arm_act_node    │      │            ▼               │
        │  hazardbot_dashboard             │      │   STS3215 × 12 (양팔 6DOF) │
        └───────┬──────────────────┬───────┘      └────────────────────────────┘
         Wi-Fi  │                  │  Wi-Fi TCP :8765
          TCP   ▼                  ▼
   ┌────────────────────┐  ┌────────────────────┐
   │   ESP32 — DRIVE    │  │   ESP32 — ENV      │
   │   주행 (승환)      │  │   환경·안전 (강희) │
   │  - TB6612FNG 2WD   │  │  - MQ-2 / MQ-135   │
   │  - 5ch IR 라인추종 │  │  - KY-026 화염     │
   │  - VL53L1X ToF     │  │  - NeoPixel · 부저 │
   │  - 모터 정지 권한  │  │                    │
   └────────────────────┘  └────────────────────┘
```

**로봇암은 ESP32 가 제어하지 않는다.** STS3215 는 1선 반이중 버스라 마스터가 하나여야 한다.
ESP32 를 서보 3핀 버스에 물리면 USB 어댑터와 충돌한다. 초기 설계(ESP32 UART2 직결)는
폐기했고 코드는 [`archive/firmware_esp32_arm/`](../archive/firmware_esp32_arm/) 에 남겨 뒀다.

**보드 번호(`#1`·`#2`)는 쓰지 않는다.** 문서마다 반대를 가리켜 사고가 난 뒤 폐지하고
**DRIVE / ENV** 로 통일했다.

## 감지 3계층

판단 기준은 「누가 이 데이터로 행동하는가」다. 정본은
[`firmware/docs/센서_지도.md`](06_firmware/센서_지도.md).

| 계층 | 주기 | 센서 | 행동 주체 |
|---|---|---|---|
| 실시간 반사 | 20ms | 5ch IR 라인센서 · VL53L1X | DRIVE 단독 |
| 환경 감시 | 100ms | MQ-2 · MQ-135 · KY-026 | ENV → RPi |
| 인지 · 학습 | 30fps | RPi Camera · 손목 카메라 | RPi · ACT |

MLX90614(온도)는 **미채택**이다. 근거는 센서 지도 §5.

## 4계층 정지 체계

**모터를 멈추는 것은 DRIVE 뿐이다.** 나머지는 정지를 *요청*할 뿐 직접 끊지 않는다.

| 계층 | 수단 |
|---|---|
| 하드웨어 | STBY 10kΩ 풀다운 — ESP32 사망·리셋 시 G4 하이임피던스 → 모터 자동 정지 |
| DRIVE 로컬 | 하트비트 소실 · ToF 임계(300mm) · 라인 이탈 |
| RPi | 판정 결과에 따른 정지 요청 |
| 사람 | XT60 수동 차단 |

정지는 **STOP 명령이 아니라 하트비트(생존 신호)로** 건다. RPi 사망 · WiFi 두절 · ENV 사망을
하나의 메커니즘으로 잡기 위해서다. `RETURN`(복귀형)과 `EMERGENCY`(정지형)는
**하트비트 처리가 서로 반대**다.

## FSM 미션 흐름

```
IDLE → PATROL → DETECTED → CLASSIFY → APPROACH → GRIP → TRANSPORT → ISOLATE → REPORT
                                          │
                    GRIP 실패: RETRY ×3 → SKIP → PATROL
                    화염 감지: EMERGENCY (부저 + 후진 이탈, 이중 경로)
```

**판정은 구역을 모른다.** 위치가 아니라 내용으로 결정한다 — 적색 + 가스 = 위험,
적색만 = 통과, 황색 = 가스와 무관하게 항상 위험.
시나리오 정본(`시나리오_확정_2026-08-15`)은 팀 내부 문서라 저장소에 두지 않는다.

## 통신 프로토콜

`<CMD,VALUE,...,CS>\n` — XOR 8-bit 체크섬, 16진수 2자리. 예: `<BUZZ,1>`

| 항목 | 값 |
|---|---|
| ENV ↔ RPi 포트 | **8765** |
| 정지점 순번 | **모듈로 4** |
| EMERGENCY 화염 | 즉시 정지, **이중 경로** |
| `RPI_TIMEOUT` | 조정 방침은 회신 문서 참조 |

확정 경위와 12건 합의 내용은
팀 내부 인계 문서(`회신_진우_2026-08-25`)에 있다 — 저장소에는 두지 않는다.

## 항법

라인 추종(5ch IR + PD, KP=60 · KD=25 · 20ms) + **전폭 가로선 마커**(폭 40mm) +
VL53L1X 정면 감지(임계 **300mm 단일 고정**).

측면 마커는 조향을 깨뜨리고, 전폭 가로선은 좌우 오차가 자기중화된다. RFID 는 미채택이다.
정지는 **2단 정지 상태기계**로 처리하고 오검출은 4중으로 막는다. 근거는
[`firmware/docs/구역_마커_설계.md`](06_firmware/구역_마커_설계.md).

**ZONE 명칭은 쓰지 않는다.** 취급구역 하나 + 점검점 **P1~P4** 구성이다.
후진은 개루프 직선이다 — 이 하드웨어로 후진 라인 추종은 제어적으로 불가능하다.

> SLAM/Nav2 는 LiDAR 도입 시 검토한다. 현 시점에는 결정론적 항법 + Fault Isolation 이 우선이다.

## ACT (시각운동 정책)

입력은 **손목 카메라 1뷰**, 정책 **1개**로 적색·황색을 모두 처리한다. VGR 과는 직렬로 잇는다.
**학습 카메라 = 추론 카메라** 원칙을 지킨다 (도메인 갭 방지). CSI 는 ACT 에 통합하지 않는다.
설계 정본은 [`docs/act/`](04_act/) 와
[`docs/schedule/ACT_수집학습_통합계획_2026-08-25.md`](04_act/ACT_수집학습_통합계획_2026-08-25.md).
