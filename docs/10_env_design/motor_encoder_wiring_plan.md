# AMR 모터 및 엔코더 배선 설계 메모

## 목적

이 문서는 현재 보유한 `DC 12V 350rpm` 모터 세트의 단자 역할을 정리하고, ESP32 #1 AMR에서 모터 드라이버와 엔코더를 어떻게 분리해 다룰지 설계한다. 아직 실제 모터 구동 코드는 추가하지 않는다.

## 현재 확인된 모터 정보

모터 연결부에는 다음 6개 표기가 있다.

```text
M2, V, A, B, G, M1
```

이는 일반적인 DC 감속모터 + 엔코더 구성일 가능성이 높다.

ICBANQ 제품 정보 기준으로 확인된 모터/타이어 사양은 다음과 같다.

| 항목 | 값 |
|---|---|
| 모터 모델 | CHR-GM25-370 / CHIHAI MOTOR DC GEAR MOTOR |
| 구동 전압 | DC 12V |
| 정격 전류 | 1.5A |
| 속도 | 350rpm |
| 토크 | 3.5kg.cm |
| 샤프트 길이 | 12mm |
| 샤프트 직경 | 4mm |
| 타이어 직경 | 130mm |
| 타이어 폭 | 60mm |
| 타이어 내경 | 육각 12mm |

| 표기 | 추정 역할 | 연결 대상 |
|---|---|---|
| `M1` | 모터 전원 단자 1 | 모터 드라이버 출력 |
| `M2` | 모터 전원 단자 2 | 모터 드라이버 출력 |
| `V` | 엔코더 전원 + | 3.3V 또는 5V, 부품 사양 확인 필요 |
| `G` | 엔코더 GND | ESP32 GND와 공통 |
| `A` | 엔코더 채널 A | ESP32 입력 핀 |
| `B` | 엔코더 채널 B | ESP32 입력 핀 |

주의: 실제 제품에 따라 `V`가 5V 전용일 수 있다. 엔코더 출력이 5V이면 ESP32 입력에 직접 넣으면 안 되고 level shifting 또는 3.3V 호환 여부 확인이 필요하다.

## 모터 드라이버가 필요한 이유

ESP32 GPIO는 모터를 직접 구동할 수 없다. `M1`, `M2`는 반드시 모터 드라이버의 출력 단자에 연결해야 한다.

기본 연결 구조:

```text
배터리 +  ── 모터 드라이버 VM
배터리 -  ── 모터 드라이버 GND
ESP32 GND ── 모터 드라이버 GND

모터 드라이버 OUT1 ── M1
모터 드라이버 OUT2 ── M2
```

ESP32는 모터 드라이버의 `PWM`, `DIR`, `IN1`, `IN2` 같은 제어 핀만 제어한다. 실제 모터 전류는 드라이버가 담당한다.

## TB6612FNG 사용 가능성 판단

현재 보유한 드라이버는 `keyestudio TB6612FNG Motor Driver for Arduino`이다. 이 부품은 DC 모터 드라이버가 맞다. 다만 현재 모터의 정격 전류가 `1.5A`이므로 TB6612FNG를 최종 주행용 드라이버로 쓰기에는 전류 여유가 부족할 가능성이 크다.

판단 기준:

| 항목 | 판단 |
|---|---|
| 전압 | 모터 12V이므로 TB6612FNG 전압 범위와 대체로 맞음 |
| 정격 전류 | 모터 1개당 1.5A로 TB6612FNG 연속 전류 한계에 가까움 또는 초과 가능 |
| stall current | 아직 미확인. 정격 전류보다 훨씬 클 가능성이 있음 |
| 최종 주행용 적합성 | 보류. 더 큰 전류 여유의 드라이버 검토 권장 |

따라서 TB6612FNG는 낮은 부하의 짧은 기능 테스트에는 사용할 수 있지만, AMR 바퀴 구동 최종안으로 확정하기 전에는 발열, 전압강하, stall current를 반드시 확인해야 한다.

권장 조건:

- 모터 1개당 연속 전류 `1.5A` 이상을 안정적으로 처리할 수 있을 것
- stall current를 감당할 피크 전류 여유가 있을 것
- 좌우 모터 2개를 동시에 구동할 때도 과열되지 않을 것
- 12V 배터리 전압과 호환될 것

## 엔코더 입력 구조

엔코더 `A`, `B` 신호는 회전 방향과 속도를 알기 위한 입력이다.

권장 구조:

```text
V  ── 엔코더 전원
G  ── ESP32 GND
A  ── ESP32 interrupt-capable input
B  ── ESP32 interrupt-capable input
```

엔코더를 통해 나중에 할 수 있는 일:

- 좌우 바퀴 속도 측정
- 직진 보정
- 회전량 추정
- 모터 stall 감지
- 주행 거리 추정

## ESP32 핀 선정 시 주의점

현재 v7에서 이미 사용하는 핀:

| 기능 | 핀 |
|---|---|
| MQ-135 | GPIO34 |
| Flame sensor | GPIO27 |
| Emergency Stop | GPIO26 |

LiPo 측정 후보로는 GPIO35를 고려 중이다. 따라서 엔코더 A/B는 위 핀과 겹치지 않게 정해야 한다.

권장 후보는 실제 보드 핀맵을 확인한 뒤 정한다. 엔코더 입력은 빠른 변화가 있으므로 interrupt 사용 가능 여부를 확인하는 것이 좋다.

## 상태별 모터 action과 연결

현재 v7에는 실제 모터 제어 대신 action 분류만 있다.

| 상태 | Action | 모터 의미 |
|---|---|---|
| `SAFE` | `NORMAL_MOTION` | 정상 주행 가능 |
| `WARNING` | `LIMITED_MOTION` | 감속 또는 제한 주행 |
| `DANGER` | `STOP_MOTION` | 정지 |
| `STOP` | `STOP_MOTION` | 정지 |
| `SENSOR_ERROR` | `STOP_MOTION` | 정지 |

나중에 실제 모터 제어를 붙일 때는 `applyAmrAction()` 안에서 action별 모터 출력을 제한한다.

## 실제 구현 전 확인할 것

아래 정보가 확정되어야 모터 제어 코드를 안전하게 추가할 수 있다.

- 사용하는 모터 드라이버 모델
- 모터 1개당 정격 전류와 stall current
- 모터 드라이버의 최대 전류
- 모터 드라이버 제어 방식: `PWM/DIR`인지 `IN1/IN2`인지
- 엔코더 전원 전압: 3.3V 호환인지 5V 전용인지
- 엔코더 A/B 출력 전압
- 사용할 ESP32 핀

## 하드웨어 없이 지금 할 수 있는 테스트

- `determineAmrAction()`이 상태별 action을 올바르게 반환하는지 확인한다.
- `DANGER`, `STOP`, `SENSOR_ERROR`가 모두 `STOP_MOTION`인지 확인한다.
- 나중에 모터 제어 함수를 추가하기 전에도 action hook이 독립적으로 유지되는지 확인한다.

현재 Python 하네스는 이 action mapping을 검증한다.

## 실제 보드에서 확인할 항목

- 모터 드라이버 없이 ESP32에 모터를 직접 연결하지 않았는가?
- 모터 드라이버 GND와 ESP32 GND가 공통인가?
- 엔코더 V 전압이 ESP32 입력 허용 범위와 맞는가?
- 바퀴를 손으로 돌렸을 때 A/B 신호가 변하는가?
- 모터 구동 중 ESP32 reset이나 Serial 끊김이 없는가?

## 추천 다음 단계

1. 모터 드라이버 모델명을 확인한다.
2. 모터 드라이버 제어 핀 표기를 확인한다.
3. 엔코더 V/A/B/G 전압을 제품 문서나 멀티미터로 확인한다.
4. ESP32에서 사용할 엔코더 입력 핀 후보를 정한다.
5. 그 다음에야 `applyAmrAction()`에 실제 모터 제어를 연결한다.
