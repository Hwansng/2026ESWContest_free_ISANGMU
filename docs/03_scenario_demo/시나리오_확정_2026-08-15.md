## §1. 시나리오 서사 — 왜 이 구성인가

### 1.1 세계관

> **인화성 물질을 취급·보관하는 구역을 자율 로봇이 순찰하며,
> 격납이 깨진 용기를 식별해 격리하고, 발화원을 발견하면 대피한다.**

이 한 문장이 시나리오 전체를 지배한다. 색상 판정 규칙·센서 선정·비상 처리가 모두 여기서 파생된다.

### 1.2 🔵 색상 코드의 산업적 근거

적색과 황색을 다르게 판정하는 것은 **자의적 설계가 아니라 실제 표준과 일치**한다.

| 표준 | 🔴 적색 | 🟡 황색 |
|---|---|---|
| **NFPA 704** (소방 마름모) | **인화성** (Flammability) | **반응성·불안정성** (Instability) |
| **UN/DOT 위험물 표지** | Class 3 인화성 액체<br>Class 2.1 인화성 가스 | Class 5.1 산화성 물질<br>Class 7 방사성 |
| **산업안전보건법 안전보건표지** | 화학물질 취급장소의 유해·위험 경고 | 그 **외**의 위험 경고 |

**적색 = 인화성 → 새어나와야 위험하다**
인화성 액체는 액체가 타는 게 아니라 **증기**가 탄다. 밀폐된 소분 용기는 격납이 유지되고, 격납이 깨져 증기가 공기와 섞일 때 위험해진다.
→ **가스 AND 조건이 물리적으로 정확하다.**

**황색 = 반응성·산화성·방사성 → 존재만으로 위험하다**
반응성 물질은 충격·물 접촉만으로 반응하고, 산화성 물질은 주변 가연물의 연소를 격화시키며, 방사성 물질은 밀폐돼 있어도 방사선이 투과한다. 어느 쪽도 "누출"을 따질 대상이 아니다.
→ **무조건 격리가 표준 대응이다.**

### 1.3 🔵 세 구역이 하나의 사고로 연결된다

```
   적색(인화성 액체) + 누출    →  가연물 · 가연성 증기가 공기 중에 있다
   황색(산화성 고체)           →  산소 공급원 · 산화제가 같은 구역에 있다
   캔들(발화원) 발견           →  점화원 · 점화 에너지가 있다
   ──────────────────────────────────────────────────
   셋이 모이면 = 화재·폭발     →  즉시 대피가 유일한 정답
```

🔵 **점검점 셋이 화재 삼요소를 하나씩 담당한다** 〔2026-08-09 확장〕.
~~황색이 이 논리 밖에 있었다~~ — 「존재만으로 위험」이라 따로 놀았다. **산화성 고체로 확정되면서 삼요소 안으로 들어왔다** (§3.1).

| 점검점 | 물질 | 삼요소 |
|---|---|---|
| P1 · P2 | 적색 · 인화성 액체 | **가연물** |
| P3 | 🔵 **황색 · 산화성 고체** | 🔵 **산소 공급원** |
| P4 | 캔들 | **점화원** |

**나열이 아니라 하나의 사고 시나리오다.** 그리고 순회 순서가 그대로 서사가 된다.

> 🔵 **로봇은 치울 수 있는 것을 치우고, 못 치우는 것 앞에서는 물러난다.**
>
> 가연물을 격리하고(P2), 산화제를 격리하고(P3), **점화원은 치울 수 없으므로 스스로 물러난다**(P4).
> **후진 이탈(§4.2.1)까지 이 한 문장 안에 들어온다.** 발표·자막에서 이 인과를 명시할 것.

### 1.4 채택하지 않은 안 — 방폐물 서사

진우 코드의 `CONTAINMENT_BREACH` / `OVERPACK_DRUM` 네이밍 때문에 방폐물 서사도 후보였으나 **기각**했다.

| 기각 사유 | 내용 |
|---|---|
| 🔴 **센서 불일치** | MQ-2가 감지하는 것은 LPG·프로판·메탄·수소·연기 = 전부 인화성 가스. "방사능 누출을 가스 센서로 검출"은 심사에서 가장 먼저 찔릴 지점 |
| 🔴 **캔들의 부자연스러움** | 방폐장에 촛불이 있을 이유가 없다. §1.3의 인과가 성립하지 않는다 |

🔵 **`CONTAINMENT_BREACH`·`OVERPACK_DRUM` 용어는 그대로 유지한다.** 인화성 액체 드럼의 격납 파손 → 오버팩(손상 드럼을 더 큰 용기에 넣는 것)은 실제 표준 대응이므로 코드를 고칠 필요가 없다.


🔴 **2026-08-09 갱신 — 「구역 A·B·C」를 「점검점 P1~P4」로 바꾼다.**

| 종전 | 🔵 확정 |
|---|---|
| 구역 A (적색 2건) · 구역 B (황색) · 구역 C (캔들) | **P1** 적색 향X · **P2** 적색 향O · **P3** 황색 · **P4** 캔들 |
| 세트 = 구역 3개 | 🔵 **세트 전체가 취급구역 하나** |

**근거가 바뀌었다.** 종전 근거는 "내용이 서로 바뀔 수 있으니 Zone1=적색으로 굳지 않게"였는데, 실제 근거는 더 강하다 — **IEC 60079-10-1 에서 Zone 은 「그 장소에 반입 가능한 방폭 기기 등급」을 정하는 개념이라, "Zone 1 을 순찰한다"고 말하면 로봇이 Zone 1 인증 기기라고 주장하는 것이 된다.** §4.2 의 복귀 논리(로봇 자신이 점화원 후보)와 정면으로 충돌한다. 상세는 `docs/03_scenario_demo/시나리오_확정_보완_2026-08-16.md` §6.

🔵 **코드·통신·판정은 손대지 않는다.** `ZoneId.ZONE1~3`은 물리적 위치 식별자일 뿐이고, `<SENS>`에 구역 필드가 원래 없으며, 판정은 원래 구역을 보지 않는다. **바뀌는 것은 자막·나레이션·PPT·대시보드 표기뿐이다.**

### 2.3 출발 절차 — 점검 후 트리거

#### 왜 바꾸는가

현재는 노드가 뜨는 즉시 출발한다.

```python
# mission_orchestrator_node.py:113
self.transition(MissionState.PATROL)     # 🔴 부팅 = 출발
```

이 상태로는 **아래 어느 것도 확인하지 않고 출발한다.**

- ESP32 DRIVE가 아직 TCP 접속 전
- ENV 미접속 → 🔴 **가스 판정이 불가능한데 적색을 향해 간다**
- 배터리 저전압 / 카메라 미개방 / 정책 미로드

> 3분 원테이크 도중에 통신이 없어 멈추는 것보다, **출발 자체를 거부하는 편이 낫다.**
> 실패를 촬영 시작 **전**으로 당기는 것이 이 변경의 목적이다.

#### 트리거 방식 — `/mission/start` 토픽

| 안 | 손이 화면에 | 배선 변경 | 재촬영 비용 | 판정 |
|---|---|---|---|---|
| 부팅 즉시 출발 (현재) | 없음 | 없음 | 🔴 전 노드 재시작 | 🔴 폐지 |
| 🔵 **`/mission/start` 토픽** | **없음** (노트북은 프레임 밖) | **없음** | 🔵 **토픽만 재발행** | **채택** |
| 대시보드 버튼 | 없음 | 없음 | 낮음 | 🔵 상위호환 — 가능하면 채택 |
| 물리 버튼 | 🔴 있음 | 🔴 **납땜 문서 재작업** | 낮음 | 기각 |

**물리 버튼을 기각한 이유 두 가지**

1. 🔴 `배선_확정_2026-08-14.md`가 확정된 상태다. D-8에 배선을 되돌릴 이유가 없다
2. 🔴 버튼을 눌러도 RPi에 알릴 길이 없다 — **DRIVE TCP 클라이언트에 의존**하며, 그것이 §8.2의 가장 큰 미구현 덩어리다

> 나중에 물리 버튼을 원하면 **ESP32 DevKit의 BOOT 버튼(G0)** 을 배선 변경 없이 쓸 수 있다.
> 부팅이 끝나면 평범한 입력 핀이다. 다만 위 2번 의존은 그대로다.

#### 🔵 출발 전 점검 7항목

| # | 점검 | 실패 시 의미 |
|---|---|---|
| 1 | DRIVE TCP 접속 | 주행 불가 |
| 2 | ENV TCP 접속 | 🔴 가스·화염 판정 불가 |
| 3 | 배터리 ≥ 임계 | 중도 정지 |
| 4 | 🔵 **가스 기준선 안정** | **예열 미완** |
| 5 | 화염 미검출 | 시작부터 비상 |
| 6 | 비전 프레임 수신 중 | 감지 불가 |
| 7 | ACT 정책 로드 완료 | 파지 불가 |

🔵 **4번으로 「예열 후 촬영」이 사람의 기억이 아니라 코드로 보장된다.** 최근 N초간 MQ 값의 변동폭이 임계 이하일 때만 통과시킨다. 임계값은 §9-6에서 실측으로 정한다.

#### 구현

```python
# __init__ 끝 :113
- self.transition(MissionState.PATROL)
+ self.create_subscription(String, '/mission/start', self.start_cb, 10)
+ self.get_logger().info('IDLE — /mission/start 대기 중')
```

```python
def start_cb(self, msg):
    if self.state != MissionState.IDLE:
        self.get_logger().warn(f'IDLE 이 아니라 무시됨 (현재: {self.state})')
        return

    ok, reasons = self.preflight()
    if not ok:
        self.get_logger().error(f'출발 거부 — {", ".join(reasons)}')
        return                              # 🔴 조용히 출발하지 않는다

    self.get_logger().info('점검 통과 — 출동')
    self.transition(MissionState.PATROL)
```

🔵 **하트비트는 손댈 필요가 없다.** `heartbeat_active = True`가 `__init__:107`에서 이미 설정되므로 IDLE에 머물러도 `<HB>`는 0.3초마다 나간다. DRIVE는 `<MOVE>`가 없어서 서 있을 뿐 통신은 살아 있다 — 정확히 원하는 상태다.

발행:

```bash
ros2 topic pub --once /mission/start std_msgs/String "{data: 'GO'}"
```

`/mission/reset`과 대칭이므로 코드 패턴도 일관된다.

## §3. 위험물 판정 규칙

### 3.1 🔵 판정표 — 구역과 무관

| 감지 | 가스 | 판정 | 동작 |
|---|---|---|---|
| 적색 | 없음 | 정상 | **통과** (정지 후 재출발) |
| 적색 | 있음 | `CONTAINMENT_BREACH` | 파지 → 격리 |
| 황색 | 🔴 **조회하지 않음** | `HANDLE_CARE` | 파지 → 격리 |
| 화염 | — | 비상 | 부저 + 🔵 **후진 이탈** |

### 3.1.1 🔵 적색과 황색은 각각 무엇을 대리하는가 〔2026-08-09 확정〕

#### 🔴 넷 다 위험물이다. 위반의 종류가 다를 뿐이다

**IPA 도, 산화성 고체도, 누출 여부와 관계없이 언제나 위험물이다.** 위험물안전관리법상 지정 물질이라 밀폐돼 있어도 보관 장소·수량·표지가 규제 대상이다. **누출로 바뀌는 것은 분류가 아니라 상태다.**

| 점검점 | 분류 | 상태 | 위치 | 판정 |
|---|---|---|---|---|
| **P1** | 위험물 | 정상 | 정상 | **통과** |
| **P2** | 위험물 | 🔴 **이상** (격납 파손) | 정상 | 조치 |
| **P3** | 위험물 | 정상 | 🔴 **이상** (혼재 위반) | 조치 |
| **P4** | 발화원 | — | 🔴 **통로** | **이탈** |

🔴 **「P1 은 위험물이 아니다」로 말하면 §9.3 정직성 규칙에 걸린다** — *"내부 분류인 적색·황색을 실제 화학물질의 법적 분류처럼 설명하지 않는다."*

🔵 **코드는 이미 정확하다.** 상태명이 `CONTAINMENT_BREACH` — **격납 파손**이다. 「위험물 발견」이 아니라 **관리 상태가 깨졌다**는 뜻이고 그게 맞다. **나레이션이 코드를 따라가면 된다.**

| | 🔴 쓰지 않는다 | 🔵 쓴다 |
|---|---|---|
| P1 | *"밀폐가 유지된 용기는 **위험하지 않습니다**"* | *"**격납이 유지되고 있습니다.** 통과합니다"* |
| 판정 근거 | *"밀폐된 용기는 **안전하다**"* | *"밀폐된 용기는 **조치 대상이 아니다**"* |

「위험물인데 위험하지 않다」는 말장난처럼 들린다. 「위험물인데 격납이 유지되고 있다」가 현장 표현이다.

#### 🔵 적색 = 이소프로필알코올(IPA) 세정용 소분 용기

```
   세척 작업에 쓰는 용제 소분 용기 두 개가 보관 셀에 놓여 있다
   하나는 뚜껑이 제대로 닫혔고, 하나는 닫히지 않았다
```

| 근거 | |
|---|---|
| **형태** | 🔵 **뚜껑을 눌러 닫는 원형 소분 용기.** 「뚜껑을 비스듬히 얹으면 개방·파손이 자연스럽다」는 연출이 **소분 용기에서만 성립**한다 — 드럼은 마개 방식이라 안 된다 |
| **왜 위험한가** | 🔵 **액체가 아니라 증기가 탄다.** 격납이 유지되면 증기가 공기 중에 없다 — **P1 과 P2 의 차이 전부가 여기서 나온다** |
| 🔴 **MQ-2 가 반응하는가** | 🔵 **데이터시트에 알코올이 감지 대상으로 명시돼 있다.** 센서 스펙과 물질이 정확히 맞는다 |
| **황색과 유별이 다른가** | 🔵 **제4류(알코올류) ↔ 제1류(산화성 고체) = 혼재 금지.** 그리고 **산화제 + 알코올은 실제로 위험한 조합**이다 |
| **서사 정합** | 🔵 **IPA 는 반도체 세정의 대표 용제**다. 도입부가 Fab 안전관리인데 물질이 그 현장의 것이다 |

🔵 **P1↔P2 가 한 문장으로 닫힌다** — *"같은 작업자가 같은 물질을 같은 자리에 두었다. **하나는 제대로 닫았고, 하나는 안 닫았다.**"* 소분 작업이므로 **두 개가 나란히 있는 것도 자연스럽다.**

🔴 **「드럼」이라고 부르지 않는다** — 규격이 **높이 ≤ 지름**이라 만들면 납작한 소분 용기가 나온다. 200L 표준 드럼은 세로로 길다(880×580). **형태와 이름이 어긋나면 아는 사람 눈에 먼저 걸린다.** 「소분 용기」로 부른다.

> 🔴 **기각한 후보** — **LPG·부탄**(압력 용기라 형태가 안 맞고 뚜껑 연출이 불가능) · **가솔린**(주유소 연상) ·
> **신너·톨루엔**(도장 현장, 도입부와 거리) · **폐용제**(🔴 **P1 「제대로 닫아 보관 중」과 짝이 안 맞는다**).

> 🔵 **향에 대해서는 이렇게 말한다** — *"실제 용제 대신 향을 씁니다. **센서는 진짜로 반응합니다.**"*
> 모의 입력 주입이 아니라 **실제 가연성 연기를 실제 센서가 검출**한다. 물질만 대체품이다.

🔲 **도입 서사 추가 검토** — IPA 증기는 공기보다 무거워(비중 ~2.1) **바닥에 깔려 국소적으로 고인다.** 그래서 이런 물질의 고정 감지기는 바닥 근처에 다는데, **고정 감지기는 자기 자리만 본다.** *"순회 로봇은 낮은 높이로 여러 지점을 훑는다"* 가 **「왜 이동 로봇인가」의 두 번째 근거**가 된다. §1 도입 서사는 확정본이라 넣을지는 별도 판단.

#### 🔵 황색은 왜 가스를 조회하지 않는가 〔2026-08-09 근거 교체〕

> 🔴 **종전 근거 — 「반응성·산화성은 존재만으로 위험하다」. 약했다.**
> 산화제가 밀폐된 채 지정 장소에 있으면 위험하지 않다. 실제 규칙은 「존재 = 위험」이 아니라
> **혼재 금지·격리 저장**이다. *"보관하라고 만든 구역인데 왜 위험합니까"* 에 답이 궁색했다.
> 그리고 **황색을 왜 치우는지가 화면에 없었다** — 적색은 8/04 에 「개방·파손」으로 원인을 넣었는데
> 황색에는 그 작업을 하지 않았다.

🔵 **황색 = 산화성 고체(소분·계량 중인 분말)로 확정한다.**

| 근거 | |
|---|---|
| **왜 위험한가 ①** | 🔵 **유별 혼재 제한 위반.** 제1류 산화성 고체는 제4류 인화성 액체와 같은 곳에 둘 수 없다 |
| **왜 위험한가 ②** | 🔵 **용기가 열려 있다** 〔8/9 추가〕 — 개방된 산화제는 비산·오염되고 **인화성 증기가 닿을 수 있다** |
| 🔴 **왜 가스를 안 보나** | 🔵 **고체는 가연성 가스를 내지 않는다. MQ-2 가 볼 것이 물리적으로 없다** |
| **원인이 화면에 있나** | 🔵 **있다** — 세트 전체(위치) + **열린 뚜껑**(상태) |
| **판정이 위치를 아나** | 🔵 **아니다.** 취급구역은 하나뿐이라 「여기서 황색은 안 된다」가 상수다. 점검점 번호를 보지 않는다 |

#### 🔴 격리함이 원인을 건드리는가 — ②가 없으면 안 건드린다

> 🔴 **위반을 「위치」 단독으로 두면 조치가 원인을 해결하지 않는다** 〔8/9 발견〕.
> 격리함은 **P3 셀 안**에 있다. 로봇이 하는 일은 **산화제를 30cm 옆 상자에 넣는 것**이고,
> **인화성 취급구역 안이라는 사실은 그대로다.**
>
> 적색과 비대칭이다 — §6.2 가 적색 격리함의 근거로 든 **「이동 최소화」**가
> **황색에는 반대로 작용한다.** 산화제는 오히려 **밖으로 빼야** 한다.

🔵 **②(개방)를 근거에 넣으면 닫힌다.** 격리함 밀폐가 **실제로 해결하는 것**이 생긴다.

| 로봇이 하는 것 | 로봇이 안 하는 것 |
|---|---|
| **접촉 차단** — 밀폐 격리 | 🔴 **구역 밖 반출 — 사람의 몫** |
| **개방 상태 해소** — 뚜껑 | |
| **관제 보고** | |

🔵 **오버팩 논리가 그대로 적용된다.** §6.2 가 오버팩을 *"손상·누출 용기를 **통째로 담는** 더 큰 용기"* 로 정의했다. **개방된 용기를 그대로 통째로 담는 것이 정확히 오버팩**이고, 실제 절차도 개방 용기를 먼저 덮지 않고 오버팩에 넣는다.

🔵 **그리고 「초동 조치」가 이 프로젝트의 프레임이다** (보완 §3.1). **구역 밖 반출은 애초에 로봇의 몫이 아니다.** 나레이션이 *"반출은 관제에 보고합니다"* 로 끝나면 **「해결했다」가 아니라 「접촉을 끊고 넘겼다」**가 되고, 한계를 아는 팀으로 읽힌다.

> 🔵 **판정 대비표는 그대로다 — 층위가 다르다.**
> **판정**(센서가 쓰는 것)은 여전히 **색만**이다 — 로봇은 개방 여부를 **판정에 쓰지 않는다.**
> 개방은 **연출이자 서사**이고, **조치**(격리함)가 그것을 해소한다.
> *"상태를 보려면 재야 하고, 위치는 보는 것으로 끝난다"* 는 변하지 않는다.

> 🔴 **기각한 대안** — **황색 격리함을 스테이션 근처 등 딴 곳에 두는 안**은
> **물건을 들고 주행하게 되므로**(§6.2 가 명시적으로 배제) 쓰지 않는다.
> **격리함 없이 보고만 하는 안**은 파지 장면이 사라져 **한 정책이 두 물체를 처리한다는 증거**가 없어진다.
> 🟠 **P3 격리함 표기만 「반출 대기」로** 하는 선택지는 남겨 둔다 (규격은 3개 동일, 표기만 다르게).

🔴 **두 번째 줄이 이 선택의 핵심이다.** 「가스를 조회하지 않는다」가 **설계자의 선택이 아니라 물리적 사실**이 된다. *"왜 안 재나요"* → **"잴 게 없습니다."**

🔵 **적색과 위반의 종류가 다르다** — 적색은 *"밀폐돼야 할 것이 열렸다"*, 황색은 *"여기 있으면 안 될 것이 놓였다"*. **그래서 판정 절차도 다르다.**

| | 무엇이 문제인가 | 판정에 무엇이 필요한가 |
|---|---|---|
| **적색** | 🔵 **상태** — 격납이 깨졌나 | 색 + **가스** |
| **황색** | 🔵 **위치** — 여기 있으면 안 되나 | 색만 (**가스는 무의미**) |

🔴 **「왜 한쪽만 가스를 조회하는가」의 가장 짧은 답이다.**

> **상태를 보려면 재야 하고, 위치는 보는 것으로 끝난다.**

*"고체라 잴 게 없다"* 가 **물리적 근거**라면 이건 **절차적 근거**다. 둘이 같은 방향을 가리킨다.

> 🔴 **황색을 가연성 계열로 잡으면 판정 규칙 전체가 무너진다.** 인화성 고체·폐액·시료는
> 전부 기각했다 — 가연물이면 **MQ-2 가 반응해야 정상**이고, 안 재는 순간 설계 오류로 읽힌다.
> 방사성(Class 7 도 황색)은 소품으로도 부적절하다. 상세는 `docs/03_scenario_demo/demo_set_build_plan.md` §5.2.

### 3.1.2 🔵 세 지점이 각각 무엇을 반증하는가

**판정에 색과 가스가 모두 들어간다는 것은 한 지점으로 증명되지 않는다.**

| 지점 | 조건 | 무엇을 배제하나 |
|---|---|---|
| **P1** | 적색 · 가스 없음 | **기준점** |
| **P2** | 적색 · 가스 있음 | 🔴 **색만 보는 필터를 배제** — 색이 같은데 판정이 갈렸다 |
| **P3** | 황색 · 가스 없음 | 🔴 **가스만 보는 감지기를 배제** — 가스가 없는데 집는다 |

🔴 **P1·P2 만으로는 「가스를 쓴다」만 증명된다.** 색이 고정된 두 지점은 색에 대해 아무것도 말하지 못한다 — **가스만 보는 감지기도 똑같이 동작한다.** 「색을 쓴다」는 **P3 에서야 증명된다.**

> **발표·자막에서 쓸 문장**
>
> P2 — *"색이 같은데 판정이 갈렸다. **색만 보는 시스템이라면 P1 도 집었을 것이다.**"*
> P3 — *"가스가 없는데 집는다. **가스만 보는 시스템이라면 지나쳤을 것이다.**"*
>
> 🔴 **P2 에서 「색과 가스를 함께 보고 판단했다」고 말하지 않는다** — 그 시점엔 아직 증명되지 않았다.

🔲 **화면 조건** — 「가스가 없는데 집는다」가 성립하려면 **P3 도착 시 대시보드 가스 수치가 정상**이어야 한다. MQ-2 회복이 ~30초라 P2 의 향이 남으면 화면에 「노랗고 가스도 있네」가 뜬다. 판정은 안 틀리지만 **주장이 흐려진다** (§9-12).

**구역 내용이 서로 바뀔 수 있으므로 판정에 구역을 넣지 않는다.** 로봇은 눈앞에 있는 것을 보고 위 표만으로 결정한다.

### 3.2 🔴 진입 순서를 반전해야 한다

현재 `mission_orchestrator_node.py` 구조:

```python
def hazard_cb(self, msg):          # :157  가스 콜백
    if level >= 2 and self.state == MissionState.PATROL:
        self.transition(MissionState.DETECTED)      # 가스가 먼저 떠야만 진입

def vision_cb(self, msg):          # :171  비전 콜백
    if self.state == MissionState.DETECTED:
        self.transition(MissionState.CLASSIFY)
        self.transition(MissionState.APPROACH)      # CLASSIFY 를 그냥 통과
```

**문제 두 가지**

| # | 문제 | 결과 |
|---|---|---|
| 🔴 1 | 가스가 떠야만 `DETECTED` 진입 | **황색을 영원히 못 잡는다** (가스 무관이므로) |
| 🔴 2 | `CLASSIFY`가 이름만 있고 판정이 없다 | 적색 음성 사례(§2.2-4)를 걸러낼 자리가 없다 |

**확정 구조** — 비전이 먼저, 가스는 조회 대상

```
  vision_cb: 색 감지 → DETECTED          (가스와 무관하게 진입)
        ↓
  CLASSIFY:  §3.1 판정표 적용
        ↓                    ↓
   위험 → APPROACH      정상 → PATROL 복귀
```

### 3.3 `CLASSIFY` 의사코드

```python
def classify(self):
    color = self.detected_color

    if color == 'yellow':
        return HAZARD                      # 가스 조회 없음

    if color == 'red':
        if self.latest_gas >= GAS_THRESHOLD:
            return HAZARD                  # CONTAINMENT_BREACH
        else:
            return PASS                    # 🔵 정상 — 통과 판정을 로그·대시보드에 남긴다

    return PASS
```

🔲 `GAS_THRESHOLD` 값은 세트 제작 후 실측으로 정한다. 향을 넣은 소분 용기 앞 정지 위치에서의 MQ-2 값과, 향 없는 소분 용기 앞에서의 값 사이에서 잡는다. **두 값의 차이가 충분히 벌어지지 않으면 향의 양이나 용기 개구부를 조정한다.**

## §4. 비상 처리 — 두 종류로 분리한다

### 4.1 🔴 화재는 「정지」가 아니라 「복귀」다

현재 코드는 시나리오와 **정반대로** 동작한다.

```python
# mission_orchestrator_node.py:161
if data.get('type') == 'FLAME':
    self.transition(MissionState.EMERGENCY)

# :149  EMERGENCY 진입 시
    self.set_buzzer('1')        # ✅ 부저는 맞다
    self.emergency_stop_all()   # 🔴 heartbeat_active = False → DRIVE 가 그 자리에 선다
```

추가로, 해제에 사람이 필요하다.

```python
# :202
if data.get('confirm') != 'SAFE_TO_RESUME':
    return                      # 🔴 3분 영상 마지막에 사람 손이 들어간다
```

### 4.2 확정 — 비상 2종

| 종류 | 트리거 | 부저 | 주행 | 하트비트 | 해제 |
|---|---|---|---|---|---|
| 🔴 **`RETURN`** (신설) | **화염 감지** | ON | 🔵 **후진 이탈** (~~스테이션 복귀~~) | 🔵 **유지** | 이격 완료 시 자동 |
| `EMERGENCY` (기존) | 저전압 · 통신두절 · E-stop · 파지 3회 실패 | ON | **즉시 정지** | 차단 | `/mission/reset` (사람) |

> **화재는 "로봇을 못 믿겠다"가 아니라 "여기서 빠져나가라"다.**
> 주행 능력이 살아 있어야 하는 비상이므로 하트비트를 끊으면 안 된다.

### 4.2.1 🔵 이탈 방향 = 후진 〔2026-08-09 변경〕

> 🔴 **종전 — 「전진 그대로 스테이션 복귀」. 폐기됐다.**
> P4 가 스테이션 직전이라 **전진이 곧 복귀**라는 것이 근거였는데, 그 결과
> **로봇이 화염을 발견하고 화염 쪽으로 갔다.** 부저는 「위험」이라고 말하는데 바퀴는
> 평소 속도로 불 옆을 지나간다 — **경보와 동작이 어긋난다.**
> *"왜 불 쪽으로 갔습니까"* 에 **"스테이션이 그쪽이라서"** 밖에 답할 수 없다. 배치 사정이지 안전 논리가 아니다.

| 근거 | |
|---|---|
| **점화원을 화염에 접근시키지 않는다** | 이 로봇은 브러시 모터·LiPo·노출 ESP32 다. 🔴 **복귀 서사 자체가 「로봇이 점화원 후보」를 전제**한다 (보완 문서 §2). 그 전제와 전진 통과는 모순이다 |
| **역행 경로는 검증된 경로다** | 방금 지나온 길이다. 밀폐공간·유해물질 대응의 원칙이 **「진입 경로로 후퇴」** 다 |
| **물러남이 몸으로 읽힌다** | 자막 없이 읽히는 동작이다 |

**동작 순서 — 🔴 감지 즉시 후진하지 않는다.**

```
   화염 감지  →  정지  →  부저 ON  →  후진  →  정지 (부저 유지)
                 └──────────────────────────┘
              「봤다 → 판단했다 → 물러났다」 세 박자가 분리된다
```

주행 중 급후진은 실제 절차와도 다르고(멈춰서 판단하고 물러난다), 관성이 로봇팔 자세와 무게중심에 부담이 된다.

#### 🔴 후진은 라인을 따라가지 않는다 — 개루프 직선

**후진 라인 추종은 이 하드웨어로 불가능하다.** 게인 문제가 아니라 구조 문제다.

`y`= 차축 횡방향 오차, `θ`= 헤딩 오차, `d`= 센서 배열이 차축보다 **앞선** 거리, `e = y + d·θ`, `ω = −K·e` 로 두면

```
   s² + (K·d)·s + (K·v) = 0        2차계는 두 계수가 모두 양수일 때만 안정
```

| | `K·d` | `K·v` | |
|---|---|---|---|
| 전진 · `K>0` | + | + | ✅ 안정 |
| 후진 · `K>0` | + | **−** | 🔴 발산 |
| 후진 · `K<0` (부호 반전) | **−** | + | 🔴 발산 |

🔴 **`v<0` 이면 `K` 의 부호를 어떻게 잡아도 둘 중 하나가 음수다.** 부호를 뒤집으면 상수항이 살아나는 대신 1차항이 죽는다 — 맞바꾸기일 뿐이다.

🔵 **`d>0` 은 가정이 아니라 사실이다** — 전진 라인 추종이 되고 있다는 것 자체가 `K·d>0` 의 증거다. **전진에서 잘 도는 바로 그 이유가 후진에서 발산하는 이유다.** 물리적으로는 트레일러 후진의 잭나이프와 같은 구조다.

> **D 항으로도 안 된다** — `TCRT5000` 은 **디지털 5채널**이라 `e` 가 이산값 몇 개뿐이다. 미분하면 감쇠가 아니라 노이즈가 나온다.
>
> **진짜 해법은 후방 센서 배열**이다(후진 시 `d<0` 이 되어 `K<0` 과 함께 두 계수가 양수가 된다 — **부호 반전은 필요조건이지 충분조건이 아니다**). TCRT5000 5개 + GPIO 5개 + 마운트 + 감도 재조절이고 **확정된 배선을 건드린다.** 8/21 을 앞두고 주행 펌웨어를 흔들지 않는다.

🔵 **그리고 우리에게는 필요 없다.**

| | 오차 증가 | 600~800mm(3~5초)에서 |
|---|---|---|
| 폐루프 (부호 무관) | 🔴 **지수** | 짧은 구간에서도 이탈한다 |
| **개루프 직선 후진** | 🔵 **선형** — 모터 개체차만큼 | 5% 편차를 **~0.5mm 규모**로 잡고 있다 (`센서_지도` §5.1) |

**짧은 구간에서는 선형 드리프트가 지수 발산을 이긴다.** 폐루프를 억지로 돌리면 개루프보다 나은 것이 하나도 없으면서 발산 모드만 하나 는다.

🔵 **애초에 후진 구간에는 라인을 따라갈 이유가 없다** — 정지 위치가 「화염에서 이격」이지 「라인 위 어느 지점」이 아니고, 후진 후에는 주행이 끝난다.

🔴 **양쪽 모터 동일 PWM 역회전 · 고정 시간 · 정지.** 엔코더가 미결선이라 거리 명령은 쓸 수 없다.

> 🔴 **`KY-026` 이 안 보일 때까지 후진」은 쓰지 않는다.** 화염 검출은 깜빡이고 이탈 거리가 불꽃 크기에 따라 변한다. 로봇이 멈칫거리다 서거나 계속 뒤로 간다.

#### 정지 위치 — 기준 3개가 상하한을 만든다

## §5. 통신 — 시나리오 각 단계에서 무엇이 오가는가

### 5.1 채널

| 채널 | 노드 | 포트 | 상대 | 방향 |
|---|---|---|---|---|
| DRIVE | `amr_bridge` | 5000 | ESP32 DRIVE | 양방향 |
| ENV | `sensor_bridge` | 🔴 **8765** (문서는 5002 — §9-2) | ESP32 ENV | 현재 수신 전용 |
| 로봇팔 | `arm_bridge` | 5001 | `arm_act_node` (RPi 내부) | 양방향 |

프레임: `<CMD,필드…,CS>\n` · `CS = sum(ord(c)) % 256`
DRIVE 수신 실제 바이트: `<HB,138>\n` · `<STOP,70>\n` · `<MOVE,L,R,CS>\n`

### 5.2 시나리오 시퀀스

| 단계 | ENV → RPi | RPi 내부 | RPi → DRIVE | RPi → ENV |
|---|---|---|---|---|
| 대기·출발 | `<SENS>` 100ms | `IDLE`→`PATROL` | `<HB>` 0.3s | — |
| 주행 | ↓ | `PATROL` | `<HB>` + `<MOVE>` | — |
| 적색 ① 통과 | ↓ | `CLASSIFY` → **PASS** | `<MOVE>` 정지→재출발 | — |
| 적색 ② 위험 | 가스값 상승 | `CLASSIFY` → HAZARD | `<MOVE,0,0>` | — |
| 파지 | ↓ | `arm_act_node` (5001) | 정지 유지 | — |
| 격리 | ↓ | `ISOLATE` | 근거리 `<MOVE>` | — |
| 🔥 화염 | `FLAME` 필드 | `RETURN` | 🔵 `<HB>` **유지** + `<MOVE>` | 🔴 **`<BUZZ,1>`** (§9-3) |

🔵 **주행 제어는 RPi를 거치지 않는다.** 라인트레이싱·ToF 회피는 DRIVE의 20ms 로컬 루프가 직접 한다. RPi는 미션 수준(어디서 멈출지, 무엇을 집을지)만 관여한다.

### 5.3 🔵 구역 번호는 통신에 넣지 않는다

`<SENS>`에 구역 필드가 없고 `current_zone`을 갱신하는 코드도 없지만, **추가할 필요가 없다.**

| 구역이 필요한 곳 | 해결 |
|---|---|
| DRIVE의 ToF 임계값 | 🔵 이미 DRIVE 안에 있음. 🔵 **300mm 단일로 단순화** 〔8/9〕 — ~~직선 1000 / 코너 300 구간 전환~~ 및 마커 순번 기반 전환 로직 폐기 (`docs/06_firmware/센서_지도.md` §4.1) |
| 격리함 위치 | 🔵 구역마다 물리적으로 존재 → "눈앞의 격리함"이면 충분 |
| 대시보드·자막 표시 | 없어도 데모는 돈다 |

→ **구역 필드 추가는 후순위.** §8의 항목을 먼저 처리한다.

```python
DESTINATION_BY_CLASS = {          # 🔴 구역별 격리함이면 삭제 대상
```

### 6.3 🔴 배치 순서 규칙 — 반드시 지킬 것

> **향 없는 적색 소분 용기을 향 있는 적색 소분 용기보다 먼저 배치한다.**

MQ-2의 **회복 시간은 약 30초**이며, 이는 **예열과 무관한 물성**이다. 순서가 뒤집히면 잔류 가스 때문에 정상품을 위험물로 오판하고, 데모의 핵심 장면이 그대로 실패 장면이 된다.

| | 응답 시간 (T90) | 회복 시간 | 예열로 해결되는가 |
|---|---|---|---|
| MQ-2 | ≈10초 | ≈30초 | 🔴 **아니오** — 예열은 기준선 안정화이지 응답 속도가 아니다 |

### 6.4 🔵 음성 사례를 넣는 이유

**산업적 근거** — 실제 누출 관리 제도는 모든 용기를 뜯지 않는다. 임계값으로 정상과 누출을 가른다.

| 제도 | 판정 방식 |
|---|---|
| LDAR (EPA Method 21 / 국내 비산배출 저감제도) | 부품별 임계 농도 미만이면 **"누출 아님"으로 통과** |
| 가스누출감지경보기 (KGS·안전보건규칙) | 폭발하한계(LEL) 25% 이하에서 경보 — 미만은 정상 |

> **현장에서 비싼 것은 위험을 찾는 능력이 아니라, 정상을 정상이라고 판단하는 능력이다.**
> 적색 소분 용기을 전부 격리하면 정상 재고까지 뜯어내고 조업이 멈춘다.

**심사 근거**

| | 영상에 보이는 것 | 판정 |
|---|---|---|
| 음성 사례 없음 | 적색을 보고 집었다 | 🔴 **컬러 필터와 구분 불가** |
| 음성 사례 있음 | 적색을 보고 **지나쳤고**, 다른 적색은 집었다 | 🔵 센서 융합으로 **판단**한다 |

심사는 영상만 본다. **보이지 않는 기능은 없는 기능이다.** 또한 "그냥 빨간 거면 다 집는 것 아닙니까"라는 질문 자체가 성립하지 않게 된다.

**비용** — 10초. 파지가 없으므로 실패 리스크가 사실상 0.

### 6.5 🔴 「통과」가 영상에서 읽혀야 한다

그냥 지나가면 **"판단해서 통과"와 "못 봤다"가 구분되지 않는다.**

| 방법 | 채택 |
|---|---|
| 🔵 **잠깐 정지 → 재출발** | **채택** — "봤고, 재고, 통과시켰다"가 동작으로 보인다 |
| 🔵 **대시보드에 `적색 감지 · 가스 정상 · 통과`** | **채택** — 판정 근거가 문자로 남는다 |
| LED 색 구분 (감지 = 주황 / 위험 = 적색) | 선택 |
| 자막 | 최후 보루 |

## §7. 촬영 계획

### 7.1 시간 예산

가스 예열은 촬영 전 완료하므로 제외한다. 아래 12초는 **응답 시간**이며 접근 주행 중 노출이 시작되는 만큼을 뺀 값이다.

| 구간 | 초 |
|---|---|
| 대기 + 출발 + 구역 A 주행 | 25 |
| 🔵 적색 ① 정지·판정·통과 | 10 |
| 적색 ② 감지 + 접근 + 가스 확정 | 12 |
| 파지 (ACT) | 20 |
| 격리 (구역 내) | 12 |
| 구역 B 주행 | 15 |
| 황색 감지 + 접근 | 8 |
| 파지 | 20 |
| 격리 | 12 |
| 구역 C 주행 | 15 |
| 캔들 감지 + 부저 + 복귀 | 20 |
| **합계** | **169** |

**제한 180초. 여유 11초.**

### 7.2 🔴 파지 재시도 1회면 예산을 넘긴다

`MAX_RETRY = 3` 이고 재시도 1회당 약 15초다. **여유 11초로는 재시도를 한 번도 감당할 수 없다.**

→ **배속 편집은 완성도용이 아니라 보험이다.** 주행 구간은 배속해도 잃는 것이 없고, 판정·파지 장면은 실속으로 보여줄 수 있다.

### 7.3 편집 방침

| 구간 | 처리 |
|---|---|
| 주행 (구역 간 이동) | 🔵 배속 |
| 적색 ① 통과 판정 | 🔴 **실속 유지** — 핵심 장면 |
| 파지 | 🔴 **실속 유지** — ACT 시연 |
| 격리 투입 | 실속 또는 소폭 배속 |
| 복귀 | 배속 |

### 7.4 🔵 구역 배치 — 확정

> **화재 구역(캔들)을 스테이션 직전에 배치한다.**

순환 루프이므로 화염 감지 후 **그대로 전진하면 복귀가 끝난다.** 되돌아가는 배치는 복귀 시간을 두 배로 만든다. §7.1의 복귀 20초는 이 배치를 전제로 한 값이다.

구역 내용이 서로 바뀔 수 있다는 조건 덕분에 **배치만 바꿔서 20초를 벌 수 있다** — 코드도 세트도 손대지 않는다.

### 7.5 🔵 반복 촬영이 가능해진다

§2.3의 출발 절차를 적용하면 복귀 완료 후 `IDLE`로 돌아가고, 다시 `/mission/start`를 쏘면 재출발한다. **노드를 재시작하지 않고 반복 촬영이 된다.**

🔴 이것이 §7.2("파지 재시도 1회면 예산 초과")의 실질적 보험이다. 예산을 지키는 방법은 재시도를 없애는 것이 아니라 **잘 나온 테이크를 고르는 것**이다.

### 7.6 오프닝 장면

대시보드에 §2.3의 점검 7항목이 순차로 통과되는 화면은 그 자체로 시스템 완성도를 보여준다. 5초면 충분하고, "관제에서 출동 지령을 하달한다"는 서사가 실제 산업 AMR과 일치한다.

🔲 대시보드로 할지 로그 화면으로 할지는 §9-7의 완성도 확인 후 정한다.
