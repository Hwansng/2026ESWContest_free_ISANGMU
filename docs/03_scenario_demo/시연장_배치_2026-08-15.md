## §1. 시나리오

### 1.1 한 문장

> **인화성 물질을 취급하는 구역을 자율 로봇이 순찰하며,
> 격납이 깨진 용기만 골라 격리하고, 발화원을 발견하면 경보와 함께 대피한다.**

### 1.2 로봇이 내리는 판단은 네 가지뿐이다

| 본 것 | 가스 | 판단 | 행동 |
|---|---|---|---|
| 적색 | ✗ | 정상 | 🔵 **통과** — 이 데모의 핵심 |
| 적색 | ✓ | 격납 파손 | 파지 → 격리 |
| 황색 | 무관 | 반응성 물질 | 파지 → 격리 |
| 화염 | — | 발화원 | 부저 + 복귀 |

🔵 **점검점 번호는 판단에 들어가지 않는다.** 점검점 내용이 서로 바뀔 수 있으므로, 로봇은 눈앞에 있는 것만 보고 위 표로 결정한다. 지점 ID 는 **기록용**이다 — LDAR 제도와 같은 구조다 (§2.1).

적색과 황색을 다르게 다루는 근거(NFPA 704 · UN 위험물 표지 · 산업안전보건법)는 상위 문서 §1.2에 있다. 요지는 **적색=인화성이라 새어나와야 위험하고, 황색=반응성이라 존재만으로 위험**하다는 것이다.

### 1.3 세 사건이 하나의 사고로 연결된다

```
   적색 소분 용기에서 인화성 증기가 샌다   →  가연물이 공기 중에 있다
   같은 순찰로에 촛불이 있다          →  점화 에너지가 있다
   ─────────────────────────────────────────────────
   둘이 만나면 화재·폭발              →  즉시 대피가 유일한 정답
```

### 1.4 시연 흐름 14단계

```
  ①  스테이션 대기       점검 7항목 통과 대기 (IDLE)
  ②  /mission/start     출동
  ③  P1 도착            정지
  ④  적색(향 없음)       판정 → 🔵 통과 · 재출발
  ⑤  P2 도착            정지 → 적색(향 있음) → 가스 확인 → 위험 판정
  ⑥  파지               ACT · 손목 카메라 1뷰
  ⑦  격리               P2 격리함 투입
  ⑧  P3 이동            라인 주행
  ⑨  노란 종이컵         가스 조회 없이 위험 판정
  ⑩  파지 · 격리         P3 격리함 투입
  ⑪  P4 이동            라인 주행
  ⑫  캔들 감지           🔥 정지 → 부저 ON · RETURN (정지 아님)
  ⑬  🔵 후진 이탈        개루프 직선 후진 · 라인 추종 없음
  ⑭  종료               이격 지점 정지 · 부저 유지 — IDLE
```

## §2. 시연장 배치

### 2.1 🔵 구조 — 취급구역 하나, 그 안의 점검점 4곳 (2026-08-09 확정)

> **전체 세트가 「인화성 물질 취급·보관 구역」 하나다. 내부를 Zone 으로 나누지 않는다.**

| 종전 | 🔵 확정 |
|---|---|
| 구역 A · B · C | **점검점 P1 · P2 · P3 · P4** |
| "구역마다 판정이 다를 수 있다"는 오해 여지 | 🔵 **모든 점검점에 같은 절차** |
| 로봇이 3개 구역을 넘나든다 | 🔵 **구역 하나 안에서만 움직인다** |

#### 🔴 왜 Zone 을 쓰지 않는가

**IEC 60079-10-1(KS C IEC 60079-10-1)에서 Zone 은 「그 장소에 반입할 수 있는 방폭 기기 등급」을 정하는 개념이다.** 로봇이 무엇을 하는지와는 무관하다.

```
   Zone 0   폭발성 분위기가 연속·장기간·빈번하게 존재   ← 가장 위험
   Zone 1   정상 운전 중 주기적으로 존재
   Zone 2   정상 운전 중 존재하지 않음 (짧은 기간만)    ← 가장 덜 위험
   Zone 3   🔴 존재하지 않는 등급
```

문제가 두 가지다.

| # | 문제 |
|---|---|
| 🔴 1 | "Zone 1 → 2 → 3"은 표준을 아는 사람에게 **위험도가 낮아지는 순서 + 없는 등급**으로 읽힌다 |
| 🔴 2 | **"우리 로봇이 Zone 1 을 순찰한다" = "이 로봇은 Zone 1 방폭 인증 기기다"** 라는 주장이 된다. HazardBot 은 브러시 모터·LiPo·ESP32 를 노출한 구조이고, 복귀 서사 자체가 「로봇이 점화원 후보」를 전제한다 — 앞뒤가 맞지 않는다 |

#### 🔵 실제 순찰 운용의 단위는 점검점이다

| 제도·사례 | 단위 | 운용 |
|---|---|---|
| **LDAR** (EPA Method 21 / 국내 비산배출 저감제도) | TAG 부여된 **점검 지점** | 사업장 하나에 수천 지점, **전부 같은 절차**. 지점 ID 는 기록용이고 판정을 바꾸지 않는다 |
| 가스누출감지경보기 (KGS·안전보건규칙) | 감지기 **설치 지점** | 가스 비중·누출원 위치로 지점 선정 |
| 4족·AMR 순찰 로봇 | **waypoint + 점검 태그** | 경로 위 각 지점에 "여기서 무엇을 볼지"가 붙는다 |

→ 상위 문서 §0-5 「판정은 구역을 몰라야 한다」와 **같은 구조다.** 설계는 이미 맞았고, 어긋나 있던 것은 이름뿐이었다.

#### 코드·통신은 손대지 않는다

| 대상 | 변경 |
|---|---|
| `ZoneId.ZONE1~3` | 🔵 **없음** — 물리 위치 식별자로 이미 격리돼 있다 |
| 통신 프로토콜 | 🔵 **없음** — `<SENS>` 에 구역 필드가 원래 없다 |
| 판정 로직 | 🔵 **없음** — 원래 구역을 보지 않는다 |
| 자막 · 나레이션 · PPT · 대시보드 | 🟠 **"구역 A/B/C" → "점검점 P1~P4"** |

### 2.2 🔵 소구획 — 점검점마다 ㄷ자 한 쌍 (2026-08-09 확정)

> **큰 방을 만들지 않는다.** 점검점마다 작은 ㄷ자 칸막이 2개를 마주 보게 두어
> **물체를 담는 셀**을 만들고, 🔵 **주행 라인이 그 셀을 가로지른다** 〔2026-08-09 개정〕.

```
   【 셀 하나 · 관통형 】

              ║  주행 라인
       ┌──────╫──────┐
       │      ║      │
       │  ◉   ║      │   ← 물체 + 얕은 링은 라인 옆, 로봇과 같은 공간 안
       │      ║      │
       └──────╫──────┘
              ║
       개구부 = 🔴 차체가 통과하는 너비
```

> 🔴 **종전은 「라인 옆에 셀, 그리퍼가 개구부로 진입」이었다** 〔8/9 개정〕.
> 이제 **로봇이 개구부로 들어가 안에서 서고 반대쪽으로 나온다.**
>
> 🔵 **얻는 것** — 「진입」이 동작이 되어 현장감이 늘고, **P4 의 트인 통로와 대비가 강해진다.**
> 그리고 **그리퍼 진입 문제가 사라진다** — 종전엔 그리퍼가 개구부를 통과해야 해서 접근면 폭이
> 실패 지점이었는데, 이제 로봇이 이미 안에 있다. 검증이 **「차체가 지나가는가」**로 바뀌어
> 한 번 주행시켜 보면 끝난다.
>
> 🔴 **벽을 키우지 말 것. 문제가 되는 건 「관통」이 아니라 「벽이 높아지는 것」이다** —
> ① 조명 그림자(NoIR 색 분리가 최대 미해결 항목인데 가장 약한 곳을 때린다) ② 촬영 각도(파지가
> 핵심 컷인데 상자 안이면 위·양 끝에서만 찍힌다) ③ 측면 충돌(소프트 실패가 하드 실패로) ④ ToF.

```
   【 코스 전체 】

                        ┌──┐  ┌──┐
                        │  P3 황색  │      ← 적색과 떨어뜨린다 (혼재 제한)
                        └──┘  └──┘
          ┌────────────────────────────────────┐
          │                                    │
          ▲             시계 방향 ▶              ▼
   ┌──┐ ┌──┐                                P4 🔥 캔들
   │ P2 적색 향O │                          🔴 구획 없음 — 통로
   └──┘ └──┘                                   │
   ┌──┐ ┌──┐                                   │
   │ P1 적색 향X │                               │
   └──┘ └──┘                                   │
          │                                    │
          └────────── ⚡ 스테이션 ◀─────────────┘
                     🔴 구획 없음
```

#### 🔵 이 배치는 「왜 여기서 멈추는가」를 스스로 설명한다

실제 현장에서 점검점이 특정 위치에 있는 이유는 **거기에 구획이 있기 때문**이고, 구획이 나뉜 이유는 임의가 아니다.

| 근거 | 내용 | 우리 배치와의 대응 |
|---|---|---|
| **위험물안전관리법 — 유별 혼재·혼합저장 제한** | 유별이 다른 위험물은 원칙적으로 같은 저장소에 둘 수 없고, 예외 조합도 일정 간격 이상 이격이 요구된다 | 🔵 **적색 = 제4류(인화성 액체) / 황색 = 산화성·자기반응성 계열** → **애초에 같은 칸에 둘 수 없다.** P2 와 P3 가 분리된 이유가 여기서 나온다 |
| **화학물질관리법 — 보관·저장시설의 방류벽·방지턱** | 누출물이 퍼지지 않게 보관 구역을 낮은 둑으로 두른다 | 🔵 ㄷ자 칸막이의 **형태 자체가 이것이다** |
| **LDAR** (EPA Method 21) | 점검 대상은 **잠재적 누출원이 있는 물리적 지점**이고 거기에 TAG 가 붙는다 | 🔵 셀 = 누출원이 있는 곳 = **TAG 가 붙을 자리** |

#### 🔵 가장 강한 효과는 P4 에서 나온다 — 구획을 두르지 **않기** 때문에

```
   구획이 있다  →  보관 지점  →  점검 대상        P1 · P2 · P3
   구획이 없다  →  통로       →  아무것도 없어야 함
   ─────────────────────────────────────────────────────────
   그런데 통로에 불이 켜져 있다                    P4  🔥
```

🔴 **캔들에는 구획을 두르지 않는다.** 발화원은 보관물이 아니다. 구획을 두르면 「발화원을 보관하는 칸」이 되어 §1.3 의 인과가 무너진다.

반대로 **구획이 없다는 사실 자체가 P4 를 비정상으로 만든다.** 다른 셋은 제자리에 있고 이것만 통로에 있다 — 자막 없이도 「여기 있으면 안 되는 것」이 읽힌다. 스테이션도 같은 이유로 구획 없이 둔다.

> **구획의 유무가 「보관물 / 이물」을 가르는 문법이 된다.** 큰 방으로는 만들 수 없는 효과다.

#### 구획은 Zone 과 다른 개념이다 (§2.1 재발 없음)

| 개념 | 무엇인가 |
|---|---|
| **Zone** (IEC 60079) | 🔴 무엇을 **들여놓을 수 있나** — 기기 자격 |
| **방화구획**(건축법·소방시설법) · **방류벽·방지턱**(화학물질관리법) · **방유제**(위험물안전관리법) | 🔵 무엇이 **새어나가지 못하게 하나** — 화재·누출 방호 |

구획은 로봇에 대해 아무 주장도 하지 않는다. 개구부가 있는 것도 맞다 — 실제 위험물 구획은 밀폐가 아니라 **환기가 요구**된다.

### 2.3 🔴 소구획 사양

| 항목 | 값 | 근거 |
|---|---|---|
| 개수 | **P1 · P2 · P3 에 각 ㄷ자 2개 = 6개.** 🔴 P4·스테이션은 없음 | 구획 유무가 「보관물 / 이물」을 가른다 |
| 🔴 **높이** | **물체 높이의 1/3~1/2 수준** (🔲 실측 확정) — 방지턱 정도 | 🔴 높으면 **팔이 부딪히고 손목 화각을 먹는다.** 배경 통제 욕심으로 키우지 말 것 |
| 개구부 | 🔵 **진입면 + 진출면.** 라인이 둘을 관통한다 | 실제 보관 구획의 접근면은 통로 쪽이다 |
| 🔴 **개구부 폭** | 🔵 **차체 260 + 산포 ±30 + 여유 → 🟠 400 내외** (🔲 실측) | ~~그리퍼 최대 개방 폭~~ — **기준이 그리퍼에서 차체로 바뀌었다** |
| 셀 내경 | 차체 + 팔 동작 여유 + 얕은 링 | 로봇이 안에 서서 옆의 물체를 잡는다 |
| 🔲 **ToF 장착 높이 ↔ 벽 높이** | **둘 다 미확정.** 🔴 **벽을 먼저 정하고 ToF 를 맞춘다** | 벽 높이는 **촬영·팔·화각**이 정하고 되돌릴 수 없다. ToF 는 높이·임계·**ROI** 세 손잡이가 있다 |
| 🔴 **색** | **무채색 (흰색 또는 회색)** | 적색·황색 계열 금지. 🔴 **크림·베이지도 금지** — 종이컵과 Hue 가 겹친다 (§7.3) |
| 표면 | 무광 | 반사광이 HSV 를 흔든다 |
| 재질·고정 | 가볍고 **바닥 테이프 고정** | 부딪혀도 물체가 튀지 않게 |
| P1 ↔ P2 | 🔵 **인접한 두 셀** | 같은 제4류라 인접 셀이 자연스럽다 |
| P2 ↔ P3 | 🔵 **떨어뜨린다** | **혼재 제한** — 이게 서사의 핵심 |
| 🔴 **표지** | **부착 금지** | 형태가 설명하게 둔다. 실제 내용물이 없는 모형이다 |

## §4. 물체

### 4.1 목록

| # | 물체 | 형상 | 비고 |
|---|---|---|---|
| ① | 적색 소분 용기 (향 없음) | 원기둥 | 🔵 **음성 사례** — 통과 시연 |
| ② | 적색 소분 용기 (향 있음) | 원기둥 | 향을 내부에 넣고 개구부로 확산 |
| ③ | 🔵 **노란색 종이컵** | 원뿔대 | 🔴 변형체·경량 — §4.3 |
| ④ | 캔들 | — | 🔴 **실화 필요** (§7.4) |

🔵 **①②③ 모두 축대칭이다.** 자세각 θ가 파지에 무관하고 x·y만 맞추면 된다.

### 4.2 얕은 링

바닥에 고정해 **측면 이탈만** 막는다. 트레이가 아니다 — 원기둥은 이미 자세와 높이가 상수라 트레이는 z 오프셋만 더한다.

| 항목 | 값 |
|---|---|
| 높이 | 5~10mm |
| 내경 | 물체 지름 + 2~4mm |
| 🔴 종이컵용 | **밑지름 기준** — 컵은 테이퍼져 위아래 지름이 다르다 (예: 상 70 / 하 50mm) |

### 4.3 🔴 종이컵이 만드는 차이

**① 변형체 — 파지 허용오차가 좁다**

| | 강체 소분 용기 | 종이컵 |
|---|---|---|
| 너무 벌리면 | 놓친다 | 놓친다 |
| 너무 조이면 | 🔵 **서보가 벽에 막혀 멈춘다** (부하 상승 = 성공 신호) | 🔴 **찌그러진다.** 멈출 벽이 없다 |

ACT는 위치 제어다 — 학습한 그리퍼 위치를 재현한다. 강체는 "조금 더 조임"을 하드스톱이 흡수하지만 **종이컵은 흡수 구간이 없다.** → §6.5의 물리 대책이 필수.

🔵 진우 코드가 이미 이걸 전제한다:

```python
GRIP_THRESHOLD_BY_CLASS = {
    CONTAINMENT_BREACH: 80,   # 적색 강체
    HANDLE_CARE:        40,   # 🔵 황색 — 낮은 부하에서 성공 판정
}
```

> 🔵 **심사에서 쓸 수 있는 이야기다.** "물체 종류를 인식해 파지 강도를 바꾼다"는 실제 구현된 능력이고, 대시보드에 임계값을 띄우면 영상에서 보인다.

**② 🔴 경량 — 환기 요구와 충돌한다**

빈 컵은 5~10g이다. §7.2는 향 누적을 막기 위해 환기를 요구하는데 **바람이 컵을 넘어뜨린다.**

| 대책 | 내용 |
|---|---|
| 🔵 컵 안에 소량의 무게추 | 동전·와셔. 바닥에 고정 |
| 🔵 환기는 **테이크 사이에만** | 촬영 중 정지 |
| 링 고정 | 측면 이탈 방지 |

🔴 **무게추는 데이터 수집 전에 넣는다.** 무게가 바뀌면 서보 부하 프로파일이 바뀐다.

**③ 🔴 소모품**

찌그러진 컵은 재사용 불가다. 재사용하면 카메라에 다르게 보여 ACT 입력 분포가 깨진다.

- 🟠 **여분 10개 이상** · 🔴 **전부 같은 제품·같은 로트** (로트가 다르면 색이 미묘하게 다르다)

**④ 🟠 파지 위치 — 몸통 하단**

| 안 | 평가 |
|---|---|
| 🟠 **A. 몸통 하단** | 🔵 **소분 용기와 같은 동작 계열** → ACT 학습 부담 최소. **채택 권고** |
| B. 테두리(림) | 림이 단단하지만 🔴 소분 용기와 완전히 다른 동작 → 데이터 2배 |
| C. 뒤집어 놓기 | 안정적이지만 용기로 안 보인다 (서사 약화) |

**⑤ 🔵 위험 표식**

카메라에 종이컵은 그냥 종이컵으로 보인다. **황색 위험 표식 스티커**를 붙이면 §1.2의 표준 기반 서사가 화면에서 완성된다. 종이 한 장 값이다.

🔴 **표식도 데이터 수집 전에 붙인다.** 손목 카메라가 보는 화면이 바뀐다.

## §5. 격리함

| 항목 | 값 |
|---|---|
| 개수 | 🔵 **3** — 🔵 **파지가 일어나는 점검점마다 1개(P2·P3) + 예비 1** |
| 형태 | 🔵 **흰색 육각 기둥 + 몸통에 경첩으로 붙은 뚜껑** 〔2026-08-09 확정〕 (~~위가 열린 상자~~) |
| 크기 | 🔲 물체 지름 + 여유. 실측 후 |
| 높이 | 🔴 **하한이 생겼다** — ~~낮을수록 좋다~~. **가장 큰 물체가 어떤 자세로 앉아도 뚜껑 아래**여야 한다 |
| 고정 | 바닥에 테이프 (투입 충격으로 밀리면 안 됨) |
| 방향 | 🔴 **평평한 면이 로봇을 향한다** — 꼭짓점이 아니다 |
| 정렬 | 🔲 §11-3 — **정지마커 기준 고정 오프셋 권장** |

🔵 **필요 개수는 2개다** — P1 은 통과 판정이라 파지가 없고, P4 는 캔들이다. 3번째는 **점검점 내용을 바꿀 때를 위한 예비**다. 세트 제작 부담이 크면 2개로 줄여도 시나리오는 성립한다 (🔲 §11-10).

🔴 **비전으로 격리함을 찾지 않는다.** 파지 정렬(VGR)이 이미 어려운데 투입 정렬까지 비전에 맡기면 실패 지점이 하나 더 는다.

### 🔵 뚜껑 — 밀어서 닫는다 〔2026-08-09 신설〕

**투하로 끝나지 않는다. 봉쇄가 화면에서 완결된다.** 상세 규격은 `docs/03_scenario_demo/demo_set_build_plan.md` §5.5.1.

| 항목 | 값 |
|---|---|
| 방식 | 🔵 **경첩식** — 그리퍼를 닫은 채 위에서 앞으로 쓸어내린다 |
| 경첩 위치 | 🔴 **로봇 반대편 면** — 열린 뚜껑이 투입 경로 뒤쪽으로 비킨다 |
| 끝점 | 🔴 **수직을 조금 넘긴 지점에서 손을 뗀다.** 나머지는 중력이 닫는다 |
| 담당 | 🔵 **프리셋** — 격리함이 고정이라 학습할 변수가 없다. ACT 는 파지까지 |
| 안쪽 면 | 🔵 **대비색** — 열림/닫힘을 손목 카메라가 구분한다 |
| 열림 각도 | 🔴 **백스톱으로 매번 같게** |

🔴 **닫힌 위치까지 눌러 앉히지 않는다.** 끝점에 하드스톱이 생기면 **Load 세이프티 클램프(80%)가 파지 판정용 신호에서 오작동**한다. 「닫는다」가 아니라 **「넘어뜨린다」**로 설계한 이유다.

🔴 **당기지 않는다.** 뚜껑 모서리를 걸어야 해서 파지에 준하는 정밀도가 다시 필요해진다.

🔵 **뚜껑 닫기까지 텔레옵으로 시연해 녹화한다** — 학습에 넣을지는 나중에 정해도 되지만, **안 찍으면 전량 재수집**이다 (`시나리오_확정_보완` §8.2).

## §6. 🔵 파지 방식 — 둘 다 ACT (2026-08-05 확정)

### 6.1 확정

| 항목 | 확정 |
|---|---|
| 적색 소분 용기 | 🔵 **ACT** (종전: 프리셋 + 비전 오프셋 보정) |
| 황색 종이컵 | 🔵 **ACT** |
| 정책 개수 | 🔵 **1개** — `POLICY_PATHS` 클래스별 2개 → 통합 |
| VGR | 🔵 **유지** |
| 컵 압착 | 🔴 ACT와 **별개로** 물리 해결 (§6.5) |
| 폴백 | 🟠 **8/21 판정** (§6.6) |

### 6.2 파이프라인 — VGR과 ACT는 직렬이다

```
   차체 정지 (산포 ±30mm)
        │
        ▼
   🔵 VGR — 호모그래피 거친 정렬       ← 해석적. 반드시 유지
        │
        ▼
   🔵 ACT — 손목 카메라 폐루프 파지     ← 학습
        │
        ▼
   부하 임계 성공 판정 (적 80 / 황 40)
```

**ACT를 쓴다고 VGR을 빼면 안 된다.** 빼면 ±30mm 전 범위를 데이터로 덮어야 하고 에피소드 수가 몇 배로 뛴다. VGR로 먼저 접으면 ACT는 좁은 범위만 배우면 되고 **같은 데이터로 훨씬 잘 된다.**

카메라 두 대의 역할도 다르다.

| 일 | 카메라 | 성격 |
|---|---|---|
| 탐지 (색·중심·형상) · 대시보드 | 🔵 **CSI NoIR** (섀시) — 진우 도메인 | 🔴 **IR 차단 필터 없음** |
| **파지** | 🔵 **손목 SO-ARM USB** — ACT 전용 입력 | 🔵 정색 |

🔴 **로봇의 카메라는 2대다** 〔2026-08-09 정정〕. 종전 문서들이 「진우 카메라」와 「CSI NoIR」을 별개로 적고 있었으나 **같은 한 대**다. → **적색·황색 판정이 NoIR 에 걸려 있다** (§7.3).

### 6.3 두 물체의 차이

| | 적색 소분 용기 | 황색 종이컵 |
|---|---|---|
| 형상 | 원기둥 | 원뿔대 |
| 축대칭 | ✅ | ✅ |
| 강성 | 강체 | 🔴 변형체 |
| 하드스톱 | 있음 | 🔴 **없음** |
| 부하 임계 | 80% | 40% |
| 실패 양상 | 놓침 | 놓침 **또는 찌그러짐** |
| 재사용 | 가능 | 🔴 1회성 |

🔵 **동작 계열은 같다** — 둘 다 축대칭 물체의 측면 파지. 다른 것은 **조임 강도**뿐이다.

### 6.4 왜 통일했나

**① 🔴 「변형체라서 ACT」라는 전제가 성립하지 않는다**

| 종전 전제 | 실제 |
|---|---|
| "변형체는 모양이 일정하지 않다" | 🔴 종이컵은 **공산품이라 매번 같다** |
| "그래서 자세 추정이 어렵다" | 🔴 축대칭 + 링 + 높이 상수 → **소분 용기와 난이도가 같다** |
| "ACT가 이걸 해결한다" | 🔴 **ACT는 위치 제어다.** 관측에 힘 피드백이 없다 |

컵이 변형되는 순간은 **그리퍼가 닫히는 동안**이지 놓여 있을 때가 아니다. ACT는 그 국면에 아무것도 해주지 않는다.

**② 🔴 D-8에 갈래를 둘 유지할 수 없다** — 프리셋 경로와 ACT 경로를 병행하면 실패 모드를 두 세트 디버깅해야 한다.

**③ 🔵 버릴 것이 없다** — `center_x`/`center_y`가 발행되지만 소비처가 없고 `arm_controller`는 포즈 테이블로 축소된 상태다. **프리셋+VGR 경로는 아직 연결되지 않았다.**

### 6.5 🔴 컵 압착 — ACT와 별개로 푼다

| 대책 | 축 |
|---|---|
| 🔵 **그리퍼 손가락에 폼/실리콘 패드** | 그리퍼 쪽 — 컴플라이언스가 위치 오차를 흡수 |
| 🔵 **컵에 무게추·충전재** | 물체 쪽 — 경량 문제(§4.3-②)도 동시 해결 |

🔴 **패드는 적색 파지에도 영향을 준다** — 두께만큼 개구가 줄어 소분 용기 파지 위치가 달라진다. **수집 전에 붙여야** 하며, 나중에 붙이면 적색 데이터까지 무효가 된다.

### 6.6 정책 1개가 성립하는 조건

🔴 **ACT는 단일 태스크 정책이라 언어 조건이 없다.** 어느 물체인지는 **손목 카메라 영상만으로** 구분해야 한다.

| 요구 | 상태 |
|---|---|
| 적색·황색이 화면에서 명확히 갈릴 것 | 🔴 **§7.3 색 분리 검증이 여기서도 걸린다** |

| 물체별 에피소드 균형 | 🔲 수집 계획에서 확정 |

### 6.7 폴백

| 시점 | 내용 |
|---|---|
| 🟠 **8/21** | ACT 성공률 판정 |
| 🟠 기준 | **물체별 10회 시도에서 8회 이상** |

🔴 **판단 시점을 미리 못 박는 것이 핵심이다.** "될 때까지 해보자"로 가면 되돌아갈 시간이 사라진다.

## §7. 🔴 시연장 환경 — 여기가 가장 위험하다

물리 배치보다 환경이 데모를 더 자주 죽인다.

### 7.1 🔴 조명 — 데이터 수집을 시연장에서 해야 한다

ACT는 손목 카메라가 본 픽셀로 학습한다. `docs/05_arm/로봇암_카메라_구성정리.md` §6:

> **수집 때와 추론 때의 화면이 픽셀 수준까지 같아야 한다.**

책상에서 수집하고 시연장에서 추론하면 조명·배경·바닥이 전부 다른 분포가 된다. **데이터를 더 모아도 해결되지 않는다.**

| 항목 | 요구 |
|---|---|
| 수집 장소 | 🔴 **시연장 세트 위** |
| 조명 | 🔴 수집 때와 촬영 때가 **같아야** 한다 |
| 촬영용 조명 | 🔴 쓸 거면 **수집 때도 켜 둔다** |
| 자연광 | 🔴 시간대에 따라 변한다 — **차단하고 인공조명만** |
| 🔴 **소구획** | **수집 전에 세워야 한다** — 아래 참조. 이유는 조명이 아니라 **배경**이다 |

#### 🔴 소구획은 손목 카메라의 배경이다 (2026-08-09 정정)

소구획은 낮고 작아 **천장광을 거의 가리지 않는다** — 조명 변화는 미미하다. 종전 판(큰 방)에 있던 "벽이 곧 조명 조건"이라는 서술은 **소구획에는 해당하지 않는다.**

🔴 **대신 더 강한 제약이 생긴다.** 소구획 벽은 **물체 바로 뒤·바로 옆**이라 파지 직전 손목 뷰의 대부분을 차지한다. §6.5 의 폼 패드 규칙이 그대로 적용된다.

> "그리퍼·**물체가 보이는 화면**이 바뀌면 이미 수집한 데이터가 무효가 된다"

| | 큰 방 (폐기안) | 🔵 소구획 (확정) |
|---|---|---|
| 무엇이 바뀌나 | 조명 + 원경 배경 | 🔴 **근경 배경 (손목 뷰)** |
| 수집 전 필수인가 | 필수 | 🔴 **필수** |
| 고정 조명으로 우회 | 🔵 부분 가능 | 🔴 **불가능** — 조명 문제가 아니다 |

🔵 **다만 이건 나쁘기만 한 게 아니다.** 물체 바로 뒤에 **매번 동일한 근경 배경**이 있는 것은 ACT 입력 분포를 안정시키는 쪽으로 작동한다 — 수집 때 있기만 하면 된다. 제작이 작아 세트 제작에 통합되므로 일정 안에 들어갈 가능성도 큰 방보다 훨씬 높다.

### 7.2 🔴 환기 — 향이 쌓이면 음성 사례가 무너진다

향을 반복해 피우면 공간 전체 농도가 올라간다. 테이크를 거듭할수록 기준선이 드리프트하고, 어느 순간 **향 없는 소분 용기도 양성으로 읽힌다.**

🔵 **소구획은 이 문제를 키우지 않는다 (2026-08-09 정정).** 큰 방은 밀폐도를 올려 환기를 막았지만, 소구획은 공간을 막지 않는다. 오히려 **P1 과 P2 를 국소 분리**해 음성 사례 오판 위험을 줄인다. 각 셀의 **뒤쪽 개구부**가 향이 고이지 않게 한다.

| 대책 | 내용 |
|---|---|
| 테이크 사이 환기 | 최소 1~2분 (종전 유지) |
| 🔵 **P2 셀의 뒤쪽 개구부를 막지 않는다** | 향이 셀 안에 고이면 로봇이 떠난 뒤에도 남는다 |
| 🔵 **P2 와 P3 를 떨어뜨린 배치가 여기서도 이득** | 유별 혼재 제한 근거가 잔류 가스 대책을 겸한다 (§2.5) |
| 🔴 **촬영 중에는 환기 정지** | **바람이 종이컵을 넘어뜨린다** — 환기와 종이컵은 동시에 못 간다 |
| 🔵 **출발 전 점검 4번이 이걸 잡는다** | 가스 기준선이 불안정하면 출발을 거부한다 |
| 향의 양 | 🔴 **최소한으로** — 임계를 넘기기만 하면 된다 |
| 촬영 순서 | 음성 사례가 필요한 테이크를 **먼저** |

### 7.3 🔴 적색·황색 색 분리 검증

HSV 색상환에서 **적색과 황색 사이에 주황이 있다.**

```
   Hue:  0~10 ─── 10~20 ─── 20~35 ─── … ─── 170~180
         적색      주황       황색               적색
                    ▲
             🔴 여기서 겹치면 오분류
```

| 위험 | 내용 |
|---|---|
| 🔴🔴 **감지 카메라가 NoIR 이다** 〔2026-08-09 판명〕 | **IR 차단 필터가 없어 근적외선이 R 채널로 들어온다.** 노랑이 주황·빨강 쪽으로 밀려 **위 두 범위가 겹치는 방향으로 직접 작용한다.** 이 표에서 가장 큰 위험 |
| 적색 소분 용기이 주황빛이면 | 황색 범위로 넘어온다 |
| 종이컵이 진한 노랑이면 | 적색 범위로 넘어온다 |
| 🔴 **종이는 무광이라 주변광 색을 그대로 받는다** | 전구색 조명에서 노랑이 주황으로 밀린다 |
| 컵 테두리 반사 하이라이트 | 흰색으로 날아가 블롭이 끊긴다 |
| 🔴 **소구획이 배경색이 된다** | 셀은 **무채색만.** 크림·베이지는 노란 컵과 Hue 가 겹쳐 블롭 경계를 무너뜨린다 (§2.3) |

#### 🔴 검증은 카메라 두 대에서 각각 한다 (2026-08-09)

두 카메라가 서로 다른 이유로 색에 의존하므로, **한쪽이 통과해도 다른 쪽은 별개**다.

| 카메라 | 무엇에 쓰이나 | 검증 내용 |
|---|---|---|
| **CSI NoIR** (감지) | 🔴 판정표 4행 중 **3행이 여기 걸린다** | 실물 둘을 시연장 조명 아래 나란히 두고 `vision_node` HSV 마스크 확인. **두 범위 사이에 빈 구간이 있어야 한다** |
| **손목 SO-ARM** (ACT) | **정책 1개가 두 물체를 구분**해야 한다 (§6.6) | 파지 직전 거리에서 두 물체의 손목 뷰가 명확히 갈리는지. 🔵 정색이라 NoIR 문제는 없다 |

| # | 대책 | 비용 |
|---|---|---|
| 1 | 🔵 **조명을 LED 로. 백열·할로겐 금지** | **0원 — 조명 선택만.** IR 성분이 적어 색 밀림이 줄고, 🔵 **KY-026 오검출 회피(§7.4)와 방향이 같다** |

| 3 | 🟠 **외장 IR-cut 필터** 부착 | 저가. 원인을 직접 제거 |
| 4 | 🟠 **형상 특징 병용** (면적·채움률·원형도) | 코드. 색이 애매해도 판정이 선다 |
| 5 | 🟠 **보유 중인 Innomaker(정색)로 교체** | 0원 — **이미 예비 부품으로 갖고 있다.** 신규 구매는 마지막 |

🔴 **수집 전에 끝내야 한다.** 색이 겹치면 오분류가 나고, 오분류는 데이터로 고쳐지지 않는다. **정책 1개(§6.6)도 이 분리에 의존한다.**

### 7.4 🔴 화기 안전

**KY-026은 적외선(약 760~1100nm)에 반응하므로 LED 캔들로는 트리거되지 않는다** — 실화가 필요하다.

| 항목 | 요구 |
|---|---|
| 받침 | 불연 재질 · 넘어지지 않는 형태 |
| 주변 | 🔴 **LiPo 배터리와 향(가연물)이 같은 공간에 있다.** 캔들 반경 내에 두지 말 것 |
| 소화 | 소화기 또는 물·뚜껑 상시 비치 |
| 감시 | 🔴 촬영 중 **화기 담당 1인 지정** — 프레임 밖 대기 |
| 촬영 후 | 즉시 소화 확인 |

### 7.5 바닥과 라인

| 항목 | 요구 |
|---|---|
| 바닥 | 평탄 · 무광. 🔴 반사가 강하면 IR 라인센서가 오독한다 |
| 라인 | 🟠 검정 절연테이프 19~20mm (S1~S5 간격에 맞춰 조정) |
| 대비 | 밝은 바닥 + 검정 라인. 회색은 마진이 좁다 |
| 코너 | 🔲 회전 반경 실측 |

## §8. 코스 치수 — 역산으로 정한다

임의로 정하지 말고 시간 예산에서 역산한다.

```
   구간 길이 = 주행 속도 × 구간 이동 시간
```

| 구간 | 시간 예산 | 속도 | 길이 |
|---|---|---|---|
| 스테이션 → P1 | 25초 (출발 포함) | 🔲 | 🔲 |
| P2 → P3 | 15초 | 🔲 | 🔲 |
| P3 → P4 | 15초 | 🔲 | 🔲 |
| P4 → 스테이션 | 20초 | 🔲 | 🔲 |

🔲 **주행 속도를 먼저 실측한다.** 라인 추종이 안정적인 최대 속도가 코스 크기를 결정한다.

🔴 **공간이 부족하면 속도가 아니라 시간 예산을 줄인다.** 무리하게 속도를 올리면 코너에서 이탈하고, 그게 곧 재촬영이다.

### 8.1 🔵 소구획은 코스 치수에 하한을 만들지 않는다 (2026-08-09 정정)

종전 판(큰 방)은 벽이 라인 정면에 서서 **직선 1000mm 하한**을 만들었다. **소구획은 라인 옆에만 있으므로 이 제약이 없다** — 코스 치수는 §8 의 시간 역산만으로 정한다.

남는 공간 요구는 하나뿐이다.

```
   점검점 옆 여유폭  ≥  셀 외곽 폭 + 로봇 통과 여유
```

🔲 **셀 외곽 치수는 §2.3 실측 후 확정한다.**

## §9. 촬영

### 9.1 시간 예산

가스 예열은 촬영 전 완료하므로 제외한다. 아래 12초는 **응답 시간**(T90 ≈10초)에서 접근 중 노출분을 뺀 값이다.

| 구간 | 초 |
|---|---|
| 대기 + 출발 + 구역 A 주행 | 25 |
| 🔵 적색 ① 정지·판정·통과 | 10 |
| 적색 ② 감지 + 접근 + 가스 확정 | 12 |
| 파지 (ACT) | 20 |
| 격리 | 12 |
| 구역 B 주행 | 15 |
| 종이컵 감지 + 접근 | 8 |
| 파지 | 20 |
| 격리 | 12 |
| 구역 C 주행 | 15 |
| 캔들 + 부저 + 복귀 | 20 |
| **합계** | **169** |

**제한 180초 · 여유 11초.**

### 9.2 🔴 파지 재시도 1회면 예산을 넘긴다

`MAX_RETRY = 3`이고 재시도 1회당 약 15초다. **여유 11초로는 한 번도 감당할 수 없다.**

🔵 **반복 촬영이 답이다.** 복귀 완료 후 `IDLE`로 돌아가므로 `/mission/start`만 다시 쏘면 재출발한다. 노드를 재시작하지 않고 좋은 테이크를 고를 수 있다.

### 9.3 카메라와 필수 컷

| # | 용도 | 위치 |
|---|---|---|
| 1 | 전체 샷 | 코스 전체가 들어오는 고정 삼각대 |
| 2 | 클로즈업 | 파지·통과 판정 구간. 🔴 동선을 막지 않게 |
| 3 | 대시보드 | 화면 캡처 또는 모니터 직촬 |

🔵 로봇의 손목 카메라와는 별개다. 손목 카메라는 ACT 입력이지 촬영용이 아니다.

| 필수 컷 | 왜 |
|---|---|
| 🔴 **적색 ① 통과** | 색만 보는 로봇과 판단하는 로봇을 가르는 **유일한 장면** |
| 🔴 **파지** | ACT 시연 |
| 대시보드 판정 표시 | 통과가 "못 본 것"이 아님을 증명 |
| 부저 + 복귀 | `RETURN`이 정지가 아님을 보여줌 |
| 점검 7항목 통과 | 오프닝 |

### 9.4 🔴 「통과」가 영상에서 읽혀야 한다

그냥 지나가면 **"판단해서 통과"와 "못 봤다"가 구분되지 않는다.**

| 방법 | 채택 |
|---|---|
| 🔵 **잠깐 정지 → 재출발** | **채택** — "봤고, 재고, 통과시켰다"가 동작으로 보인다 |
| 🔵 **대시보드에 `적색 감지 · 가스 정상 · 통과`** | **채택** |
| LED 색 구분 (감지=주황 / 위험=적색) | 선택 |
| 자막 | 최후 보루 |

### 9.5 편집

| 구간 | 처리 |
|---|---|
| 구역 간 주행 | 🔵 배속 |
| 통과 판정 · 파지 | 🔴 **실속 유지** |
| 복귀 | 배속 |

🔴 **배속 편집은 완성도용이 아니라 보험이다** (§9.2).
