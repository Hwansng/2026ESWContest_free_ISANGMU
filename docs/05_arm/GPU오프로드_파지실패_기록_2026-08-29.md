## 1. 배경 — 왜 GPU 오프로드를 시도했나

RPi 로컬 추론(`lerobot-rollout --strategy.type=base`)에서 CPU가 정책의 다음 행동 청크 계산을 실시간으로 못 따라가 20초 에피소드 중 4번씩 정지가 생기는 문제가 있었다. "RPi CPU 추론이 근본 한계"라는 가설 아래, 추론 자체를 노트북 GPU로 옮기는 쪽으로 방향을 틀었다.

## 2. 구조

`lerobot`에 이미 있는 `lerobot.async_inference` 모듈(gRPC 기반)을 그대로 썼다.

```
RPi(robot_client) — 카메라·서보 I/O, 관측을 gRPC로 송신
        ↕ gRPC
노트북(policy_server) — RTX 4060 GPU로 실제 정책 추론, 액션 반환
```

RPi는 연산을 전혀 안 하므로, 로컬 추론 경로에서 있었던 청크 경계 스톨은 구조적으로 없다.

## 3. 결과 — 연결은 성공, 파지는 재현 안 됨

**로봇·카메라·gRPC 연결 전부 성공.** 다만 실제 동작에서:

> 팔이 움직이긴 하나 **제자리에서 조금씩만**, **파지 시도 자체를 안 함**

## 4. 시도한 조치 — 둘 다 실측 근거로 고쳤지만 증상 그대로

| # | 가설 | 조치 | 결과 |
|---|---|---|---|
| A | `aggregate_fn_name` 기본값 `weighted_average`(이전 청크와 30% 블렌딩)가 결정적 동작(파지)을 흐린다 | 블렌딩 없는 `latest_only`로 교체 | 증상 지속 |
| B | `calibration/follower_home.json`의 `wrist_flex`가 학습 시 홈 자세와 어긋나 있다 | 학습 데이터셋 100개 에피소드의 첫 프레임 `observation.state`를 직접 집계(평균 50.20, 표준편차 4.22) → 기존 값(41.89 상당)이 분포 최솟값보다도 낮음을 확인 → `2567`→`2664`로 수정(역변환 공식 round-trip 검산 완료) | 증상 지속 |

색상 채널(RGB/BGR) 불일치도 의심해 확인했으나, `lerobot`의 `OpenCVCameraConfig` 기본값(`color_mode=RGB`)이 학습 경로·현재 경로 양쪽에 동일하게 적용됨을 코드로 확인 — 원인에서 배제.

## 5. 결론

**두 가설 모두 실측 근거를 가지고 고쳤음에도 증상이 그대로였다 — 진짜 원인은 못 찾았다.** 시간 관계상 여기서 중단.

## 6. 미확인 단서 (더 조사하지 않음)

테스트는 전부 `--actions_per_chunk=50`을 썼는데, 체크포인트의 `config.json`엔 `chunk_size: 100, n_action_steps: 100`으로 돼 있다 — **학습된 청크 크기의 절반만 요청**하고 있었다는 뜻이다. 이게 서버 쪽 청크 슬라이싱 로직과 어떻게 상호작용하는지는 확인하지 못했다.

## 7. 결정

- **시연·제출 영상**: 검증된 노트북 단독 경로(`rollout_act.ps1`, COM3 직결, RTX 4060) 그대로 사용. 86.7%(근거리 100%) 검증치가 그대로 유효.
- **이 경로(ROS2 통합 + GPU 오프로드)**: 영상에는 넣지 않는다. 개발완료보고서·PPT에서 "ROS2 오케스트레이션 + 원격 GPU 추론 아키텍처까지 구현·실물 검증을 시도했다"는 근거로만 쓴다.
