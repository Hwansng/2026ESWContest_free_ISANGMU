## 왜 옮기는가

점퍼선+브레드보드는 주행 로봇에서 **실패가 보장된 구조**다.

- Dupont 암커넥터의 유지력은 스프링 압력뿐이다. 신품 ~1.5N이 20회 삽입 후 0.5N 이하로 영구 변형된다. 브링업하며 이미 수십 번 뺐다 꽂았다.
- 빠지는 진짜 원인은 인장이 아니라 **지렛대**다. 뻣뻣한 케이블이 커넥터를 옆으로 비트는 모멘트가 접점을 벌린다.
- 브레드보드 클립은 단선용이라 Dupont 수핀에 헐겁고, 접점당 접촉 저항이 수십~수백 mΩ이다. 모터 1A가 흐르면 전압 강하로 나타난다 — **7/22 VM=7V 사건의 한 요인**.

여기에 모터 진동이 상시로 가해지면 확률적으로 반드시 빠진다. 심사가 **녹화 영상**이라 촬영 중 이탈은 재촬영을 뜻하고, 아래 표의 상위 항목은 이탈 즉시 부품이 죽는다.

### 선이 빠졌을 때의 결과 — 작업 우선순위 근거

| 빠지는 선 | 결과 | 위험도 |
|---|---|---|
| **12V(−) 전력 GND** | 모터 전류가 로직 GND(=ESP32)로 되돌아감 → **ESP32 파손** | 🔴 최악 |
| 전력 GND **한쪽만** (2개 중 1개) | 해당 채널만 귀환 경로 상실 → **좌우 중 한쪽 모터만 안 돎.** 배선을 봐도 안 보인다 | 🔴 |
| 모터 출력 A01/A02/B01/B02 | 코일 전류 급차단 → 역기전력·아크 | 🔴 |
| 라인센서 VCC | 5채널 출력 불확정 → 엉뚱한 조향 | 🔴 주행 사고 |
| STBY | TB6612 STBY는 **내부 풀다운이 없어** 플로팅 = 불확정 | 🟠 |
| AIN/BIN | 한쪽 방향 고정 또는 브레이크 | 🟠 |
| 라인센서 신호 1채널 | 해당 채널 플로팅 → 랜덤 감지 | 🟠 |
| 12V(+) | 모터 정지 (안전하지만 촬영 실패) | 🟡 |

### 정리가 필요한 것 ① — VL53L1X 를 어느 보드에 다는가

핀은 안 겹치지만 **센서 하나가 양쪽 문서에 다 들어가 있다.** 물리적으로는 한 곳에만 달린다.

| | 강희 보드 (ENV) | 이 보드 (DRIVE) |
|---|---|---|
| 현재 | **v9 에 코딩·검증 완료** (`RAW_DIST`/`DIST`, INIT 에러 처리) | `J_TOF` 커넥터만 설계됨 |
| 반응 경로 | ToF → ENV → WiFi → RPi → WiFi → DRIVE → 정지 | ToF → DRIVE → **즉시 정지** |
| v5 §4 | — | **여기로 지정** (466~469행) |

**권장: DRIVE 로 가져온다.** 장애물 회피는 **모터를 멈추는 쪽이 직접 봐야 하는 로컬 반응 루프**다.
ENV 에 두면 안전 반응이 WiFi 두 홉에 의존한다. 촬영 중 무선이 한 번 튀면 그 테이크는 버린다.

옮기는 비용은 작다 — Adafruit 라이브러리 호출 20줄 수준이고 **강희가 이미 디버깅해둔 코드를 그대로 가져오면 된다.**
강희 문서에서는 `J_TOF`·GPIO21/22·`RAW_DIST`/`DIST`/`DIST_SENSOR` 를 삭제한다.

*(반대로 ENV 에 두기로 하면 이 문서의 `J_TOF` 를 빼면 된다. v5 의 판단을 뒤집는 것이므로 이유를 v5 에 남길 것.)*

### 정리가 필요한 것 ② — 배터리 전압

강희 문서의 `G35` LiPo 예약. 배터리 감시는 **이 보드 `G39`(33k/10k)로 확정**이라 (v5 454행) ENV 쪽은 빼도 된다.
v9 의 `BAT=12.00V` 고정 소프트웨어 값도 DRIVE 실측으로 대체된다.

### 정리가 필요한 것 ③ — 전원

강희 문서의 "외부 정전압 5V + PC USB" 구성은 **책상 시험용**이다. 로봇에 올리면 두 보드가
**같은 배터리·같은 5V 레일**을 쓴다. §4.5 에서 확정했다.

### 강희 문서에서 가져오는 것

핀 배정과 무관하게 이 기판에도 적용할 좋은 관행이다. 해당 절에 반영했다.

- **JST-XH 잠금형 커넥터** — 애초에 이 이전 작업의 목적이 "점퍼선이 빠진다"였다. 래치 있는 커넥터가 정답이다 (§1·§3)
- **테스트 포인트** — 멀티미터 프로브 전용 패드. 통전 후 검사가 훨씬 안전해진다 (§3·§6)
- **핀 1 표시와 좌우 반전 방지 절차** (§5)
- **센서를 하나씩 추가하며 전원 투입** (§6)

## 2. 설계 원칙 4가지

1. **ESP32와 TB6612는 납땜하지 않고 소켓에 꽂는다.**
   TB6612는 고장 확률이 가장 높은 부품이고, ESP32는 USB 재플래시가 필요하다.
   모듈을 마지막에 꽂으므로 납땜 실수로 부품이 죽을 일도 없다.
2. **USB 포트는 기판 밖으로 돌출시킨다.** 안 그러면 케이블이 안 들어간다.
3. **스타 그라운드 유지** — 12V(−) 터미널이 로직 GND와 전력 GND의 유일한 접점.
   TB6612 내부에서 PGND1/PGND2와 GND는 분리되어 있고, **브레이크아웃 GND 패드는 3개다**
   〔2026-08-06 실측 — 7/22 의 "2개"는 오기〕. 서로 이어져 있지 않으므로 **3개 전부** 연결한다.
   🔴 벤치에서는 3개를 브레드보드 (−) 레일에 몰아 꽂아도 동작하지만(무부하 확인 완료),
   **만능기판에서는 전력 GND 2개를 12V(−) 터미널로 직결**한다. 이게 이 원칙의 실체다.
4. **캐패시터는 TB6612의 VM/GND 핀 바로 옆.** 멀어지면 의미가 없다.

### 확장 커넥터 — JST-XH 잠금형

기존 계획의 "확장 6P 수 핀헤더"를 **래치 있는 JST-XH 3개**로 바꾼다.
이 이전 작업의 목적 자체가 "점퍼선이 진동으로 빠진다"였는데, 확장부만 Dupont 로 두면 앞뒤가 안 맞는다.
핀 순서는 강희 문서의 `J_TOF` 규약과 **동일하게 맞춰** 케이블을 호환시킨다.

| 커넥터 | 핀 | 용도 |
|---|---|---|
| `J_TOF` **XH 4P** | `3V3 / GND / G21(SDA) / G22(SCL)` | **VL53L1X ToF** — v5 §4 에서 #1 에 남긴 유일한 센서 (장애물 회피 로컬 반응 루프) |
| `J_ENC_L` **XH 3P** | `3V3 / GND / G33(A상)` | 좌 모터 — **스톨 검출 예약**, 지금은 미결선 |
| `J_ENC_R` **XH 3P** | `3V3 / GND / G36(A상)` | 우 모터 — **스톨 검출 예약**, 지금은 미결선 |

- 🔴 엔코더 VCC 는 **3V3** 이다. 5V 를 주면 A상 출력도 5V 가 되어 ESP32 가 손상된다
- 좌우를 따로 뺐으므로 3V3·GND 를 갈라 쓰는 Y 케이블이 필요 없다 (이전 6P 안의 단점 해소)
- 지금 커넥터를 다는 건 몇백 원이지만, 나중에 추가하려면 기판을 다시 뜯어야 한다

### 그 밖에

- **테스트 포인트** `TP_3V3` · `TP_GND` · `TP_VM` — 굵은 단선을 고리 모양으로 세워 납땜한다.
  통전 상태에서 프로브가 미끄러져 옆 패드를 건드리는 사고를 막는다. 서로 충분히 띄울 것
- 전력 배선(12V·모터)은 신호선과 **나란히 길게 가지 않게** 한다. 최단 경로로
- I2C(`G21`·`G22`)는 **짧게 나란히**, 모터 배선과 평행하게 길게 붙이지 않는다
- 배치를 확정하기 전에 **실물 부품을 기판에 올려놓고** 연필로 외곽선을 그린다

### 모터 출력

| TB6612 | → | 대상 |
|---|---|---|
| A01 / A02 | → | **좌측** 모터 터미널 |
| B01 / B02 | → | **우측** 모터 터미널 |

모터 6선 중 이번에 연결하는 것은 **빨강/흰색(모터 전원)** 2가닥뿐.
**속도 폐루프는 미사용 확정**(2026-07-25 — 전압 보상으로 대체, `README.md` 참조).
다만 **스톨 검출 슬라이스는 열어둔다** — 채택 시 파랑(VCC)·검정(GND)·노랑(A상) 3가닥이 필요하다.

> 🔴 **엔코더 4가닥은 반드시 절연 처리할 것.**
> 피복 벗겨진 끝단이 모터 단자·TB6612 출력에 닿으면 단락된다. 진동으로 움직이므로 방치 금지.
> 각 선 끝에 **수축튜브를 씌우고**, 4가닥을 묶어 **케이블타이로 모터 몸체에 결속**한다.
> 나중에 뜯어 쓸 수 있게 **너무 짧게 자르지 말 것** — 기판까지 닿는 길이를 남긴다.

### VL53L1X ToF (`J_TOF`)

v5 §4 에서 **#1 에 남기기로 한 유일한 센서**다. 장애물 회피가 로컬 반응 루프여야 하기 때문이다.
아래 값은 강희가 v9 에서 실제로 검증한 것이므로 그대로 따른다.

| XH 핀 | 신호 | VL53L1X 단자 | 색(권장) |
|---:|---|---|---|
| 1 | 3V3 | **VIN** | 빨강/주황 |
| 2 | GND | GND | 검정 |
| 3 | G21 | **SDA** | 파랑 |
| 4 | G22 | **SCL** | 초록 |

- I2C 주소 **0x29**
- Adafruit 보드에 I2C 풀업이 내장되어 있다 → **SDA/SCL 외부 풀업을 달지 말 것**
- `GPIO` · `XSHUT` 는 **연결하지 않는다**
- 센서 쪽 **6핀 헤더는 미리 납땜**해 둔다 (기판 작업과 별개로 먼저 해두면 좋다)
- 광학 창 앞을 비우고, 반복 촬영 중 각도가 틀어지지 않게 단단히 고정한다

## 4.5 전원 계통 — USB 없이 주행하기

주행 중에는 USB 가 없다. ESP32 를 배터리에서 내려받아야 한다.

### 확정 구조

```
12V 배터리
   │
   ├─[메인 스위치 ≥5A]─┬─ 12V 터미널 ─── TB6612 VM ─── 모터
   │                    │
   │                    └─ XL4015 #B ── 5.0V ─┬─ 5V IN 터미널 ─▶|─ ESP32(DRIVE) VIN
   │                                          │                SS34
   │                                          └─ 별도 한 쌍 ──── ENV 보드 + MQ 히터
   │
   └─ 33k/10k 분압 ─── G39 (전압 보상 · 과방전 감시)
```

- 🔴 **12V 를 VIN 에 직결하지 말 것.** 온보드 AMS1117 이 (12−3.3)×0.25A ≈ **2.2W** 를 태워
  열보호로 떨어진다. 5V 를 넣으면 0.43W 라 문제없다
- 벅은 입력이 출력+1.5V 이상이면 출력을 유지한다. 배터리가 10V 까지 처져도 5V 는 안 흔들린다
  → **모터 기동 전류로 배터리가 순간 처져도 ESP32 가 리셋되지 않는다.** 12V 직결보다 이 점이 더 중요하다
- ENV 보드는 XL4015 **출력 단자에서 별도 한 쌍**을 뽑는다. **데이지체인 금지** —
  MQ 히터 상시 300mA 가 DRIVE 쪽 5V 를 흔든다

### 🔴 USB 역급전 차단 — SS34 다이오드

`README.md` 의 "USB 와 VIN 동시 금지"는 **지키는 사람에게 의존하는 규칙**이다. 한 번 잊으면 레귤레이터가 죽는다.
5V IN 터미널과 ESP32 VIN 사이에 **쇼트키 다이오드 SS34**(또는 1N5819)를 넣으면 하드웨어가 대신 막는다.

| 상황 | 결과 |
|---|---|
| 벅만 ON | VIN ≈ 4.65V (SS34 강하 ~0.35V) — AMS1117 드롭아웃 1.1V 대비 여유 있음 |
| USB 만 | 다이오드 역방향 → 벅 쪽으로 흐르지 않음 |
| **둘 다** | USB(5.0V)가 이겨 다이오드 차단 → **PC 로 역급전 없음** |

- 방향 🔴 **띠(캐소드)가 ESP32 쪽.** 거꾸로 달면 전원이 아예 안 들어온다
- 벅 출력이 4.8V 아래로 내려가면 여유가 사라진다 → **5.0~5.2V 로 트리밍하고 실측**할 것

### XL4015 2대 배정 — 🔴 재조정 금지

| 유닛 | 출력 | 용도 |
|---|---|---|
| **#A** | **7.4V** | 리더암 (데이터 수집) |
| **#B** | **5.0V** | AMR — DRIVE + ENV |

시연 영상에 리더암이 안 나오는 건 맞다. 그래도 **한 대를 돌려쓰지 않는다.**

- 리더암은 **데이터 수집이 끝날 때까지(~W4, 8/16~8/22) 계속 필요하다.** 지금 노는 물건이 아니다
- 7.4V ↔ 5V 를 왔다갔다 트리밍하는 **절차 자체가 위험하다.** 한 번 잊으면 서보 6개 전멸
  (₩178,315, 복구 불가). 2대가 있으므로 이 위험을 감수할 이유가 없다

→ 조정 후 **유닛에 라벨**을 붙이고 다시 건드리지 않는다: `#A 7.4V 리더암 전용` / `#B 5.0V AMR 전용`
→ 가변저항 위에 **매니큐어나 글루건을 한 방울** 떨어뜨려 물리적으로 잠근다 (진동으로도 돌아간다)
→ 리더암 연결 전에는 **매번** 멀티미터로 7.4V 확인 (기존 규칙 유지)

### 소비 전류 개산

| 부하 | 5V 기준 |
|---|---|
| ESP32 DRIVE (+ 3V3 로 나가는 라인센서 5채널·ToF·TB6612 로직) | ~350mA (WiFi 송신 피크 시 더) |
| ESP32 ENV | ~250mA |
| MQ-135 히터 | ~150mA |
| MQ-2 히터 | ~180mA |
| **합계** | **~930mA** (피크 ~1.2A) |

XL4015 는 5A 급이라 여유가 크다.

> DRIVE 쪽 AMS1117 이 (4.65−3.3)×0.35A ≈ **0.5W** 를 태운다. 규격 내지만 미지근해진다.
> 손대기 뜨거울 정도면 라인센서 VCC 를 별도 3.3V 로 빼는 걸 검토할 것.

### 배선·접지

- XL4015 의 **GND 는 12V(−) 터미널 나사에 함께 물린다** (§2-3 스타포인트).
  로직 GND 레일에서 따로 따면 모터 리턴 전류가 갈라져 흐른다
- 5V 입력선은 **20AWG 연선** 이상 — 같은 전력에서 12V 보다 전류가 2.4배다
- 메인 스위치는 **12V(+) 배터리 선**에 넣는다. 모터·벅·양쪽 보드가 한 번에 꺼진다

## 5. 납땜 순서

**낮은 부품부터.** 기판을 뒤집어 놓고 작업하므로, 키 큰 부품을 먼저 달면 낮은 부품이 뜬다.

- [ ] **1. 배치 확정** — 실물을 올려놓고 연필로 외곽선. USB 돌출 / TB6612–캐패시터 근접 / 터미널이 기판 가장자리를 향하는지 확인
- [ ] **2. 방향·핀1 표시** — 실장면·납땜면을 구분해 적고, 모든 커넥터 자리의 **1번 핀에 유성펜으로 삼각형**.
      3V3 / GND / 12V 영역을 서로 다른 색으로 칠해 둔다
- [ ] **3. 10kΩ 저항** (가장 낮음)
- [ ] **4. 암 핀헤더 소켓** — 대각선 2핀만 먼저 납땜 → **기판과 수직인지 확인** → 나머지 핀
      삐뚤어지면 모듈이 안 들어간다. 이 단계에서 서두르지 말 것.
- [ ] **5. JST-XH 커넥터 3개** (`J_TOF`·`J_ENC_L`·`J_ENC_R`) — 래치가 바깥을 향하는지 확인
- [ ] **6. 스크류 터미널 블록**
- [ ] **7. 테스트 포인트** `TP_3V3`·`TP_GND`·`TP_VM` — 굵은 단선을 고리로 세워 납땜
- [ ] **8. SS34 다이오드** (5V IN → ESP32 VIN) — 🔴 **띠가 ESP32 쪽**
- [ ] **9. 캐패시터** — 🔴 **흰 띠 = (−)**. 반대로 달면 7/22 VM=7V 사건이 재현된다.
- [ ] **10. 레일 배선** — GND 먼저, 3V3 다음. 굵은 선(12V·모터·5V)도 이 단계
- [ ] **11. 신호선 12가닥** — 한 가닥 납땜할 때마다 **바로 테스터 부저로 도통 확인**.
      몰아서 찾으면 지옥이다.
- [ ] **12. 섀시에 스페이서로 마운트** — XL4015 #B 도 같이 고정할 자리를 잡는다

### 커넥터 좌우 반전 방지 (강희 문서에서)

XH 하우징은 압착할 때 **앞뒤를 헷갈리면 핀 순서가 좌우로 뒤집힌다.** 납땜면에서 보면 좌우가 반대라는 점이 함정이다.

1. 기판 실장면의 1번 핀에 삼각형 표시
2. 케이블 **양쪽** 하우징에도 1번 표시
3. 꽂은 상태에서 1번 핀의 **선 색이 양 끝 모두 같은지** 확인
4. 전원 넣기 전, 센서 VIN 핀에서 `TP_3V3` 까지 도통 확인

### 나사 터미널 팁

22AWG 연선은 5.08mm 터미널에 가늘어서 헛돈다. **선단을 반으로 접어 두 겹**으로 넣는다.

> **납칠(tinning)한 선을 나사 터미널에 넣지 말 것.** 납이 냉간 유동(cold flow)으로 눌려 시간이 지나면 헐거워진다. 나사 터미널에는 맨 구리선 또는 페룰(ferrule)을 쓴다.

## 6. 통전 전 검사 — 모듈 꽂기 전에

ESP32와 TB6612를 **아직 꽂지 않은 상태**에서 한다. 소켓 핀끼리 직접 측정할 수 있어 훨씬 쉽다.

- [ ] **육안** — 인접 패드 납땜 브리지 확인 (휴대폰 카메라 확대가 잘 보인다)
- [ ] **3V3 ↔ GND 단락 없음** (수 kΩ 이상 또는 ∞)
- [ ] **12V ↔ GND 단락 없음**
- [ ] 🔴 **12V ↔ 3V3 절연 확인** — 여기 붙으면 ESP32가 즉사한다
- [ ] 🔴 **5V ↔ 12V, 5V ↔ GND, 5V ↔ 3V3 절연 확인**
- [ ] **신호선 12개 도통** (ESP32 소켓 핀 ↔ 목적지)
- [ ] 🔴 **TB6612 소켓 GND 3자리 전부 배선됨** — 소켓만 납땜하고 뒤쪽을 2개만 이으면 육안으로 안 보인다.
      전력 GND 2자리는 **12V(−) 터미널에 직결**, 로직 GND 1자리는 **로직 레일 경유**인지 각각 확인
      (판별법은 `README.md` §1 「모터」 절)
- [ ] **`J_TOF` 4핀 도통** — 1↔TP_3V3 · 2↔TP_GND · 3↔G21 소켓 · 4↔G22 소켓
- [ ] **`J_TOF` 3↔4 (SDA↔SCL) 연결 없음** — 붙어 있으면 I2C 가 아예 안 뜬다
- [ ] **SS34 방향** — 다이오드 모드로 5V IN(+) → VIN 방향만 도통 (역방향 ∞)
- [ ] **캐패시터 극성 재확인**

### 전원 인가 순서

- [ ] **XL4015 #B 를 기판에서 뗀 채로** 12V 를 물려 출력을 **5.0~5.2V 로 트리밍** → 라벨 부착
- [ ] 전원 OFF 상태로 **모듈 꽂기** (VL53L1X 는 아직 꽂지 않는다)
- [ ] **USB만 연결** → ESP32 부팅·시리얼 확인
- [ ] `TP_3V3` ↔ `TP_GND` = **3.3V 실측**
- [ ] USB 분리 → **바퀴 띄우고** 메인 스위치 ON
- [ ] `TP_VM` 에서 **VM = 12V 실측** (7V면 `README.md` §6 트러블슈팅 참조)
- [ ] **VIN 핀에서 4.6~4.9V 실측** — 4.5V 미만이면 벅 출력을 올린다 (§4.5)
- [ ] **USB 를 꽂은 채로 메인 스위치 ON** — SS34 가 정상이면 아무 일도 없어야 한다.
      이 시험을 통과하면 "USB·VIN 동시 금지"가 하드웨어로 보장된 것이다
- [ ] 전원 끄고 **VL53L1X 를 마지막에** 꽂는다 → 부팅해 `[VL53L1X] READY` 확인

> 센서는 **한 번에 하나씩, 꽂을 때마다 전원을 끄고** 추가한다 (강희 문서 원칙).
> 한꺼번에 꽂고 켜면 어느 배선이 문제인지 찾는 데 몇 배가 든다.

      물리적으로 그렇게밖에 안 된다. 🔵 **이 기판의 `STBY` 10kΩ 풀다운이 그 결정의 계층 0** 이다 —

## 8. ENV 보드 (강희 / 안전·환경) 와의 접점

강희가 `amr_v9_4sensor_만능기판_배선_가이드.md` 를 이미 써 뒀다. **핀은 겹치지 않으므로 그대로 진행하면 된다.**
반대로 강희 문서의 **기판 A/B 2장 구조 · JST-XH · 테스트 포인트 · 단계별 전원 투입**은 이 문서보다 낫다 — 가져왔다.

두 보드가 실제로 맞물리는 지점은 세 곳뿐이다.

| 접점 | 확정 |
|---|---|
| **전원** | XL4015 #B 5.0V 를 **출력 단자에서 별도 한 쌍**으로 ENV 에 보낸다. 강희 문서의 "외부 정전압 5V"가 이것 (§4.5). 데이지체인 금지 |
| **접지** | 두 보드 GND 는 XL4015 출력에서 공통이 된다. ENV 의 **MQ 히터 리턴(상시 ~300mA)은 ADC GND 와 분리**해 벅 GND 로 직접 보낼 것 |
| **VL53L1X** | ✅ **DRIVE 담당으로 확정** 〔2026-08-01〕. 양쪽 문서에 다 있었으나 v5 §4 기준(관계 절)대로 DRIVE 로 정리한다. 구간별 임계까지 DRIVE 가 갖는다 — 직선 1000mm / 코너 ≈300mm (`구역_마커_설계.md` §6.1) |

### 강희 문서에서 손볼 것

- **VL53L1X 절** — DRIVE 이관이 확정됐으므로 `J_TOF`·GPIO21/22·`RAW_DIST`/`DIST`/`DIST_SENSOR` 삭제
- **G35 LiPo 예약** — 배터리 감시는 DRIVE 의 G39(33k/10k)로 확정 (v5 454행).
  v9 의 `BAT=12.00V` 고정값도 DRIVE 실측으로 대체된다
- **전원 절** — "PC USB + 외부 5V, GND 만 공통" 구성은 책상 시험용.
  로봇에 올릴 때는 §4.5 구조로 바뀐다 (ENV 도 USB 없이 배터리로 돈다)

### 그대로 유효한 것

핀 배정(MQ-135 `G34` / MQ-2 `G33` / KY-026 DO `G27`, 둘 다 ADC1 이라 WiFi 제약 충족) ·
10kΩ/15kΩ 분압 · JST-XH · 테스트 포인트 · 단계별 전원 투입 · 문제 해결 절.

> 🔴 변하지 않는 제약: **ENV 보드는 서보 3핀 버스에 절대 연결하지 않는다.**
> (v5 §2.3 — STS3215 는 1선 반이중이고 마스터는 RPi USB 어댑터 하나뿐이다)
