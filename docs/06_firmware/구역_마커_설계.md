## 2. 왜 가로선인가 — 제어 법칙이 형태를 강제한다

현재 위치 계산은 **감지된 채널의 가중 평균**(−2 ~ +2)이다.

### 측면 마커는 조향을 깨뜨린다

라인 옆 검정 패치가 S1·S2 를 덮고 라인이 S3 에 있으면:

```
pos  = (−2 + −1 + 0) / 3 = −1.0
corr = KP × pos = 60 × (−1.0) = −60
좌 = 120 + (−60) = 60 · 우 = 120 − (−60) = 180
→ 왼쪽 바퀴가 느려져 좌선회. 로봇이 마커 쪽으로 끌려간다
```

마커 길이 40mm 를 지나는 동안 6~7 제어주기가 이 상태로 유지된다. **라인을 벗어난다.**
「마커 중 조향 동결」로직으로 막을 수는 있지만, 상태를 하나 더 만드는 것 자체가 비용이다.

### 전폭 가로선은 자기중화된다

5채널이 전부 HIGH 면:

```
pos = (−2 −1 + 0 + 1 + 2) / 5 = 0   →  corr = 0  →  직진 유지
```

**가중치가 대칭이라 전 채널이 켜지면 보정이 정확히 0 이 된다.** 별도 처리 없이 조향이 보존된다.

> 진입·이탈 순간의 D 항 스파이크도 무시할 수준이다.
> 중심에서 err=0.2 로 진입하면 dTerm = (0−0.2)/0.02 = −10 → `KD × dTerm × 0.001` = **−0.25**.
> 듀티 1 미만이라 영향 없다.

## 3. 왜 RFID 가 아닌가

### 산업계의 선택 기준은 경로 위상이다

| 조건 | 현장의 선택 |
|---|---|
| **다중** 분기 · 다수 스테이션 · 다수 로봇 | **RFID / QR** — 고유 ID 필수 |
| 단일 폐루프 · **분기 1개** · 소수 정지점 · 단일 로봇 | **마커 카운트**로 충분 |

HazardBot = 단일 폐루프 · 분기 1개(스테이션 지선) · 정지점 4개 · 로봇 1대 → **마커**.

> **분기가 하나면 「지금 어느 분기인가」가 자명하다.** 갈 수 있는 곳이 하나뿐이라
> 고유 ID 로 구분할 대상이 없다. **둘 이상이 되는 순간** 어느 분기인지 알아야 하고,
> 그때부터 RFID 가 필요해진다 — §6.2 에서 지선을 하나로 못박은 이유다.

### 이 보드에서 RFID 는 특히 나쁘다

**① SPI 핀이 없다.**

```
VSPI 기본:  SCK=18(S2✗)  MISO=19(S3✗)  MOSI=23(S4✗)  CS=5(✓)
HSPI 기본:  SCK=14(PWMB✗) MISO=12(✓)   MOSI=13(S1✗)  CS=15(✓)
```

기본 매핑이 라인센서·모터와 겹친다. GPIO 매트릭스 재배치는 가능하지만
**남는 핀이 G0·G2·G5·G12·G15 — 전부 스트래핑 핀**이다.
특히 G12 는 부팅 시 HIGH 면 플래시 전압이 1.8V 로 잡혀 보드가 아예 안 켜진다.

**② RC522 는 바닥 태그 규격이 아니다.** 13.56MHz, 판독 거리 2~5cm.
현장 AGV 는 125kHz LF 에 큰 안테나를 쓴다. 바닥 태그 ↔ 안테나 간격 관리가
라인센서 높이(3~10mm)만큼 빡빡해진다.

**③ 폴링 지연** 10~30ms/시도 — 주행 중 놓칠 확률이 라인센서보다 높다.
라인센서는 이미 도는 20ms 루프 안에서 즉시 잡힌다.

**④ 신규 하드웨어다.** `센서_지도.md` §5 의 "추가 센서 없음" 결정을 마커로 풀리는 문제 때문에 뒤집는 건 손해다.

### 발표용 논리

> 현장 AGV 는 자기 테이프 + RFID 로 스테이션 고유 ID 를 읽는다.
> 본 시스템은 **경로가 단일 폐루프이고 분기가 하나뿐이라 고유 ID 가 불필요해** 가로선 검출로 대체했다.
> 구역 식별은 비전으로 교차검증한다. **분기가 둘 이상으로 늘면 RFID 가 필요해진다.**

구현하지 않은 것을 **알고서 제외했다**는 게 드러나는 편이 유리하다.

### 🔵 「정지 마커를 따로 두는 것」에 대한 발표 논리 〔2026-08-03 추가〕

*"바닥에 정지선을 그어놓고 거기 서는 게 자율인가"* 는 나올 만한 질문이다. 답을 미리 정해둔다.

**① 2단 정지는 현장 표준이다.** 자기 테이프 AGV 는 테이프 옆에 **감속 마크 → 정지 마크**를
순서대로 깔고, 마크 조합으로 명령을 인코딩한다. 광학식은 반사 테이프 가로 마크를 쓴다.
SLAM 기반 최신 AMR 도 정밀 도킹에서는 **개략 접근 → 감속 → 정밀 정렬**의 같은 3단을 밟는다.
마크 하나로 즉시 멈추는 설계는 쓰이지 않는다 — **제동거리가 속도²에 비례**하기 때문이다.

**② 결정성은 한계가 아니라 요구사항이다.** 현장은 로봇이 매번 다른 곳에 서기를 **원하지 않는다.**
사람과 설비가 공존하는 공간에서 정지 위치는 **측량되고 허가된 지점**이어야 한다.
*"자율"의 가치는 매번 다른 곳에 서는 것이 아니라, 사람 없이 같은 곳에 정확히 서는 것이다.*

**③ 자율성은 다른 층에 있다.** 차체 정지가 결정적이기 **때문에** 팔의 학습 정책이 작동할 수 있다.
현장은 마크 정지의 잔여 오차를 **센터링 지그·기계적 가이드**로 잡는데,
본 시스템은 같은 잔여 오차를 **학습 정책으로** 흡수한다. 문제는 같고, 해법이 한 세대 뒤다.

**④ 누적 오카운트는 이미 이중화했다.** 마커에 고유 ID 가 없다는 약점은 §7 비전 교차검증이
받는다. **질문받기 전에 먼저 말하는 편이 강하다.**

> 🔴 **시각적 보완** — 실제 현장의 정지 마크는 자기 테이프·RFID 라 **사람 눈에 안 보인다.**
> 대신 사람에게 알리려고 **바닥에 정위치 표시**(모서리 ㄱ자 브래킷, 「AGV 정지 위치」 표기)를 따로 그린다.
> 검정 가로선 옆에 이 표시를 나란히 두면, 실험실 감각의 검정선이 **현장 표기 체계 안으로 들어온다.**
> 소품 비용 0원. `../docs/03_scenario_demo/demo_set_build_plan.md` §10.1 참조.

## 4. 마커 규격

| 항목 | 값 | 근거 |
|---|---|---|
| 색·재질 | **검정 무광 테이프** (주행 라인과 동일) | 반사율 대비 유지 |
| 폭 (진행 방향) | **40mm** | 검출 조건 ≥2주기 + 여유 (아래) |
| 길이 (직각 방향) | **≥150mm** | 센서 배열 40mm + 횡방향 오차 여유 |
| 각도 | 라인에 **직각** | 비스듬하면 채널이 순차 점등해 전 채널 동시 HIGH 가 안 뜬다 |
| 배치 | 정지점당 **2개** — 감속 마커 → 정지 마커 | 2단 정지 (§6) |
| 감속↔정지 간격 | **200~300mm** | 제동거리 ∝ 속도². 실측 후 조정 |

### 폭 40mm 의 근거

주행 속도가 **아직 실측 전**이다. 0.3m/s 가정 시:

```
20ms 당 이동 = 6mm
40mm 통과 = 약 6~7 제어주기   (검출 조건 2주기의 3배 여유)
```

🔴 **섀시 주행에서 속도를 재고 재계산할 것.** 속도가 두 배면 주기 수가 절반이 된다.
최소 조건: `마커 폭 ≥ 속도 × 제어주기 × 3`

## 5. 검출 알고리즘

```cpp
// 🔴 주행 중일 때만 마커를 센다 (아래 「정지 중 오검출」 참조)
if (state == CRUISE || state == APPROACH) {

  // 조건: 5채널 전부 HIGH 가 2주기 연속
  bool allBlack = (detectedCount == 5);

  if (allBlack) {
    blackStreak++;
  } else {
    blackStreak = 0;
    markerLatch = false;          // 마커를 벗어나면 래치 해제
  }

  if (blackStreak >= 2 && !markerLatch
      && (millis() - lastMarkerMs) > MARKER_GUARD_MS) {   // 1000ms
    markerLatch  = true;          // 한 마커를 한 번만 센다
    lastMarkerMs = millis();
    onMarker();                   // 상태기계로 전달
  }

} else {
  blackStreak = 0;                // 정지 상태에서 나갈 때 깨끗한 상태로
  markerLatch = false;
}
```

### 오검출 방지 4중

1. **5채널 전부** — 4채널로 낮추면 급커브에서 라인이 배열을 비스듬히 가로지를 때 오검출
2. **연속 2주기** — 순간 노이즈 차단
3. **`MARKER_GUARD_MS = 1000`** — 한 마커 이중 카운트 차단.
   정지점 간격이 1m 이상(세트 3.6×4.0m)이라 0.3m/s 에서 3초 이상 → 가드 1초는 충분히 안전
4. **주행 중 상태에서만 검출** — 아래

### 🔴 정지 중 오검출 〔2026-08-17 추가〕

**정지점이 파지 지점이 되면서 생긴 문제다.** 로봇이 마커 위 또는 경계에 걸친 채로
**파지 동안 약 20초간 서 있게** 된다.

센서가 마커를 계속 밟고 있으면 `markerLatch` 가 유지되어 문제가 없다. 위험한 것은 **경계에 걸친 경우**다.

```
진동·조명 흔들림으로 allBlack 이 한 번 false
        ↓
markerLatch = false  (래치 해제)
        ↓
파지에 20초 → MARKER_GUARD_MS(1초)는 이미 만료
        ↓
allBlack 이 다시 true → 🔴 가만히 서 있는데 마커를 하나 더 센다
        ↓
상태기계의 정지점 순번이 어긋난다 → RPi 가 잘못된 ACT 정책을 로드한다
```

가드 타이머로는 못 막는다. **정지 시간이 가드보다 훨씬 길기 때문**이다.
가드를 20초로 늘리면 이번엔 정상 주행에서 다음 마커를 놓친다.

→ **정지 상태에서는 애초에 마커를 셀 이유가 없다.** 위 코드처럼 상태로 게이팅한다.
`STOPPING` 진입과 동시에 검출이 꺼지고, `CRUISE` 복귀 때 `blackStreak`·`markerLatch` 가
초기화된 상태로 다시 켜진다.

> 재출발 직후 **차체 아래에 남아 있는 마커를 다시 밟는 경우**도 이 초기화로 함께 처리된다 —
> 전진하면 마커에서 멀어지므로 `allBlack` 이 곧 false 가 되고, 그때까지는 아직
> `blackStreak` 가 2에 못 미치거나 래치가 걸린다. 다만 **재출발 시 마커를 밟은 상태로
> 시작하지 않도록 정지 위치를 잡는 편이 안전하다** — §9.1 측정 때 함께 확인할 것.

## 6. 2단 정지 — 상태기계

현장 AGV 의 스테이션 정지는 거의 예외 없이 **감속존 → 정밀 정지** 2단계다.
마커 하나로 즉시 멈추는 설계는 쓰지 않는다 — 제동거리가 속도²에 비례해 산포가 커지기 때문.

```
CRUISE (baseSpeed=120)
   │ onMarker()
   ▼
APPROACH (baseSpeed↓ ~70)        ← 감속 마커
   │ onMarker()
   ▼
STOPPING (숏브레이크 → 정지)      ← 정지 마커
   │ 임무 완료 신호
   ▼
CRUISE
```

**마커 종류를 구분할 필요가 없다.** 다음 마커의 의미는 현재 상태가 정한다.

- 이 구조가 **정지 위치 산포 문제의 1차 대응**이다 (`만능기판_이전_가이드.md` §7 실측 항목)
- 감속은 산업적 현실성(speed zone)도 동시에 얻는다 — 영상에서 눈에 보인다

> 🔵 **순번 체계(모듈로 4)와 상태기계는 바뀌지 않는다** — 바뀌는 것은 각 순번에서 RPi 가 하는 일이다.

| 순번 | 링 위치 | 점검점 | 임무 | 파지물 목적지 | 마커 |
|---:|---|---|---|---|---|
| 1 | 좌측 | **P1** 적색 · **향 없음** | 판정 → 🔵 **통과** (정지 후 재출발, 파지 없음) | — | 2 |
| 2 | 좌측 | **P2** 적색 · 향 있음 | 가스 확정 → **파지 (ACT)** → 뚜껑 봉쇄 | **P2 격리함** | 2 |
| 3 | 후면 | **P3** 노란 종이컵 | 가스 조회 없이 위험 판정 → **파지 (ACT)** → 뚜껑 봉쇄 | **P3 격리함** | 2 |
| **4** | 전면 | **분기점** (스테이션 지선) | 순회 중 **통과**. 입고 시에만 진입 | — | 2 |

**정지점 4개 × 마커 2개 = 검정 가로선 8줄.**

> 🔴 **P4(캔들)는 이 표에 없다 — 마커로 서지 않는다.**
> 정지 트리거가 **KY-026 화염 검출**이다. 감지 → 정지 → 부저 → **개루프 직선 후진** → 정지로 임무가 끝난다
> (`../docs/03_scenario_demo/시나리오_확정_2026-08-15.md` §4.2.1). 🔴 **스테이션으로 복귀하지 않으므로 순번 4 로 되돌아오지 않는다.**
> 순환은 리허설에서 연속 주행할 때만 일어난다.

> 🔵 **관통형 소구획이 확정되면서 정지 횟수가 줄 수 있다** 〔2026-08-18〕.
> 종전에는 P2·P3 마다 **물체 앞 / 격리함 앞** 두 번 섰다. 관통형에서는 물체와 격리함이
> **라인 양옆에 마주 보고** 있으므로 **한 번 서서 왼쪽에서 집어 오른쪽에 넣는다.**
>
> 🔲 **실측 조건** — 한 정지 자세에서 팔이 **양쪽 모두**에 닿는가. 닿으면 정지가 절반으로 줄고
> 시간·실패 지점이 함께 준다. 안 닿으면 종전대로 두 번 선다. **마커 수량은 이 실측 뒤에 확정한다.**

**파지물은 같은 구역 안에서 처리한다 — 물건을 들고 주행하지 않는다.**
목적지가 팔 도달 범위 안이므로 파지 후 곧바로 놓고 재출발한다 (`../docs/03_scenario_demo/demo_set_build_plan.md` §5.5).

> **🔴 순번이 되돌아온다 — 법은 4다.**
>
> ```cpp
> stopIndex = (stopIndex % 4) + 1;              // 4 다음은 1
> if (stopIndex == 4 && !dockRequested) return; // 분기점은 세되 서지 않는다
> ```
>
> 상태기계 쪽은 두 줄이지만 **RPi 는 순번을 절대값이 아니라 순환값으로 받는다.**
> ACT 정책 선택이 여기에 걸려 있으므로, 진우와 정할 메시지 형식에 이 조건이 들어간다.
> 「1번째 정지」와 「5번째 정지」가 같은 ZONE 1 이다.
>
> 촬영되는 임무는 1바퀴이므로 순환이 실제로 일어나지 않지만,
> **리허설에서 연속 주행하면 즉시 드러난다.** 모듈로를 빼먹으면 2바퀴째에 정책 선택이 깨진다.

> **🔴 루프는 단순 폐곡선을 유지한다.**
>
> 선이 만나는 지점은 5채널이 전부 검정이 되어 **마커와 구분되지 않는다.**
> 교차까지 가지 않고 한쪽에 선이 더 있기만 해도 **조향 가중평균이 쏠려 로봇이 휜다**(§2).
> 8자 경로, 가운데를 가로지르는 복귀선 모두 불가.
>
> 충전 스테이션은 루프 밖에 있고 지선으로 연결하지만 **지선이 루프에 닿지 않는다** — §6.2.

> 🔵 **정지 정밀도 요구는 순번 2·3 에 걸린다** 〔8/18 정정 · ~~ZONE 1~~〕.
> 순번 1(P1)은 **통과 판정**이라 파지가 없어 몇 cm 어긋나도 무관하다.
> 파지가 있는 **순번 2·3 은 팔 도달 범위 안에 서야 한다.** 정지 산포 ×10 측정 대상이다.
>
> 🔵 **상태기계 코드는 바뀌지 않는다** — 바뀌는 것은 각 순번 도착 후 RPi 가 하는 일이고,
> 그건 DRIVE 의 관심사가 아니다.

> ## 🔴 「순번으로 정책을 고른다」는 폐기됐다 〔2026-08-18〕
>
> ~~순번 1 → 적색 정책, 순번 2 → 황색 정책~~ → **성립하지 않는다.**
>
> 🔵 **ACT 정책이 1개로 통합됐다** (`../docs/03_scenario_demo/시나리오_확정_2026-08-15.md` §0-3, 8/6 확정).
> 적색·황색을 **같은 정책**이 처리하고, 물체 구분은 **손목 카메라 픽셀**이 한다 —
> 서보 부하 임계만 물체별로 다르다(적 80% / 황 40%). `POLICY_PATHS` 의 클래스별 2개 매핑은 삭제 대상이다.
>
> 🔵 **DRIVE 쪽에 좋은 소식이다** — 순번을 정책 선택에 쓰지 않으므로 **DRIVE 가 RPi 에
> 보내는 순번의 의미가 하나 줄어든다.** 순번은 이제 「어디에 섰는가」만 뜻한다.
> 다만 순번 자체는 여전히 필요하다 — 감속·정지 2단 상태기계와 분기점 판정이 순번으로 돈다.

### 6.1 🔵 ToF 임계 — 300mm 단일 〔2026-08-17 신설 · **08-18 전면 개정**〕

> ## 🔴 구간 전환은 폐기됐다. 이 절의 구현 항목이 하나 사라진다
>
> ~~직선 1000mm / 코너 300mm 를 마커 순번과 통과 이력으로 전환~~ → **폐기.**
>
> **직선 1000mm 가 무엇을 위한 값인지 다시 물었더니 근거가 없었다.** 실제 AMR 이라면
> 멀리서 감속하려는 값인데 **이 세트에는 미리 볼 동적 장애물이 없다.**
> 그 값 하나 때문에 코너마다 벽이 걸려 **전환 로직을 새로 만들어야 했고**,
> 관통형 소구획이 확정되면서 측벽까지 시야각에 들어올 참이었다.

```cpp
// 🔵 구간 판정 불필요. 상수 하나.
static const uint16_t TOF_STOP_MM = 300;
// ~~uint16_t tofStopMm = inCornerSegment ? TOF_CORNER_MM : TOF_STRAIGHT_MM;~~
```

| 구간 | 종전 | 🔵 확정 |
|---|---:|---:|
| 직선 | ~~1000mm~~ | **300mm** |
| 코너 | 300mm | **300mm** |
| 구간 판정 | 마커 순번 + 통과 이력 | 🔴 **불필요 — 삭제** |

**강희 작업이 줄어든다** — `inCornerSegment` 판정, 전환 시점 튜닝, 그에 딸린 실측이 전부 없어진다.

**안전은 남는다** — 기본속도에서 ~0.3m/s 이므로 **300mm 는 1초**다. 계층 ① 반응이 20ms 이고
이 크기 로봇의 제동거리는 수십 mm 다. 사람 발이 30cm 앞에 들어오면 닿기 전에 선다.
**센서를 끄는 것이 아니므로 「장애물 안전」 주장은 그대로 유지된다.**

> 🔴 **ToF 자체를 빼자는 안은 검토 후 기각했다** — 상세는 `센서_지도.md` §4.1.
> **계층 ① 에서 거리를 보는 수단이 ToF 뿐**이고, **NoIR 카메라로 대체할 수 없다.**
> 지면 호모그래피로 거리 계산 자체는 되지만(VGR 이 이미 그 방법이다) 정지 경로가 RPi 를 거치게 되어
> §0 의 ① 계층 요건을 깬다. 발표에서 물으면:
> *"카메라는 RPi 가 살아 있어야 보입니다. ToF 는 RPi 가 죽어도 봅니다."*

🔲 **실측**: 🔴 **소구획을 세운 상태에서** 300mm 가 오검출 없이 도는지 — 코너 4개 + 셀 3개 전부.
~~라인만 깔고 벽 없이 주행해 확인한 뒤 벽을 세운다~~ → **순서가 바뀌었다.**
관통형이라 **라인이 셀을 가로지르므로**, 셀 없이 잰 값은 실제와 다르다.

**걸리면 손대는 순서** — ① 🔵 **VL53L1X ROI 축소**(SPAD 영역을 좁혀 시야각을 줄인다 · 펌웨어 · 0원)
② 임계를 더 낮춘다 ③ 개구부를 넓힌다. **①이 정공법이다** — 원인 자체(넓은 시야각)를 없앤다.

🔲 **벽 높이와 ToF 장착 높이는 둘 다 미확정이다.** 🔴 **벽 높이를 먼저 정하고 ToF 를 맞춘다** —
벽 높이는 촬영·팔·화각이 정하고 되돌릴 수 없는데, ToF 는 높이·임계·ROI 세 손잡이가 있다.

### 6.2 🔴 분기 — 지선이 루프에 연결된다 〔2026-08-17 확정〕

충전·대기 스테이션이 **루프 밖**에 있고 지선(스퍼) 하나로 **접선 합류**한다.

```text
   스테이션 ──╮
              ╰──────╮
   ═══════╫═╫════════╪══════   ← 루프 라인
        정지 감속    합류 (R≈340)
```

- 분기점에 **정지점 마커 2줄** → 정지점 **4개**, 가로선 **8줄**
- 지선은 **양방향**. 나갈 때와 들어올 때 모두 쓴다
- 접선이어야 한다. **직각 합류는 불가능**하다

#### ① 마커만으로는 부족하다 — 조향이 따로 논다

**마커 검출과 조향은 다른 회로다.**

| | 조건 |
|---|---|
| 마커 검출 | 5채널이 **전부** 검정 |
| 조향 | 검출된 채널의 **가중평균** (§2) |

분기선이 옆에 있으면 5채널을 다 채우지 못해도 **가중평균은 이미 그쪽으로 쏠린다.**
크로스바를 지난 **직후**부터 분기선이 배열에 들어오면서 로봇이 휜다.
§2 에서 계산한 측면 마커 사례와 같다 — S1·S2 가 추가로 검정이면 위치 −1.0, 보정 −60.

**마커를 박아두는 것으로는 이 문제가 해결되지 않는다.**

#### ② 분기 선택 — 한쪽 그룹만 본다

실제 자기테이프 AGV 가 분기에서 쓰는 방식이다. 두 선이 보이면 전체 평균 대신
**한쪽 연속 그룹의 중심**만 위치로 삼는다.

```cpp
// 분기 구간에서는 전체 가중평균을 쓰지 않는다
position = (branchMode == KEEP_INNER) ? innerGroupCenter()
         : (branchMode == KEEP_OUTER) ? outerGroupCenter()
                                      : weightedAverageAll();
```

| 상황 | 모드 |
|---|---|
| 순회 중 (분기 무시) | `KEEP_INNER` |
| 스테이션 입고 | `KEEP_OUTER` |
| 그 외 전 구간 | 기존 가중평균 그대로 |

**분기 구간은 정지점 4번 통과 전후로 한정**한다. 나머지 구간에서 그룹 분리를 쓰면
급커브에서 라인이 배열을 비스듬히 가로지를 때 오히려 불안정해진다.

#### ③ 정지점 4번은 세되 서지 않는다

**세지 않고 무시하면 안 된다** — 그러면 다음 마커가 몇 번인지 알 수 없다.
카운트는 하고 **액션만 건너뛴다.**

```cpp
stopIndex = (stopIndex % 4) + 1;              // 3 다음은 4, 4 다음은 1
if (stopIndex == 4 && !dockRequested) return; // 세되, 서지 않는다
```

순회 순서: `ZONE1 → ZONE2 → ZONE3 → 분기점(통과) → ZONE1 …`
RPi 는 순번을 **순환값으로, 법 4로** 받는다.

#### 🔴 분기는 하나만 둔다

두 개 이상이면 「지금 어느 분기인가」를 관리해야 하고, 그때부터 마커에 **고유 ID 가 필요**해진다.
§3 에서 RFID 를 기각한 근거(*"경로 위상이 단일하고 정지점이 적어 고유 ID 가 불필요"*)가
무너지는 지점이다. **지선은 하나로 고정한다.**

#### 🔲 개발·검증 순서

1. 라인을 깔고 **분기 없이** 주행 튜닝을 끝낸다
2. 정지 산포·코너 ToF 를 잰다
3. **그다음에** 분기를 붙이고 `KEEP_INNER` 통과를 ×10 확인
4. `KEEP_OUTER` 입고를 ×10 확인

**동시에 하지 않는다.** 흔들릴 때 원인이 라인 튜닝인지 분기인지 구분되지 않는다.
분기 선택은 **신규 로직**이므로 기존 PD 게인과 상호작용을 따로 봐야 한다.

### 대안 (테이프를 아끼려면)

정지점당 마커 1개 + 감속 후 **고정 시간 주행 → 정지**.
배터리 전압 보상이 속도를 일정하게 유지하므로 시간 기반도 재현된다.
다만 정지 위치가 테이프가 아니라 타이밍으로 정해져 **2마커 방식보다 부정확**하다.

## 7. 구역 검증 — 비전 교차검증

마커의 유일한 약점은 **고유 ID 가 없어 누적 오카운트 가능**이라는 것.
각 구역은 소품·라벨이 달라 화면이 다르므로, RPi `mission_orchestrator` 가 대조하면
**하드웨어 0원으로 이중화**된다.

```
DRIVE 카운트: "3번째 정지 = 위험구역"
프론트 카메라: "위험구역 소품이 보인다"
        └─ 불일치 → 정지 후 경고
```

이게 실질적으로 RFID 고유 ID 의 역할을 대신한다.
심사가 **녹화 영상**이라 마커를 놓쳐도 재촬영이지 임무 실패가 아니라는 점도 감안한다.

> 인터페이스는 진우와 협의 필요 — DRIVE 가 현재 정지점 순번을 `<SENS>` 계열 메시지에 실어 보낼지,
> 별도 필드를 만들지.

## 8. 구역 경계 = 우드락 수직 구조물 〔확정 2026-08-17〕

**구역 경계는 바닥 테이프가 아니라 우드락으로 만든다.**

### 이 결정이 문제 하나를 없앤다

원래 v5 §5.9 계층3 은 위험구역 경계를 **검정/흰색 사선 테이프**로 정했는데, 그게 주행 라인을 가로지르면
라인센서가 마커로 읽고 — 사선이라 검정이 끊겼다 이어지므로 **가짜 마커가 연속으로 터질** 위험이 있었다.
경계가 수직 구조물이 되면 **바닥에 경쟁 테이프가 없어져 이 위험이 원천 제거된다.**

부수 효과로 설계 원칙도 깨끗해진다 — **로봇이 읽는 것(바닥 가로선)과 사람이 보는 것(수직 경계·명판)이 분리**된다.
실제 현장에서도 로봇 측위 체계와 안전 표시 체계는 서로를 읽지 않는다.

| | 담당 |
|---|---|
| 사람이 보는 구역 경계 | **우드락 게이트** + 벽면 ZONE 명판 (세트 계획서 §6.3 에 이미 폼보드 용도로 있음) |
| 로봇이 읽는 정지점 | **바닥 검정 가로선** (§4) |

### 🔴 대신 새로 생긴 제약 4가지

**① 바닥에 우드락을 깔지 말 것 — 라인센서가 깨진다**

TCRT5000 은 바닥과 **3~10mm** 에서만 정상 동작한다 (`README.md` §3).
5T 우드락을 라인 위나 옆에 깔면 그 구간만 바닥이 5mm 높아진다.
7mm 로 맞춰둔 센서가 **2mm 가 되어 포화**한다. 경계는 **반드시 세우는 구조**로만 만든다.

**② 게이트 개구부 ≥ 800mm — ToF 가 기둥을 장애물로 읽는다**

VL53L1X 는 전방 장애물 반사 루프라, 경계 기둥이 빔에 들어오면 **정지·회피가 발동**한다.

```
FOV 27° → 반각 13.5°, tan = 0.24
빔 폭 = 0.48 × 거리

개구부 800mm, 로봇 중심 정렬 → 기둥까지 각 400mm
기둥이 빔에 들어오는 거리 = 400 / 0.24 ≈ 1670mm
횡방향 오차 100mm 를 줘도 = 300 / 0.24 ≈ 1250mm
```

**정지 임계는 1m 이내이므로 800mm 개구부면 안전하다.**
세트 계획서 §4.1 의 「라인 중심 ↔ 고정 장애물 400mm 이상」 기준과도 그대로 맞는다.

> 여유가 부족하면 VL53L1X 의 **ROI 를 좁혀** 빔 폭을 줄이는 방법이 있다 (소프트웨어).
> 다만 유효 거리가 함께 줄어드니 개구부를 넓히는 쪽이 먼저다.

**③ 카메라 시야를 막지 않을 것**

촬영 카메라는 높이 400~600mm 저각(세트 계획서 §4.1)이고,
검증 항목에 **「카메라 이동 없이 ZONE 1~3 의 핵심 행동을 촬영할 수 있다」**(§13.1)가 있다.

- 구역이 좌→우로 늘어서 있으므로 경계는 **전후 방향**이 되어 카메라에서 **측면으로 보인다** → 가림이 적다
- 그래도 상단 가로대(문틀 윗변)는 두지 않는 편이 안전하다. **양쪽 기둥만** 세우는 형태 권장
- 기둥 높이는 300~400mm 면 구역 구분이 읽히면서 뒤쪽 동작을 가리지 않는다

**④ 자립·안전 — 우드락은 단프라보다 가볍다**

- 세트 계획서 §12.2: 외부 무게추 금지, 넘어질 우려가 있는 소품은 **벽 뒤 구조와 연결하거나 마스킹테이프 위에 고정**
- 접이식 발이나 ㄴ자 받침을 붙여 자립시킨다. 받침은 **주행로 밖**으로
- 우드락 **절단면은 부스러지므로 테이프로 감쌀 것** (§12.2 와 동일 취지)
- 로봇이 부딪히면 넘어진다 — 파손은 아니지만 **재촬영**이다. 개구부 여유를 넉넉히

### 사선 무늬는 기둥에 그대로 쓴다

v5 가 의도한 **검정/흰색 사선**은 바닥이 아니라 **기둥 표면**에 적용한다.
현장의 위험구역 방호 기둥에 줄무늬를 넣는 것과 같은 형태라 오히려 현실성이 올라가고,
빨강·노랑을 쓰지 않으므로 HSV 마스크 충돌도 없다 (v5 857~860행의 회피 근거는 그대로 유효).

### 9.1 정지 산포 측정 절차

**왜 하는가** — 로봇은 마커에서 매번 똑같은 자리에 서지 않는다. 그 변동폭이 곧
**팔 기준에서 물체가 움직이는 폭**이고, 그것이 **ACT 가 학습해야 할 분포의 폭**이다.
한 자리에서만 수집한 데이터로 산포가 있는 실제 주행을 찍으면, 정책은 학습 때 못 본 화면을 보게 된다.

**산포의 원인**

| 원인 | 성격 |
|---|---|
| 마커 검출 양자화 | 20ms 주기 × 2사이클 연속 조건 → **접근속도 × 40ms** 가 하한. 0.15m/s 면 6mm |
| 배터리 전압 변동 | 접근 속도가 달라져 제동거리가 달라진다. 전압 피드포워드가 1차로 잡는다 |
| 바닥 마찰·먼지 | 숏브레이크 제동거리에 직접 영향 |
| 라인 추종 잔류 오차 | 좌우(y) 산포와 방위각(θ) 산포의 원인 |

**측정 조건 — 이걸 안 맞추면 측정값이 무의미하다**

- 섀시 완성 + 팔 장착 후. **무게가 제동거리를 바꾼다**
- 라인센서 감도를 실제 주행 높이·촬영 조명에서 최종 조절한 다음
- 배터리를 **완충 / 중간 / 하한** 세 구간에서 나눠 측정. 촬영 당일 잔량을 고를 수 없다
- 출발점을 매번 동일하게. 접근 구간 길이가 다르면 속도가 다르다

**측정 방법**

1. 정지 마커 옆 바닥에 **기준선**을 긋고 자 또는 모눈종이를 붙인다
2. 차체에 기준점을 하나 정한다 (앞 모서리 중앙 또는 바퀴축 중심). **매번 같은 점**
3. **정지점 1** 에서 10회 주행 → 매회 아래 3개를 기록

| 기호 | 측정값 | 왜 필요한가 |
|---|---|---|
| **x** | 진행 방향 전후 오차 (mm) | 물체까지의 거리가 바뀐다 |
| **y** | 좌우 오차 (mm) | 물체가 화면 좌우로 밀린다 |
| **θ** | 차체 방위각 (도) | 🔴 **화면 전체가 회전한다.** 가장 다루기 어렵다 |

4. **정지점 2** 에서 동일하게 10회
5. 각각 **최댓값 − 최솟값**을 산포로 기록한다

> ⚠ 10회의 최대-최소는 **실제 범위보다 좁게 나온다.** 데이터 수집 범위로 넘길 때는
> 측정값에 **여유를 30% 정도 더해서** 쓴다. 좁게 잡는 쪽이 실패가 크다.

**결과 판정과 조치**

| x·y 산포 | 판정 | 조치 |
|---|---|---|
| ±3cm 이하 | 양호 | 그 범위로 데이터 수집 |
| ±3~8cm | 경계 | APPROACH 속도를 낮추고 재측정 |
| ±8cm 초과 | 과다 | 감속 마커를 한 줄 더 앞에 붙여 3단 감속 → 재측정 |

θ 는 별도로 본다. **3° 이하면 무시**하고 물체 각도 변화로 흡수한다.
그보다 크면 데이터 수집 때 **차체를 실제로 비스듬히 세운 에피소드**를 섞어야 한다 —
물체를 옮기는 것으로는 화면 회전을 재현할 수 없다.

> 🔴 **적색(정지점 1)은 이 흡수 여유가 좁다** 〔2026-08-03〕
>
> 적색 블록을 **정방향 배치**로 확정했기 때문이다 (`docs/03_scenario_demo/demo_set_build_plan.md` §5.1).
> 의도적인 각도 변화를 넣지 않으므로, θ 를 흡수해 줄 각도 분포가 그만큼 얇다.
>
> - **정지점 1 의 θ 를 반드시 측정한다.** 황색보다 우선순위가 높다
> - 3° 를 넘으면 순서대로: ① APPROACH 감속으로 θ 자체를 줄인다
>   → ② 그래도 크면 **적색 수집에 각도 변동을 넣는다** (정방향 배치 결정을 되돌린다)
> - **물체를 손으로 놓을 때 나는 몇 도의 자연 오차는 없애지 말 것.** 공짜로 얻는 여유다
>
> 🔵 **손목 롤은 제약이 아니다.** 창이 ±157°(총 314°)라 각도 변동을 넣는 데 하드웨어 문제가 없다
> (`calibration/README.md`). 정방향 배치는 **수집 시간**을 위한 선택이므로,
> ②는 하드웨어가 아니라 **시간**만 쓰면 실행할 수 있다.

**데이터 수집으로 넘기는 방법**

수집 때 매번 주행시킬 필요는 없다. **로봇을 공칭 정지 위치에 세워두고 물체를 측정 범위 안에서
옮기는 것으로 등가**다 (x·y 한정). 에피소드마다 주행을 반복하면 수집 시간이 몇 배가 된다.

→ 이 값이 계획 개선안 v5 §6 프로토콜 ③ 「물체 위치·각도 변화 범위」에 그대로 들어간다.
