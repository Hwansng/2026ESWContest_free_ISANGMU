# 1. 즉답 — 오늘 안에 정해지는 것

## 1.1 `GAS_THRESHOLD = 400` → 강희 실측값 대기 · 🔵 판단 맞음

- 🔵 **구역별 딕셔너리를 제거한 것이 정본대로다.** 판정은 구역을 몰라야 한다
  (점검점 내용물이 서로 바뀔 수 있어서, 판정에 위치를 넣으면 **소품 하나를 옮길 때 코드가 틀린다**)
- 강희가 오늘 P1(향 없음 기준선) / P2(향 있음 검출값)을 여러 번 재고 **그 사이**로 정한다 → 상수 한 줄 교체

🔴 **덧붙일 것 하나** — 8/06 사본 기준으로 **대시보드에도 임계가 따로 하드코딩돼 있었다**
(`dashboard_node.py`, `ZONE_GAS_THRESHOLDS` = 300 / 500 / 9999).
🔴 `hazard_detector` 쪽(300 / 200 / 150)과 **값이 서로 달랐다.** 이미 지웠으면 무시하고,
안 지웠으면 **같이 지워야** 두 곳이 갈리지 않는다.

## 1.2 `sensor_bridge` distance 파싱 유지 → 🔵 판단 맞음

먼저 지우면 깨진다는 판단이 옳다. 순서는 이것이다:

```
  ① 강희: ENV 펌웨어 <SENS> 에서 DISTANCE · BAT 제거
  ② 진우: sensor_bridge 의 distance 파싱·발행 제거      ← ① 완료 확인 후
```

🔴 **①과 ② 사이에 구간이 있다.** 오늘 강희 작업이 끝나면 그 자리에서 확인하고 지우면 된다.
🔵 ToF 가 DRIVE 소관이라는 방향은 배선 정본(`docs/06_firmware/배선_확정_2026-08-14.md`) 그대로다.

## 1.3 ENV↔RPi 포트 → ✅ **8765 확정**

**5002 를 고르면 안 되는 이유가 있다.**

ENV 가 오타로 **5000** 에 붙으면 연결이 실패하는 게 아니라 **`amr_bridge` 가 받는다.**
그런데 두 `<SENS>` 는 필드 배치가 다르다:

```
ENV   : <SENS, MQ135, MQ2, FLAME, BAT, STATE, ACTION, FAULT, DISTANCE, CS>
DRIVE : <SENS, battCv, state, action, fault ...>
```

🔴 **조용히 엉뚱한 값이 배터리·상태로 파싱된다.** 연결은 「성공」이고 대시보드에 숫자도 뜬다.
**8765 는 5000 과 멀어서 이 사고가 원천적으로 안 난다.** 코드 유지, **문서를 고친다.**

# 2. 설계 판단

## 2.1 `arm_act_node` EMERGENCY 경로 → 🔴 **화염만 즉시 경로를 추가한다** (이중 경로)

**1초는 너무 길다.** 화염 시퀀스가 「감지 → 정지 → 부저 → 후진」인데,
팔이 물체를 든 채 1초를 더 움직이면 장면이 깨진다.

🔵 **다만 원래 방식으로 통째로 되돌릴 필요는 없다. 두 경로를 같이 둔다:**

```
  정상 경로 : /mission/state 구독 → orchestrator 판단을 따른다     ← 권한 일원화 유지
  긴급 경로 : hazard_cb 에서 화염만 판별 → 즉시 정지               ← 지연 제거
```

🔵 **이건 이 프로젝트의 4계층 정지와 같은 형태다** — 상위가 판단하되
**가장 급한 것 하나만 로컬에서 먼저 자른다.** 화염이 그 하나다.

🔴 **`/mission/state` 발행 주기를 올려서 해결하지 말 것.** 상태 발행 주기를 안전 반응 시간으로 쓰면,
나중에 누가 주기를 바꿀 때 **안전이 조용히 느려진다.**

## 2.2 `mission_orchestrator` HOME 도착 확인 → 🔵 **방향 맞음. 단 지금은 임시 유지**

`/amr/home_arrived` 신설 방향은 맞다. 🔴 **다만 이건 정지점 순번 규격과 같은 문제다.**

오늘 3인 합의에서 **정지점 순번을 `<SENS>` 안의 「상태」 필드**로 넣기로 하면
(이벤트 메시지가 아니라 상태 — 주기 송신이라 **놓쳐도 다음 패킷에 같은 값이 온다**),
**HOME 도착도 별도 토픽 없이 그 상태로 표현된다.**

🔵 **권고: 순번 규격이 확정될 때까지 임시 방식 유지.** 토픽을 먼저 만들면 나중에 둘이 겹친다.

## 2.3 구역별 판정 매트릭스 카드 → 🔵 **빼지 말고 문구를 바꾼다**

🔴 **세 구역이 같은 결과가 뜨는 지금이 제일 나쁘다.** 화면에 의미 없는 표가 남는다.

🔵 **그런데 이 카드의 서사는 살릴 수 있고, 오히려 더 강해진다.**
판정에서 구역을 뺀 이유가 *"점검점 내용물이 서로 바뀔 수 있다"* 였다.
그러니 카드의 주장을 이렇게 바꾼다:

| | 종전 | 🔵 바꿀 것 |
|---|---|---|
| 제목 | 「같은 값, 다른 판정」 | **「위치가 아니라 내용으로 판정한다」** |
| 증거 | 구역별 임계 3행 | **P1(적색·가스 없음) = 통과 / P2(적색·가스 있음) = 격리** |

🔵 **같은 색 · 같은 자리 · 다른 판정**이라 시연 장면과 정확히 일치한다.
🔴 P1 통과 장면이 없으면 이 로봇은 컬러 필터와 구분되지 않는다 — 그 장면의 화면 증거가 이 카드다.

🔴 **발표 서사라 승환·강희와 같이 확정하는 게 맞다.**

## 2.4 `DESTINATION_BY_CLASS` → 🔵 **삭제 보류가 옳았다**

삭제하려던 근거는 *"목적지가 색이 아니라 위치로 결정된다 — 점검점마다 격리함 하나"* 다.
즉 **클래스로 목적지를 고르는 것 자체가 틀렸다**는 뜻이지, 지금 지우라는 뜻이 아니었다.
🔴 **대체 로직이 없는데 지우면 깨진다.** 순서는 이렇다:

```
  ① 정지점 순번 → 격리함 오프셋 매핑 구현      ← 승환이 오늘 격리함 정렬 오프셋을 잰다
  ② 그 다음에 DESTINATION_BY_CLASS 제거
```

🔵 **오늘은 그대로 두는 게 맞다.**

# 3. 임시 상수

| 상수 | 답 |
|---|---|
| `CMD_VEL_TIMEOUT_SEC = 1.0` | 🔵 **`RPI_TIMEOUT` 과 같은 값으로 맞추는 게 맞다.** 🔴 다만 **하트비트 주기부터 어긋나 있다** — 문서 0.3초 / 8/06 코드 `create_timer(0.5, ...)`. **주기를 먼저 확정해야 타임아웃이 유도된다**: `주기 × 허용 연속 누락 + 여유`. 0.3 × 3 = 0.9 → **1.0초** |
| `MOVE_TIMEOUT_SEC = 5.0` | 🔵 오늘 승환이 팔을 4~5시간 돌린다. 텔레옵 중 관절 도달 편차를 볼 기회라 **실측 근거를 오늘 얻을 수 있다** |
| `POSITION_TOLERANCE = 20` | 〃 |

🔴 **타임아웃 판단은 대칭이 아니다.** 짧으면 헛 정지(테이크 다시 찍으면 된다),
길면 늦게 정지(세트를 부순다). **의심스러우면 짧게.**
