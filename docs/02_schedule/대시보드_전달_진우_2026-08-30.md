## 0. 배경 — HazardBot이 뭘 하는 로봇인지

HazardBot은 위험물 취급 구역을 순찰하면서, 정지 지점마다 카메라로 물체를 보고 "이게 지금 위험한 상태인가"를 판단해서 화면(대시보드)에 표시하는 로봇이다. 판단 규칙은 딱 두 가지 색만 본다.

- **노란색 물체 = 산화성 고체.** 고체라서 가스를 내뿜지 않는다. 그래서 **가스를 잴 필요 없이, 보이는 순간 바로 "위험"으로 판정한다.** (이유: 인화성 물질을 다루는 구역에 산화성 고체가 있는 것 자체가 규정 위반이다.)
- **빨간색 물체 = 인화성 액체(알코올).** 액체는 용기가 멀쩡하면 안전하고, **새어나올 때만 위험하다.** 그래서 카메라로 빨간색을 본 다음 **가스 센서로 3초간 다시 확인**하고, 그 결과에 따라 "위험" 또는 "정상"으로 판정이 갈린다.

이번 작업은 이 판정 로직(이미 완성돼 있음)을 **화면(대시보드)에서 문장으로 보여주는 것**이다. 로직 자체를 고치는 게 아니다.

---

## 1. 무엇을 만들었는가 — 화면에 실제로 뜰 문장 (확정, 그대로 쓸 것)

**노란색 물체를 봤을 때** 화면에 뜨는 문장:
```
황색 산화성 고체 감지 — 취급구역 내 위치 자체가 위반
```

**빨간색 물체를 봤는데 가스가 검출됐을 때** 화면에 뜨는 문장:
```
적색 물질 — 가스 감지(zone=P1 또는 P2). 격납 파손
```

**빨간색 물체를 봤는데 가스가 검출 안 됐을 때** 화면에 뜨는 문장:
```
적색 물질 — 가스 없음(zone=P1 또는 P2). 격납 유지, 통과
```

이 세 문장은 이미 코드(`hazard_detector_node.py`)에 그대로 박혀 있다. **바꿀 필요 없고, 그대로 화면에 나오는지만 확인하면 된다.**

### 2-1. `ros2_ws/src/hazardbot_dashboard/hazardbot_dashboard/dashboard_node.py`
- `/env/gas_result` 토픽 구독 추가 — 가스 검사 결과(zone, 판정, 원시값)를 화면 데이터로 받아옴
- 예전에 쓰던 3구역 임계값 표(`zone_thresholds`) 삭제 — 지금 판정 방식이랑 안 맞아서 뺐음

### 2-2. `ros2_ws/src/hazardbot_dashboard/templates/index.html`
- **"위험물체 판정" 카드** — 1번 항목의 문장이 여기 뜬다. 색상 표시(●빨강/●노랑)도 같이 뜬다
- **"가스 정밀검사(GAS_CHECK)" 카드** — 어느 구역을 쟀는지, 판정(검출/정상/오류), 세부 수치

**이 두 파일은 이미 완성됐다. 코드 내용을 이해하거나 고칠 필요 없이, 아래 4번 순서대로 RPi에 올리기만 하면 된다.**

## 3. 지금 막혀 있는 것 — RPi 접속 비밀번호

`ssh hazardbot@hazardbot.local`로 접속해야 하는데 비밀번호를 모른다. 아래 순서를 그대로 따라가면 된다.

**3-1. 비밀번호로 먼저 접속해서 SSH 키를 등록한다** (이 한 번만 비밀번호가 필요하고, 이후로는 안 물어봄):
```bash
cat ~/.ssh/id_ed25519.pub | ssh hazardbot@hazardbot.local \
  "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```
- 비밀번호를 물어보면 입력한다. (비밀번호 자체는 RPi를 처음 세팅한 사람이 알고 있음 — 모르면 팀에 물어볼 것)
- `hazardbot.local`로 안 붙으면 `192.168.4.1`로 시도할 것: `ssh hazardbot@192.168.4.1`

**3-2. RPi가 방금 재부팅된 상태라면**, 위 명령보다 먼저 RPi 본체(모니터+키보드 직결 또는 이미 열려 있는 다른 터미널)에서 이 명령을 한 번 실행해야 접속 자체가 된다:
```bash
sudo ip addr add 192.168.4.1/24 dev wlan0
```
(재부팅할 때마다 이 IP가 초기화된다. 접속이 아예 안 되면 이것부터 의심할 것.)

## 4. 배포 순서 — 이대로 그대로 실행

**4-1. 예전에 켜져 있던 프로그램들 정리** (안 하면 포트 충돌로 새 화면이 안 뜬다):
```bash
ssh hazardbot@hazardbot.local "pkill -f amr_bridge_node; pkill -f sensor_bridge_node; pkill -f dashboard_node; pkill -f hazard_detector_node; pkill -f vision_node; pkill -f camera_node"
```

**4-2. 파일 전송** (아래 두 줄, HazardBot 폴더에서 실행):
```bash
scp ros2_ws/src/hazardbot_dashboard/hazardbot_dashboard/dashboard_node.py \
    hazardbot@hazardbot.local:~/ros2_ws/src/hazardbot_dashboard/hazardbot_dashboard/dashboard_node.py

scp ros2_ws/src/hazardbot_dashboard/templates/index.html \
    hazardbot@hazardbot.local:~/ros2_ws/src/hazardbot_dashboard/templates/index.html
```

**4-3. 빌드**:
```bash
ssh hazardbot@hazardbot.local "cd ~/ros2_ws && source /opt/ros/jazzy/setup.bash && colcon build --symlink-install --packages-select hazardbot_dashboard"
```
- 에러 없이 끝나면 성공. 에러 나면 화면에 뜬 에러 메시지를 그대로 캡처해서 승환에게 물어볼 것 (직접 판단해서 코드 고치지 말 것).

**4-4. 실행**:
```bash
ssh hazardbot@hazardbot.local "cd ~/ros2_ws && source install/setup.bash && ros2 launch hazardbot_dashboard hazardbot_patrol_demo.launch.py"
```
- 이 창은 끄지 말고 계속 켜둔다. 로그가 계속 흐르는 게 정상이다.

**4-5. 화면 확인**: 컴퓨터 브라우저에서 `http://hazardbot.local:8080` 접속 (안 되면 `http://192.168.4.1:8080`)

## 5. 실물 검증 — 정확한 순서

### 준비물
- **노란색 물체**: 이전 검증 때 쓴 노란 종이컵(또는 같은 계열의 노란색 물체)
- **빨간색 물체 2개**: 빨간 소분 용기 — 하나는 **향(인센스)을 피워서 안에 넣어둔 상태**(=가스 있음), 하나는 **아무것도 안 넣은 상태**(=가스 없음)
  - 참고: 이 용기는 시나리오상 "인화성 액체(알코올)를 담은 용기"라는 설정이라 MQ-2 센서(알코올·가연성 가스·연기 감지)를 쓰는 것이고, 향을 피우는 건 그 가스 누출을 실물로 재현하는 실용적인 방법이다. 초를 켜서 "화염"을 재현하는 것과 같은 방식이니 신경 안 써도 됨

### 순서
1. 카메라 앞에 **노란색 물체**를 놓는다 → "위험물체 판정" 카드에 `● 노랑 물체`와 1번 항목의 노란색 문장이 뜨는지 확인
2. 카메라 앞에 **밀폐한 빨간색 물체**를 놓는다 → "가스 정밀검사" 카드에 판정이 `🟢 정상 — 통과`로 뜨는지, "위험물체 판정" 카드에 1번 항목의 "가스 없음" 문장이 뜨는지 확인
3. 카메라 앞에 **개방한(알코올 적신) 빨간색 물체**를 놓는다 → "가스 정밀검사" 카드가 `🔴 검출 — 위험`으로 뜨는지, "위험물체 판정" 카드에 1번 항목의 "가스 감지" 문장이 뜨는지 확인

**주의**: 2번과 3번 순서를 바꾸지 말 것. 알코올 가스는 한번 감지되면 센서가 정상으로 돌아오기까지 약 30초가 걸린다. 개방한 것(3번)을 먼저 테스트하면, 그 직후에 밀폐한 것(2번)을 테스트해도 잔류 가스 때문에 잘못된 "위험" 판정이 나올 수 있다. **반드시 밀폐(2번) → 개방(3번) 순서로 할 것.**

## 6. 화면이 안 바뀔 때 — 이렇게 할 것 (결정 완료, 고민할 필요 없음)

대시보드는 물체를 봤다는 "신호"가 와야 카메라 분석을 시작한다. 정상적인 상황(로봇이 실제로 주행하다 마커에서 멈춤)에서는 이 신호가 자동으로 온다. **그런데 지금은 로봇 주행(모터)이 고장 나 있어서 이 자동 신호가 안 온다.**

그래서 검증·촬영 때는 **아래 명령어로 신호를 직접 보낸다.** 물체를 카메라 앞에 놓은 다음, 새 터미널을 열어서 RPi에 접속한 뒤 이 명령을 실행한다:

```bash
ssh hazardbot@hazardbot.local
# 접속된 상태에서:
source ~/ros2_ws/install/setup.bash
ros2 topic pub /amr/object_near std_msgs/msg/Bool "{data: true}" --once
```

이 명령을 실행하는 순간 카메라가 사진을 분석하고, 화면이 몇 초 안에 바뀐다. **물체마다(5번의 1·2·3 각 단계마다) 이 명령을 한 번씩 다시 실행해야 한다.**

(참고 — 실제 촬영 영상에 이 화면을 쓸 경우, 로봇이 스스로 감지한 게 아니라 사람이 신호를 준 것이므로 화면 한쪽에 "DEMO INPUT" 또는 "모의 입력"이라고 자막을 넣어야 한다. 이건 편집 담당 강희와 승환이 처리할 부분이니 진우는 신경 안 써도 된다.)
