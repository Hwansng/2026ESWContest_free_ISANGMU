# 2. 미션 로직 (정본 §8.1-3·4·5)

## 2.1 `CLASSIFY` 판정 + 진입 조건 반전 (규모 중)

### 🔴 판정은 구역을 몰라야 한다

| 색 | 가스 | 판정 |
|---|---|---|
| 적색 | **있음** | 위험 → 격리 (`CONTAINMENT_BREACH`) |
| 적색 | **없음** | 🔵 **통과** |
| 황색 | 무관 | 항상 위험 → 격리 (`HANDLE_CARE`) |
| 화염 | — | 비상 → `RETURN` |

**왜 구역을 안 보는가**: 점검점의 내용물이 서로 바뀔 수 있다.
**판정에 위치를 넣으면 소품 하나를 옮길 때 코드가 틀린다.**

🔵 **황색이 가스를 안 보는 이유는 물리적 사실이다** — 산화성 고체는 가연성 가스를 내지 않는다.

### 진입 순서 반전 (§3.2)

정본 §3.2 대로 **진입 조건을 반전**한다. 종전 순서로는 통과 판정이 성립하지 않는다.

🔴 **P1 통과 장면이 여기 걸린다.** *적색을 보고 지나치는 장면*이 없으면
이 로봇은 **컬러 필터와 구분되지 않는다.**

## 2.2 `RETURN` 상태 신설 (규모 중)

🔴 **`EMERGENCY` 와 하트비트 처리가 반대다. 이게 핵심이다.**

| | `EMERGENCY` (정지형) | `RETURN` (복귀형) |
|---|---|---|
| 하트비트 | **중단** → DRIVE 타임아웃 정지 | 🔵 **유지** — 주행 능력이 살아 있어야 한다 |
| 부저 | ON | ON |
| 동작 | 정지 | 감지 → 정지 → 부저 → **후진** → 정지 |
| 해제 | 수동 | 자동 (완료 후 `IDLE`) |

### 🔵 후진 이탈 (8/9 변경 — 스테이션 복귀 폐기)

- 🔴 **전진 복귀는 폐기됐다.** 로봇이 불을 발견하고 **불 쪽으로 가고 있었다**
- 논리: **로봇 자신이 점화원 후보다.** 이탈은 도망이 아니라 **점화원 제거 조치**
- 🔴 **자막·나레이션은 「점화원 이탈 · 관제 보고」** — *"충전 복귀"* · *"안전구역 복귀"* 둘 다 금지
  (후진 이탈은 **이격만** 하지 안전구역에 **도착하지 않는다**)
- 후진은 **개루프 직선** — 라인 추종 없음. 🟠 800mm 내외, 실측은 승환

## 2.3 `/mission/start` + 출발 전 점검 7항목 (규모 중)

- 부팅 즉시 출발은 **폐지**됐다
- `/mission/start` 토픽으로 출발 → 🔵 **복귀 완료 후 `IDLE` 로 돌아가므로
  노드 재시작 없이 재출발**한다 → **반복 촬영이 된다**
- 🔴 **이것이 촬영 예산의 실질적 보험이다.** 파지 재시도 1회가 약 15초인데
  예산에 여유가 없다 — 예산을 지키는 방법은 **잘 나온 테이크를 고르는 것**이다
- 🔲 **점검 임계값 미확정** — 배터리 하한 · 가스 기준선 안정 판정 기준(변동폭·시간창).
  🔴 **출발이 부당하게 거부되면 촬영이 막힌다**

## 4.1 VGR 과 ACT 는 직렬이다

```
  NoIR 비전 → 픽셀 좌표 → 호모그래피 → 팔 베이스 x·y → 접근
                                                        ↓
                                              ACT 가 마지막 폐루프 파지
```

🔵 **이 구조가 발표의 강한 주장이 된다** — *"접근 오차는 산업 표준 비전 보정이 접고,
마지막 폐루프 파지만 학습이 맡는다."* VGR 을 빼면 ±30mm 전 범위를 데이터로 덮어야 해
에피소드가 몇 배로 뛴다. **학습의 사용 범위를 절제했다는 증거가 여기 남는다.**

🔴 **호모그래피는 카메라-팔 베이스 상대 포즈가 고정되어야 성립한다.**
**바퀴 교체(75mm, +5mm)로 배율이 바뀌면 재측정**해야 한다.

## 4.2 `DESTINATION_BY_CLASS` 를 왜 지우는가

목적지가 **색이 아니라 위치로 결정**된다 — **점검점마다 격리함 하나**다.
🔴 **비전으로 격리함을 찾지 않는다.** 정지마커 기준 **고정 오프셋**이다.

# 5. 🔴 NoIR 색 분리 검증 (오늘, 승환과)

**감지 카메라가 CSI NoIR 본인임이 8/21 에 판명됐다.**
종전 문서들이 「진우 보유 카메라」와 「CSI NoIR」을 별개 2대로 적고 있었으나 **같은 한 대**다.

🔴 **NoIR 은 IR 차단 필터가 없어 적외선이 R 채널로 새어 노랑이 적색 쪽으로 밀린다.**
🔴 **정본 §3.1 판정표 4행 중 3행이 색으로 갈린다.**

## 방법

- 🔴 **카메라 2대에서 각각** — CSI NoIR(감지) · 손목 SO-ARM(ACT 입력, 정색)
- 🔴 **오늘 고정한 촬영 조명 아래에서**
- 물체를 **각각의 소구획 안에 놓은 상태로** (근경 배경이 셀이다)
- 판정: **Hue 분포가 겹치지 않는가.** 겹치면 S·V 로 갈리는가

## 실패 시 대책 순서

```
  ① 조명 LED 고정      ← 오늘 어차피 한다
  ② AWB 고정
  ③ IR-cut 필터
  ④ 형상 특징 병용 (색 단독 → 색 + 형상)
  ⑤ 보유 중인 Innomaker 로 교체     ← 신규 구매는 마지막
```

🔴 **오전 중에 결론.** ③~⑤ 로 가야 하면 **그 자체가 오늘의 우선순위**가 되고 수집이 하루 밀린다.

# 8. 통신 규격

| 채널 | 포트 | 방향 | 메시지 |
|---|---|---|---|
| `amr_bridge` ↔ DRIVE | **5000** | RPi → DRIVE | `<HB,CS>` · `<MOVE,L,R>` · `<STOP,CS>` |
| | | DRIVE → RPi | `<SENS>` (battCv · state · action · fault) · 정지점 순번 |
| `sensor_bridge` ↔ ENV | 🔲 **8765 vs 5002** | RPi → ENV | `<BUZZ,n>` |
| | | ENV → RPi | `<SENS>` (gas · flame) |

- `HEARTBEAT_INTERVAL` = **0.3초** · EMERGENCY 시 발행 중단
- 🔲 `RPI_TIMEOUT` **실측 필요** — 3초 → 1초 전후.
  짧으면 **WiFi 오작동 정지(nuisance trip)**, 길면 주행 중 상당 거리를 간다
- 🔲 **EMERGENCY 시 `<STOP>` 병행 발행** — 하트비트 중단만으로는 정지가 타임아웃만큼 늦는다
- 🔲 **정지점 순번 메시지 규격** (승환 → 진우) — 🔴 **모듈로 4 순환값**이다
- 🔵 **구역 번호는 통신에 넣지 않는다** (§5.3) — 판정이 위치를 모르기 때문

🔴 **성공 기준을 낮게 잡는다.** 값 하나가 끝에서 끝까지 흐르면 그날은 성공이다.

```
  6. 🔴 ACT 추론 루프 착수            8/20 학습 결과를 받을 준비
  7. 대시보드 (통과 판정 · 버튼)      §9-7 기한 오늘
  8. VGR 소비 · 정리 3건
```

🔴 **6번을 뒤로 미루지 말 것.** 규모가 「대」이고, **8/20 저녁에 체크포인트가 나온다.**
그때 루프가 비어 있으면 **8/21 판정 자체를 못 한다.**

# 🔴 절대 하면 안 되는 것

| | 결과 |
|---|---|
| **`last_recv_time` 방치** | 정상 하드웨어에서도 DRIVE 가 2초 뒤 정지 |
| **`RETURN` 에서 하트비트 중단** | 후진 이탈이 안 된다 — `EMERGENCY` 와 반대다 |
| **판정에 구역·위치 넣기** | 소품 하나를 옮기면 코드가 틀린다 |
| **비전으로 격리함 찾기** | 정지마커 기준 **고정 오프셋**이다 |
| **`detected_angle` 로 손목 회전** | 둘 다 축대칭 — 원형 블롭에서 불안정 |
| **ACT 입력을 2뷰로 가정** | 키가 `observation.images.wrist` 하나뿐 — **전량 재수집** |
| **RPi 추론 지연이 수집과 다름** | 도메인 갭 — 정책이 안 맞는다 |
| **자막에 「Zone」·「충전 복귀」** | IEC 60079 의 Zone 은 **기기 반입 등급** — 방폭 인증을 주장하게 된다 |
