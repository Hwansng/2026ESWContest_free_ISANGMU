## 2. 설계 방향 확인이 필요한 것

### 2.1 arm_act_node의 EMERGENCY 반응 경로

| | |
|---|---|
| 파일 | `arm_act_node/arm_act_node.py` |
| 현재 상태 | `hazard_cb`는 로깅만 하고, 실제 EMERGENCY 판정은 `/mission/state` 구독으로 mission_orchestrator의 판단을 그대로 따르는 구조로 설계함 |
| 확인 필요 | `/mission/state`가 1초 주기 발행이라 화염 감지부터 팔이 멈추기까지 최대 1초 정도 지연 발생 가능함. 더 빠른 반응이 필요하면 hazard_cb에서 화염 종류를 직접 판별하는 원래 방식으로 되돌릴지 결정 필요 |

### 2.2 mission_orchestrator HOME 상태 처리

| | |
|---|---|
| 파일 | `mission_orchestrator/mission_orchestrator_node.py` |
| 현재 상태 | TRANSPORT 완료 후 ISOLATE REPORT HOME을 곧바로 순서대로 밀어서 PATROL로 복귀시키는 임시 방식임. AMR이 실제로 홈 위치에 도착했는지 확인하는 과정이 없음 |
| 확인 필요 | DRIVE가 고장 상태라 지금은 실제 도착 확인 경로가 없음. DRIVE 복구 후 `/amr/home_arrived` 같은 토픽을 신설해서 HOME에서 대기하다가 실제 도착 신호를 받은 뒤 PATROL로 넘어가는 방식으로 바꿀지 확인 필요 |

### 2.3 구역별 판정 매트릭스 카드 방향

| | |
|---|---|
| 파일 | `hazardbot_dashboard/templates/index.html` |
| 현재 상태 | 판정 로직이 구역 무관 단일 기준으로 바뀌면서, 세 구역 모두 항상 같은 결과가 뜨도록 수정함 |
| 확인 필요 | 원래 이 카드는 같은 가스값이 구역마다 다르게 판정된다는 걸 보여주는 발표용 화면 증거였음. 판정 로직이 바뀐 지금 이 스토리가 성립하지 않아서, 카드를 이대로 둘지 다른 내용으로 바꿀지 아예 뺄지 팀 확인 필요 |

### 2.4 DESTINATION_BY_CLASS 삭제 여부

| | |
|---|---|
| 파일 | `mission_orchestrator/mission_orchestrator_node.py` |
| 현재 상태 | 작업일정 문서에는 삭제 대상으로 적혀 있으나, TRANSPORT 전이 로직에서 목적지 결정에 실제로 쓰이고 있어서 삭제 보류하고 그대로 둠 |
| 확인 필요 | 삭제하려는 의도가 무엇이었는지, 대체할 로직이 있는지 확인 후 처리 필요 |
