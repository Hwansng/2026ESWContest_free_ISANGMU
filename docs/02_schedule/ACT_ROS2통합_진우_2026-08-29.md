## 0. 먼저 — 확인된 것 3가지

**① `arm_bridge`/`arm_controller`가 가정하는 하드웨어가 실물과 다르다.** 둘 다 "ARM ESP32 #2"가 서보를 구동하고 TCP(포트 5001)로 중계한다고 짜여 있는데, README 상시주의엔 "**ESP32는 서보 3핀 버스에 연결 금지. STS3215는 1선 반이중, 마스터는 RPi USB 어댑터 하나**"라고 돼 있다. 실제 검증된 ACT 파이프라인도 ESP32 없이 RPi/노트북이 USB로 서보 버스를 직접 잡는다. **ARM ESP32 #2는 존재하지 않는 것으로 결론냄** — RPi가 USB 직결로 간다.

**② ACT 정책은 "파지"만 하지 않는다.** 학습된 태스크가 "집기 → 이동 → 격리함에 넣기 → 뚜껑 닫기"를 한 에피소드로 묶여 있다(`rollout_act.ps1`과 동일 지시문, 30회 검증도 이 전체를 한 번에 실행해서 잰 것). 그래서 `arm_controller`의 별도 "놓기" 프리셋 이동(`OVERPACK_DRUM`/`HAZMAT_STORAGE`)은 ACT 뒤에 또 실행하면 안 된다 — 이미 끝난 동작 위에 엉뚱한 프리셋 이동이 덧씌워진다.

**③ 자동 성공/실패 판정이 없다.** 30회 검증 때도 사람이 영상 보고 성공/실패를 기록했다. 지금 구현한 `arm_act_node`도 "에피소드가 정상 종료됐는가"만 보고하지, 파지가 실제로 성공했는지는 모른다.

## 1. `arm_act_node.py` — 전체 교체

기존 `POLICY_PATHS = {..., None}` 더미 폴백을 걷어내고, 검증된 `tools/run_lerobot_record_patched.py`(조기종료 + 같은 프로세스 내 홈복귀 + 토크안전, 30회 실물 검증됨)를 **서브프로세스로 그대로 재사용**하는 방식으로 다시 짰다. 인프로세스로 다시 구현하지 않은 이유: 그 안전 로직(MAX_SAFE_DIFF, finally 토크해제, 조기종료 임계값)을 처음부터 다시 검증해야 하는 리스크를 피하기 위해서다.

```python
"""
ACT 정책으로 "파지 → 이동 → 격리함에 넣기 → 뚜껑 닫기" 전체를 실행하는 노드.

2026-08-29 전면 재작성 — 기존 POLICY_PATHS=None 더미 폴백을 걷어내고 실제
검증된 정책(local/hazardbot_red_yellow_act_v1, 30회 실물 검증 86.7%)을 돌린다.

🔴 왜 서브프로세스인가 — 인프로세스로 다시 짜지 않는다
    `tools/run_lerobot_record_patched.py` + `tools/go_home.py` 가 이미 실물로
    검증된 조기종료·홈복귀·토크안전(MAX_SAFE_DIFF, finally 토크해제) 로직을 갖고
    있다. 그걸 이 노드 안에 인프로세스로 다시 구현하면 그 안전 로직 전체를
    처음부터 다시 검증해야 한다 — 검증된 걸 서브프로세스로 그대로 불러 쓰는 게
    훨씬 안전하다. 부수 효과로 LeRobot/추론 쪽이 죽어도 이 ROS2 노드 자체는 산다.

🔴 이 정책은 "파지"만 하지 않는다
    태스크 지시문(`rollout_act.ps1` 과 동일) 자체가 "집기→이동→격리함에 넣기→
    뚜껑 닫기"를 한 에피소드로 묶어 학습됐다. 그래서 이 노드가 끝나면
    `arm_controller`의 별도 "놓기" 프리셋 이동은 **건너뛰어야 한다** —
    mission_orchestrator.py 의 GRIP→REPORT 직결(TRANSPORT 생략)이 그래서 필요하다.

🔴 자동 성공/실패 판정이 없다
    30회 검증 때도 사람이 영상을 보고 성공/실패를 판정했다(자동 그레이딩 없음).
    이 노드는 "에피소드가 정상 종료됐는가"만 `/arm/act_result` 로 보고한다.
    실제 파지 성공 여부는 여전히 사람이 판단해야 한다 — completed=True 를
    "파지 성공"으로 오해하지 말 것.

🔲 전제 — 실물로 확인 안 됨
    이 노드가 도는 RPi 5 에 LeRobot 환경·체크포인트 사본·서보 USB 직결이
    전부 갖춰져 있다고 가정하고 짰다. 노트북(RTX 4060)에서 나온 추론 속도가
    RPi 5(CPU)에서도 나올지는 검증된 적이 없다 — 처음 돌릴 때 반드시 옆에서
    지켜볼 것.
"""
import json
import subprocess
import threading
from pathlib import Path

import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class ArmActNode(Node):
    def __init__(self):
        super().__init__('arm_act_node')

        # ── 파라미터 — 코드 수정 없이 launch 인자/`ros2 param`으로 바꿀 수 있다 ──
        # 🔲 기본값은 전부 추정치다. RPi 의 실제 경로·포트로 launch 인자에서 덮어쓸 것.
        self.declare_parameter('project_root', str(Path.home() / 'HazardBot'))
        self.declare_parameter('python_path', 'python3')
        self.declare_parameter('policy_path',
                                str(Path.home() / 'act_checkpoint' / 'pretrained_model'))
        self.declare_parameter('robot_port', '/dev/ttyACM0')
        self.declare_parameter('dataset_root',
                                str(Path.home() / 'act_data' / 'eval_hazardbot_mission_v1'))
        self.declare_parameter('camera_index', 0)
        self.declare_parameter('camera_backend', 700)   # 🔲 Windows 값 그대로 둠 — RPi 는 V4L2 필요할 수 있음
        self.declare_parameter('episode_time_s', 20.0)
        self.declare_parameter('still_seconds', 0.5)
        self.declare_parameter('min_seconds', 8.0)
        self.declare_parameter('home_seconds', 3.0)
        self.declare_parameter('display_data', False)   # 헤드리스 RPi 기본값

        self._busy_lock = threading.Lock()
        self._busy = False

        self.create_subscription(String, '/arm/grip_request', self.grip_request_cb, 10)
        self.pub_result = self.create_publisher(String, '/arm/act_result', 10)

        self.get_logger().info('Arm ACT Node 시작함 (실물 정책 서브프로세스 방식)')

    # ════════════════════════════════════════════
    # mission_orchestrator 의 GRIP 진입 신호
    # ════════════════════════════════════════════
    def grip_request_cb(self, msg: String):
        with self._busy_lock:
            if self._busy:
                self.get_logger().warn('이미 ACT 에피소드 실행 중 — 이번 요청은 무시함')
                return
            self._busy = True
        threading.Thread(target=self._run_episode_guarded, daemon=True).start()

    def _run_episode_guarded(self):
        # 🔴 스레드 안에서 발생한 예외는 조용히 사라진다 — 반드시 여기서 잡는다
        try:
            self.run_episode()
        except Exception as e:
            self.get_logger().error(f'ACT 에피소드 실행 중 예외: {type(e).__name__}: {e}')
            self.publish_result(completed=False, error=f'{type(e).__name__}: {e}')
        finally:
            with self._busy_lock:
                self._busy = False

    # ════════════════════════════════════════════
    # 실제 롤아웃 — rollout_act.ps1 의 절차를 그대로 파이썬으로 옮긴 것
    # ════════════════════════════════════════════
    def run_episode(self):
        g = lambda name: self.get_parameter(name).value
        project_root = Path(g('project_root'))
        python_path = g('python_path')
        policy_path = g('policy_path')
        dataset_root = Path(g('dataset_root'))
        robot_port = g('robot_port')

        if not Path(policy_path).exists():
            self.get_logger().error(f'정책 체크포인트 없음: {policy_path} — 에피소드 실행 안 함')
            self.publish_result(completed=False, error='policy_path 없음')
            return

        # ① 실행 전 안전점검 — rollout_act.ps1 과 동일 순서(check_goal --fix 로
        #    194°급 순간이동 위험을 미리 잡는다). 이게 실패하면 절대 정책을 돌리지 않는다.
        goal_check = [python_path, str(project_root / 'tools' / 'check_goal.py'),
                      '--port', robot_port, '--fix']
        r = subprocess.run(goal_check, cwd=str(project_root))
        if r.returncode != 0:
            self.get_logger().error('check_goal --fix 실패 — 팔 자세 확인 필요, 에피소드 중단')
            self.publish_result(completed=False, error='check_goal 실패')
            return

        # ② 실제 롤아웃 — tools/run_lerobot_record_patched.py 그대로 재사용
        #    (조기종료 + 같은 프로세스 내 홈복귀 + finally 토크해제, 전부 검증된 로직)
        camera_cfg = (f"{{wrist: {{type: opencv, index_or_path: {g('camera_index')}, "
                       f"width: 640, height: 480, fps: 30, backend: {g('camera_backend')}}}}}")
        resume = self._dataset_has_episodes(dataset_root)
        task = 'Pick up the hazardous object, place it in the isolation bin, and close the lid.'
        args = [
            python_path, str(project_root / 'tools' / 'run_lerobot_record_patched.py'),
            f"--still-seconds={g('still_seconds')}",
            f"--min-seconds={g('min_seconds')}",
            f"--home-seconds={g('home_seconds')}",
            '--robot.type=so101_follower',
            f'--robot.port={robot_port}',
            '--robot.id=follower_arm',
            '--robot.use_degrees=false',
            f'--robot.cameras={camera_cfg}',
            f'--policy.path={policy_path}',
            # 🔴 sanity_check_dataset_name — policy.path 지정 시 repo_id 는 eval_ 로 시작해야 한다
            '--dataset.repo_id=local/eval_hazardbot_mission_v1',
            f'--dataset.root={dataset_root}',
            '--dataset.push_to_hub=false',
            '--dataset.streaming_encoding=false',
            f'--dataset.single_task={task}',
            '--dataset.num_episodes=1',
            f"--dataset.episode_time_s={g('episode_time_s')}",
            '--dataset.reset_time_s=0',
            '--dataset.fps=30',
            f"--display_data={'true' if g('display_data') else 'false'}",
        ]
        if resume:
            args.append('--resume=true')

        timeout_s = float(g('episode_time_s')) + float(g('home_seconds')) + 30.0  # 여유
        self.get_logger().info(f'ACT 에피소드 시작 — 최대 {timeout_s:.0f}초까지 기다림')
        try:
            r = subprocess.run(args, cwd=str(project_root), timeout=timeout_s)
        except subprocess.TimeoutExpired:
            self.get_logger().error('ACT 에피소드 타임아웃 — 팔 상태를 직접 확인할 것')
            self.publish_result(completed=False, error='timeout')
            return

        if r.returncode != 0:
            self.get_logger().error(f'ACT 에피소드 비정상 종료 (exit {r.returncode})')
            self.publish_result(completed=False, error=f'exit {r.returncode}')
            return

        self.get_logger().info('ACT 에피소드 정상 종료 — 파지/격리 성공 여부는 사람이 확인할 것')
        self.publish_result(completed=True)

    @staticmethod
    def _dataset_has_episodes(dataset_root: Path) -> bool:
        info_path = dataset_root / 'meta' / 'info.json'
        if not info_path.exists():
            return False
        try:
            return int(json.loads(info_path.read_text()).get('total_episodes', 0)) > 0
        except Exception:
            return False

    def publish_result(self, completed: bool, error: str | None = None):
        msg = String()
        msg.data = json.dumps({'completed': completed, 'error': error})
        self.pub_result.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    node = ArmActNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        if rclpy.ok():
            rclpy.shutdown()


if __name__ == '__main__':
    main()
```

**실행 전 RPi에서 채워야 하는 파라미터** (전부 launch 인자 또는 `ros2 param set`으로):

| 파라미터 | 기본값(추정) | 실제 값으로 바꿔야 하는 이유 |
|---|---|---|
| `project_root` | `~/HazardBot` | RPi의 실제 클론 경로 |
| `python_path` | `python3` | LeRobot 가상환경 안의 python이어야 함 |
| `policy_path` | `~/act_checkpoint/pretrained_model` | 학습 완료 체크포인트를 RPi로 복사한 실제 경로 |
| `robot_port` | `/dev/ttyACM0` | RPi에서 서보 버스가 잡히는 실제 포트(`ls /dev/ttyACM*`로 확인) |
| `camera_index`/`camera_backend` | `0`/`700` | `700`은 Windows(MSMF) 백엔드 값 — RPi는 V4L2 계열로 바꿔야 할 가능성 높음 |

### ② `act_result_cb` 신규 추가 (feedback_cb 위에)

```python
    # ════════════════════════════════════════════
    # ACT 에피소드 완료 콜백 — arm_act_node 가 발행 (2026-08-29 추가)
    # ════════════════════════════════════════════
    def act_result_cb(self, msg: String):
        if self.state != MissionState.GRIP:
            return
        try:
            data = json.loads(msg.data)
        except (json.JSONDecodeError, TypeError):
            data = {}

        self.grip_retry = 0
        if data.get('completed'):
            self.get_logger().info(
                'ACT 에피소드 완료 — REPORT 로 전이 '
                '(TRANSPORT/ISOLATE 는 ACT 가 한 에피소드 안에서 이미 처리함)'
            )
            self.transition(MissionState.REPORT)
            self.detected_color = None
            self.detected_angle = None
            self.transition(MissionState.PATROL)
        else:
            self.get_logger().error(
                f'ACT 에피소드 실패: {data.get("error")} — PATROL 로 복귀'
            )
            self.detected_color = None
            self.detected_angle = None
            self.transition(MissionState.PATROL)
```

## 3. 적용 순서

1. 위 패치를 GitHub `jinu-rpi5-restore`(또는 원하는 브랜치)에 반영
2. RPi에서 §1 표의 파라미터 5개를 실제 값으로 확인·설정
3. `arm_controller`/`arm_bridge`는 지우지 않았지만 ACT 경로에서는 이제 안 쓰임 — 남겨두는 이유는 §2-③,④ 코멘트 참고
4. 실물로 GRIP 1회 강제 트리거(`/debug/force_grip`)해서 `arm_act_node`가 실제로 서브프로세스를 띄우는지, `/arm/act_result`가 오는지, `mission_orchestrator`가 `PATROL`로 잘 돌아오는지 확인 — **이게 이 통합 전체에서 처음으로 실물 검증되는 지점**이라 옆에서 지켜볼 것
