# 🔴 오늘의 갈림길 — 바퀴 (도착 즉시 5분)

75mm 바퀴는 8/18~22 에 도착한다. **교체하면 차체가 5mm 오른다.**
`demo_set_build_plan.md` §7.1.1 이 이 상황을 이미 정확히 기술해 놓았다.

> 트레이는 **바닥**에 있고 팔은 **차체**에 붙어 있다. 차체가 20mm 덜 서면 용기는 바닥에서
> 안 움직였어도 **팔 기준으로는 20mm 어긋난다.**

바퀴 교체는 같은 일을 **반대 방향으로** 한다.

| 대상 | 바퀴 교체의 영향 |
|---|---|
| 카메라 ↔ 팔 베이스 상대 포즈 | ✅ **안 변한다** (프론트·팔 모두 섀시) — §6 최우선 원칙은 지켜진다 |
| 팔 ↔ 바닥 물체 | 🔴 **5mm 어긋난다** → 적색 프리셋 z 상수 무효 |
| 프론트 화각 배경 | 🔴 **이동한다** → 황색 수집 데이터 무효 |
| 라인센서 갭 | 🔴 **5mm 벌어진다** → 감도 재조절 |

### 판정 방법

로봇을 옆으로 눕히고 **바닥면의 긁힌 자국이 어디 있는지** 본다. 5분이면 된다.

```
국소(케이블 · 볼트머리 · 브래킷 모서리)
  → 오늘 제거 → 🔵 바퀴 교체 취소 → 수집 즉시 착수 가능

바닥판 전체가 닿는다
  → 8/22 까지 대기 → 수집 8/22~ → 촬영 일정 재조정
```

> **「차체가 살짝 끌린다」 하나 때문에 ACT 일정 전체가 일주일 밀리는 구조다.**
> 그래서 이 판정이 오늘 다른 무엇보다 앞선다.

# 6단계 — 카메라 3대 최종 고정 → `wrist_roll` 범위

### 6.1 3대 전부 최종 위치에 볼트 고정

`로봇암_카메라_구성정리.md` §7.2 — **「학습에 안 쓴다」 ≠ 「학습 때 안 달아도 된다」.**
NoIR 은 ACT 입력이 아니지만 **본체·브래킷·리본 케이블이 프론트 화각에 들어온다.**
나중에 달면 추론 시점 프론트 이미지에 학습 때 없던 물체가 나타난다 → 도메인 갭.

**프론트 마운트 절차** (§9):

1. 팔을 섀시에 올린 상태로 후보 위치에 카메라를 **손·클램프로 임시로** 대본다
2. 팔을 **접근 시작 자세 → 파지 자세**로 텔레옵하며 라이브 영상 확인
3. 전 궤적이 보이고 · 파지 순간 물체가 안 가려지고 · 팔과 안 부딪히는지
4. 만족하면 **볼트로 영구 고정**

기준: 팔 정면에서 **30~45° 옆 대각선**, 작업공간보다 약간 높은 곳에서 **아래로 15~30°**.

### 6.2 프론트 화각 안의 모든 것을 같이 확정한다

- [ ] **WS2812B 점등 시나리오** — 수집 때 꺼져 있으면 데모와 조명이 불일치한다
- [ ] 섀시 배선 · ESP32 보드 · 부저 · 센서 브래킷 부착 완료
- [ ] 소품 최종 배치 (안전콘 · 표지판 · 드럼통 · 바닥 테이프)
- [ ] **카메라 AWB · 자동노출 고정** — 프레임마다 튀면 같은 물체 색이 흔들린다
- [ ] `python tools/check_cameras.py --list` — 손목/프론트 인덱스 확인 (내장 웹캠이 0 을 차지)

### 6.3 🔴 `wrist_roll` 안전 범위 — 빠뜨리면 수집이 통째로 날아간다

> 손목 카메라 **미장착 상태**에서도 팔로워 `wrist_roll`(id5)이 4077 까지 돌아가 배선에 막혀
> `[RxPacketError] Overload error!` 가 걸렸다. **카메라 케이블이 추가되면 더 좁아진다.**

**절차** (`로봇암_카메라_구성정리.md` §10.2-3):

1. 손목 카메라를 장착하고 케이블에 **여유 루프**를 주어 라우팅
2. `wrist_roll` 을 손으로 양방향 회전 → **배선이 버티는 실제 범위 측정**
   (`python tools/measure_leader_range.py --port COM3`)
3. 그 범위를 **서보 `Min/Max_Position_Limit` 과 캘리브레이션 JSON 양쪽에** 반영
   — `is_calibrated()` 가 둘을 대조하므로 하나만 고치면 재캘리브레이션 프롬프트가 뜬다

> 🔴 **반드시 수집 전에 끝낸다.** 수집 중 과부하는 그 에피소드 폐기이고,
> **수집 후 캘리브레이션 변경은 이전 데이터 전량 무효**다.

# 7단계 — 정지 산포 실측

**팔이 장착된 상태여야 한다** — 무게가 제동거리를 바꾼다.
그리고 라인센서 감도를 **실제 주행 높이 · 촬영 조명**에서 잡은 다음이어야 한다.

### 여기 걸려 있는 것이 셋이다

| 종속 항목 | 근거 |
|---|---|
| **파지물·격리함 최종 배치** | §5.5 — *"pick·place 가 모두 한 정지점의 팔 도달 범위 안. 산포 실측 이후에 함께 확정"* |
| **비전 오프셋 보정 커버 범위** | 프리셋이 상대할 오차의 크기 |
| **ACT 수집 범위** | 8/6 — *"산포 실측 → 수집 범위 확정이 먼저"* |

### 측정

정지점 1·2 에서 각 **10회**, 매회 **x · y · θ** 기록.

| 기호 | 측정값 |
|---|---|
| **x** | 진행 방향 전후 오차 (mm) |
| **y** | 좌우 오차 (mm) |
| **θ** | 차체 방위각 (도) |

- 🔴 **정지점 1(적색)의 θ 를 우선.** 정방향 배치라 θ 흡수 여유가 좁다. **3° 초과 시 조치 필요**
- 출발점을 매번 동일하게 (접근 구간 길이가 다르면 속도가 다르다)
- 차체 기준점을 하나 정하고 **매번 같은 점**으로 잰다
- 각각 **최댓값 − 최솟값**을 산포로 기록하고, 넘길 때 **여유 30% 를 더한다**

> 완전한 측정은 배터리 3구간 × 2정지점 × 10회 = 60주행이다. **오늘은 완충 구간만**으로 충분하다.
> ±8cm 수준으로 크게 나오면 대책 순서는 ① APPROACH 속도 인하 ② 감속 마커 3단화 ③ 엔코더 다.

|---|---|
| 포획 범위 (경사면 폭) | 한쪽에 **20~30mm** |
| **최종 정밀도** (안지름) | 용기 지름 **+ 2~4mm** ← 이게 프리셋이 상대하는 오차 |
| 벽 높이 | 용기 높이의 **1/4~1/3** (그리퍼가 옆에서 들어갈 공간) |
| 경사각 | **45° 부근**에서 시작해 실물로 조정 |

> 🔴 **용기를 떨어뜨리듯 넣었다 빼기를 10회 반복해 매번 같은 자리에 앉는지 확인한다.**
> **손으로 밀어 맞추면 안 된다** — 자기 정렬이 안 되는 치구는 치구가 아니다.

🔵 **황색에는 만들지 않는다.** 종이컵은 변형체라 트레이에 넣는 행위가 형상을 바꾼다.
그게 황색을 ACT 로 처리하는 이유 자체다.

### 8.3 🔴 놓치기 쉬운 것 셋

- **종이컵 동일 제품을 넉넉히 확보한다.** 수집 50~100 에피소드 동안 컵은 찌그러진다 —
  **소모품이다.** 중간에 다른 제품이 섞이면 정책이 실패한다 (§7.4)
- **GHS/NFPA 라벨은 수집 전에 붙어 있어야 한다.** 수집 후에 붙이면 화면이 바뀐다
- **두 파지 대상을 한 화면에 두지 않는다.** 다른 대상이 손목 카메라에 들어오면
  학습 때와 입력이 달라져 정책이 실패한다

# 9단계 — 적색 프리셋 + 🔴 VGR 인수인계

### 🔴 프리셋만으로는 안 잡힌다

§7.1.1 의 8/07 정정이 핵심이다.

> **이 트레이는 정지 산포를 흡수하지 않는다.**
> 트레이는 바닥에 있고 팔은 차체에 붙어 있다. 산포는 **비전 오프셋 보정**이 흡수한다.

비전 오프셋 보정(VGR)은 **진우 신규 작업**이다. 따라서 오늘 적색 작업의 목표는
*"프리셋으로 잡히나?"* 가 아니라 아래 셋이다.

1. **프리셋 포즈 티칭** — 트레이 정위치 기준
2. **차체를 일부러 x·y 로 어긋나게 세워 오프셋이 얼마나 필요한지 실측**
3. 🔴 **진우에게 이관** — 프론트 카메라 **픽셀 좌표 → 팔 베이스 x·y(mm)** 변환

> 체커보드 없이 된다. **트레이를 알려진 위치 4곳에 놓고 대응점 4쌍**만 잡으면
> 호모그래피가 나온다. 팔과 카메라가 같은 섀시에 있으므로 관계가 고정이다.
> **셋이 모인 날에만 되는 작업이다.**

🔴 바퀴를 교체하면 이 프리셋의 **z 상수를 다시 잡는다.**

# 10단계 — 황색 수집 (게이트 통과 시에만)

### 착수 게이트

| 게이트 | 상태 |
|---|---|
| 바퀴 결정 확정 | 🔲 0단계 |
| 촬영 조명 확정 | 🔲 1단계 |
| 카메라 3대 최종 고정 | 🔲 6.1 |
| `wrist_roll` 안전 범위 | 🔲 6.3 |
| 정지 산포 실측 | 🔲 7단계 |
| 소품·라벨 최종 배치 | 🔲 8단계 |
| 종이컵 여유분 | 🔲 8.3 |

### 게이트를 못 넘으면 — **버릴 셈 치고 10 에피소드**

카메라 인덱스 · 인코딩 시간 · 에피소드 길이 · 시리얼 글리치를 한 번에 검증하는 값이 있다.
🔴 **단, 「버린다」고 먼저 선언하고 찍는다.** 애매하게 남기면 나중에 *"이거 쓸까?"* 가 된다.

### 명령 플래그 — 기본값이 전부 위험하다

```
--dataset.push_to_hub=false                          기본값이 HuggingFace 공개 업로드
--robot.use_degrees=false --teleop.use_degrees=false  기본 DEGREES 는 손목 폭주를 일으켰다
--dataset.streaming_encoding=false                    켜면 sync_read 타임아웃으로 세션이 죽는다
```

- **10 에피소드씩 나눠 녹화한다.** `sync_read` 는 재시도가 없어 글리치 한 번에 세션 전체가 죽는다
- 수집 10 에피소드 시점에 **학습 벤치마크 재실행**하여 `data_s` 확인
