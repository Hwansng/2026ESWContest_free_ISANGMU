# 1. 오늘 바뀐 전제 두 가지

## 1.1 진우 부재 — ④ 색분리 판정은 미루고, 수집은 간다

**근거는 `로봇암_카메라_구성정리.md` §7.3 이 두 문제를 이미 분리해 놓은 것이다.**

| | |
|---|---|
| ACT 입력 | **손목 SO-ARM USB = 일반 컬러 카메라.** NoIR 이 아니다 |
| NoIR 의 역할 | 진우의 감지·판정 노드. **ACT 는 분류가 끝난 뒤 「잡아라」만 받는다** |
| 문서 표현 | *"색 리스크는 학습 쪽이 아니라 **NoIR 쪽에 몰려 있다**"* |

**실패 시 대책 5개 중 4개가 손목 뷰를 건드리지 않는다.**

| # | 대책 | 손목 뷰 영향 |
|---|---|---|
| 1 | LED 조명 | 🔴 **유일한 연결 고리** — 아래 참조 |
| 2 | AWB · 자동노출 고정 | 없음 (NoIR 쪽 설정) |
| 3 | 외장 IR-cut 필터 | 없음 (NoIR 에 부착) |
| 4 | 형상 특징 병용 (면적·채움률·원형도) | 없음 (코드) |
| 5 | Innomaker 정색 카메라로 교체 | 없음 (섀시 감지 카메라) |

> 🔴 **오늘의 결정 — 조명은 오늘 굳히고 다시 건드리지 않는다.**
> 색분리가 나중에 실패해도 **대책 2~5번으로만 푼다.** 조명을 다시 만지면 그 순간
> 수집분이 전량 무효다. 그러므로 오늘 조명은 **NoIR 에 유리한 쪽으로 넉넉하게** 잡는다 —
> LED · IR 성분 적게 · 밝기 여유.

> 🔴 **NoIR 실물이 진우에게 있어 오늘은 캡처조차 못 한다.** ④-b 는 통째로 복귀일 대기다.
> 판정표 4행 중 3행이 여기 걸려 있으므로 **복귀일 확정과 대책 리드타임 역산**이 오늘의 몫이다 (§3 2단계).
> 🔵 손목 카메라(④-a)는 노트북에 있으므로 **오늘 닫는다.**

## 1.2 바퀴 75mm 도착 — 순서가 강제된다

| 단계 | 내용 |
|---|---|
| 1 | 🔴 **12mm 헥스 허브 보어 치수 확인 (5분 판정)** — 이것부터. 안 맞으면 교체 자체가 무산이고, 그 경우 **기존 바퀴로 오늘 산포를 재고** 교체 후 재측정한다 |
| 2 | 교체하면 **차체가 5mm 오른다** → 라인센서 갭 5mm 벌어짐 → **감도 재조절 필수** |
| 3 | 감도가 바뀌면 제동거리가 바뀐다 → **산포는 교체·감도조절 이후에** |
| 4 | 게이트 ② 차체 통과 10/10 도 **최종 바퀴 상태로** 해야 의미가 있다 |

🔵 **ACT 데이터 자체는 바퀴 교체에 강하다** (손목 뷰는 그리퍼↔물체 상대 관계를 본다).
그러나 그건 *이미 찍은 것이 살아남는다*는 뜻이지 **순서를 뒤집어도 된다는 뜻이 아니다** —
팔 베이스 높이가 최종이어야 물체까지의 거리 분포가 실제 주행과 맞는다.

🔲 **VGR 호모그래피 재측정**은 바퀴 5mm 때문에 필요하지만 **진우 몫**이다. 수집에는 영향 없다.

# 2. 실행 순서

```
  아침  0단계  바퀴 5분 판정 → (보어 OK면) 교체 → 라인센서 감도 재조절
        1단계  🔴 조명 고정 · 마킹 · 설정값 기록        모든 값이 여기 종속
        2단계  게이트 ④ — 손목만 오늘 완결. 🔴 NoIR 은 실물이 진우에게 있어 전면 대기

  낮    3단계  게이트 ① 골무 → 개구 실측
              게이트 ②-1 뚜껑 5조건
              게이트 ② 차체 통과 10/10 + 그리퍼 진입
              게이트 ③ 캘리브레이션 재조정 + 연쇄 4건
              게이트 ⑤ 정지 산포 ×10 (θ 우선)

  저녁  4단계  🔴 수집 프로토콜 ①~⑦ 확정 (30분, 종이에 적는다)
        5단계  데이터 수집 — 10 에피소드씩
        6단계  학습 착수 (15.6h — 다른 작업 없는 밤에)
```

🔴 **3단계 안의 순서를 바꾸지 말 것.** 그리퍼·물체·조명·근경 배경이 바뀌면 **이미 수집한 데이터가 무효**다.

# 3. 단계별 체크리스트

## 0단계 — 바퀴 (아침 제일 먼저)

- [ ] 🔴 **12mm 헥스 허브 보어 치수 확인** — 5mm 이상이면 4mm 보어를 주문에 담아야 한다
- [ ] 보어 OK → 바퀴 교체 (차체 +5mm)
- [ ] 🔴 **라인센서 감도 재조절** — 갭이 5mm 벌어졌다. 실제 주행 높이 + **촬영 조명 아래서**
- [ ] 보어 NG → 기존 바퀴 유지. 🔲 **오늘 잰 산포는 교체 후 재측정 대상**이라고 이 문서에 적어둔다

> ⚠ 감도 재조절은 **1단계 조명이 켜진 상태**에서 해야 한다. 순서가 겹치면 조명을 먼저 켜고 온다.

## 1단계 — 조명 고정 (다른 어떤 측정보다 먼저)

- [ ] 🔴 **LED 인가** — 백열·할로겐은 NoIR 색 밀림과 KY-026 오검출을 동시에 키운다
- [ ] 위치 · 높이 · 각도 **바닥 마킹**
- [ ] 밝기 · 색온도 **설정값을 숫자로 기록** + 조명 기구 **모델명** → §9 기입란
      🔴 **NoIR 이 오늘 없으므로 이 기록이 게이트 ④-b 를 나중에 살리는 유일한 수단이다.**
      "나중에 대충 비슷하게"가 아니라 **숫자로 복원 가능한 수준**이어야 한다
- [ ] 🔴 **수집 조명 = 촬영 조명.** 오늘 굳힌 상태를 **8/28 촬영까지** 유지한다
- [ ] 손목 카메라 **AWB · 자동노출 고정** — 1뷰라 이 한 대의 노출이 전부다

## 2단계 — 게이트 ④ 색 분리

🔴 **게이트 ④ 는 카메라 2대에서 각각이다** (`demo_video_scenario.md` §957 · `demo_set_build_plan.md` §1517).
🔵 **손목 쪽은 오늘 혼자 닫을 수 있다. NoIR 쪽만 진우 대기다.**

**판정 기준** — 적색 Hue 범위와 황색 Hue 범위 **사이에 빈 구간이 있어야 한다.** 겹치면 실패.

### ④-a 손목 카메라 (🔵 오늘 완결 가능)

- [ ] 조명 켠 상태에서 `& $py tools\check_cameras.py --list` 로 적색 용기 · 황색 종이컵 캡처
- [ ] `outputs\camera_check\*.png` 에서 두 물체의 Hue 분포 확인 → **빈 구간 있는가**
- [ ] 🔵 정색 카메라라 통과가 거의 자명하다. **그래도 숫자로 남긴다** — 나중에 근거가 된다

### ④-b NoIR (🔴 오늘 불가 — 캡처도 못 한다)

🔴 **NoIR 실물이 진우에게 있다.** 섀시 마운트가 아직 미확정이라 카메라가 로봇에 없다
(`담당정리_진우_2026-08-18.md` NoIR 섀시 마운트 · `로봇암_카메라_구성정리.md` §11 남은 결정).
→ **캡처도 판정도 전부 진우 복귀일로 넘어간다.**

- [ ] 🔴 **진우 복귀일을 오늘 확정한다** — 아래 역산이 여기서 나온다
- [ ] 🟠 **진우가 적색 용기나 노란 종이컵을 가지고 있다면 원격 사전 스크리닝을 요청한다**
      아무 LED 조명이라도 좋다. **거기서도 두 범위가 겹치면 거의 확실히 실패**다 —
      NoIR 의 IR 감도 자체는 조명과 무관한 카메라 특성이라 **실패 신호는 조기에 나온다.**
      🔴 다만 **통과 신호는 못 믿는다.** 최종 판정은 세트 조명에서 다시 해야 한다
- [ ] 🔲 실패 시 대책은 **2~5번으로만.** 조명은 재조정 대상이 아니다 (§1.1 결정)

**🔴 역산 — 대책에 리드타임이 있다**

```
  진우 복귀일 → ④-b 판정(당일 가능) → 실패 시 대책
                                        3번 IR-cut 필터  = 조달 리드타임
                                        5번 Innomaker 교체 = 마운트 작업
                                      → 🔴 촬영 8/24~28 전에 끝나야 한다
```

> 🟠 **복귀일이 8/23 이후면 대책을 실행할 날이 사실상 없다.**
> 그 경우 판정을 기다리지 말고 **대책 4번(형상 특징 병용)을 기본값으로 깔고 가는 결정**을
> 오늘 내리는 편이 낫다 — 코드라 조달이 없고, 색이 애매해도 판정이 선다 (v5 §5.8).

> 🔴 **그래서 오늘 §1단계 조명 마킹의 성격이 바뀌었다.**
> 단순 기록이 아니라 **④-b 를 나중에 살리는 유일한 수단**이다. 진우가 오는 날 오늘 조명을
> 그대로 재현하지 못하면 그날 찍는 캡처도 무효다. **숫자로 복원 가능한 수준**으로 남길 것 —
> 위치·높이·각도 바닥 마킹 + 밝기·색온도 설정값 + 조명 기구 모델명.

## 3단계 — 수집 게이트

### ① 그리퍼 골무

- [ ] 골무 부착 — 목적은 완충이 아니라 **파지력**(테이퍼 쐐기 미끄러짐)
- [ ] 🔴 **골무 낀 상태로 그리퍼 최대 개구 실측** → 기입란에 기록
- [ ] 🔴 **수집 전에 끼운다.** 나중에 끼우면 두께만큼 개구가 줄어 **적색 데이터까지 무효**

### ②-1 격리함 뚜껑 — 성립 조건 5개 (색칠은 그중 하나)

- [ ] **안쪽 면 대비색** — 🔵 **도료보다 색지·색테이프.** 건조 시간이 수집을 막는다
- [ ] **백스톱** — 열림 각도가 매번 같아야 한다. 흔들리면 접촉 지점을 못 배운다
- [ ] **높이** — 물체가 어떤 자세로 앉아도 뚜껑 아래 (🔲 격리함 내경 높이 미확정 항목)
- [ ] **경로** — 열린 뚜껑이 투입 동선을 막지 않는다
- [ ] **경첩 내구성** — 수백 사이클. 🔴 종이테이프 안 됨. 천 테이프 또는 소형 경첩

> 🔴 뚜껑은 **「닫는다」가 아니라 「넘어뜨린다」** — 수직을 조금 넘겨 손을 떼면 끝점 하드스톱이 사라진다.
> 🔵 **왜 대비색인가** — 손목 1뷰로는 「놓은 직후 빈 그리퍼」와 「닫은 직후 빈 그리퍼」가 거의 같아 보인다.
> 안쪽 색이 열림/닫힘을 **픽셀 수준에서 자명**하게 만든다.

### ⑤ 정지 산포 ×10

- [ ] 바닥에 **기준선** + 자·모눈종이. 차체 기준점 하나 정하고 **매번 같은 점**
- [ ] **정지점 1** 10회 → x · y · θ 기록. 🔴 **θ 우선** (적색은 정방향 배치라 θ 흡수 여유가 좁다)
- [ ] **정지점 2** 10회 → 동일
- [ ] 각각 **최댓값 − 최솟값**을 산포로 기록
- [ ] 🔲 여건이 되면 배터리 **완충 / 중간 / 하한** 으로 나눠 측정 (촬영 당일 잔량을 고를 수 없다)

| x·y 산포 | 판정 | 조치 |
|---|---|---|
| ±3cm 이하 | 양호 | 그 범위로 수집 |
| ±3~8cm | 경계 | APPROACH 속도를 낮추고 재측정 |
| ±8cm 초과 | 과다 | 감속 마커를 한 줄 더 앞에 → 3단 감속 → 재측정 |

**θ 는 3° 이하면 무시**하고 물체 각도 변화로 흡수한다. 넘으면 ① APPROACH 감속 → ② 그래도 크면
**적색 수집에 각도 변동을 넣는다**(정방향 배치 결정을 되돌린다).

> 🔵 **수집 때 매번 주행시킬 필요는 없다.** 로봇을 공칭 정지 위치에 세워두고
> **물체를 측정 범위 안에서 옮기는 것으로 등가**다 (x·y 한정).

# 4. 🔴 수집 프로토콜 ①~⑦ — 오늘의 가장 큰 구멍

**v5 §6 에서 W2 마감이었는데 ② 하나만 닫혀 있다.** 게이트를 다 통과해도 이게 백지면
수집 도중에 규칙이 흔들려 데이터셋이 오염된다. **수집 시작 전에 적고, 적은 대로 지킨다.**

| # | 항목 | 결정 | 비고 |
|---|---|---|---|
| ① | 에피소드 **시작·종료 지점** | 🔲 | 홈 자세에서 시작? 어디서 끊나? 🔴 **녹화는 뚜껑 닫기까지 전부** |
| ② | **ACT 담당 구간** | ✅ **접근·파지·들어올리기 = ACT / 놓기·뚜껑 밀기 = 프리셋** | 격리함이 고정이라 변하는 게 없다 |
| ③ | **물체 배치 범위** | 🔲 | 🔴 **산식: 의도 변동 + 실측 산포 × 1.3.** ⑤ 의 소비처다 |
| ④ | **실패 에피소드 처리** | 🔲 | 남길지 버릴지. 섞으면 정책이 실패 궤적도 모방한다 |
| ⑤ | **조작 속도·리듬** | 🔲 | 매번 다르면 CVAE 다중성이 커져 수렴이 늦어진다 |
| ⑥ | **`episode_time_s`** | 🔲 | ②·⑤ 확정 후 역산. 뚜껑까지면 **+3~4초** |
| ⑦ | **조작 인원** | 🔲 | 🔵 **1인 고정 권장.** 번갈아 조작하면 시연 스타일이 섞인다 |

> 🔵 **학습 범위 A/B 선택은 오늘 하지 않아도 된다.**
> A = 전체(파지→격리→뚜껑) 먼저 / B = 파지까지만 잘라내기.
> 🔴 **오늘 판단할 일은 하나 — 녹화를 빠뜨리지 않는 것.**
> 잘라내는 건 스크립트 작업이지만 **안 찍은 건 전량 재수집**이다.

# 5. 수집 실행

## 5.1 녹화 직전 확인 — 매번 틀리는 것들

- [ ] 🔴 **카메라 인덱스 확인** — `& $py tools\check_cameras.py --list` → `outputs\camera_check\*.png` 를 **눈으로** 본다

- [ ] 🔴 `--dataset.push_to_hub=false` — 기본값이 **HuggingFace 업로드**다
- [ ] 🔴 `--robot.use_degrees=false --teleop.use_degrees=false`
- [ ] `streaming_encoding` **켜지 말 것** — 4초 만에 세션이 죽은 이력. 불안정하면
      `--dataset.num_image_writer_threads_per_camera` 를 4 → 2
- [ ] 🔴 **10 에피소드씩 나눠 녹화** — 한 번에 돌리다 90번째에서 끊기면 그때까지가 날아간다
- [ ] 물체에 **위험 표식 부착 완료** (🔴 실제 내용물 없는 모형에 임의 GHS 그림문자 금지)
- [ ] 종이컵 **동일 제품 여유분** 확보
- [ ] 🔴 **두 파지 대상을 한 화면에 두지 않는다** — 다른 대상이 손목 뷰에 들어오면 입력이 달라진다
- [ ] 디스크 여유 확인 (3대 기준 10~20GB → 🟠 1뷰라 **4~7GB 추정**)
