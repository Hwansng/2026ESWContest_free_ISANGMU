## 1. ENV 보드 배선 정본 (강희)

### 1.1 전원

| 레일 | 공급원 | 부하 |
|---|---|---|
| **5V_SENSOR** | 🔴 **XL4015 #B 출력에서 별도 한 쌍** | MQ-135 VCC, MQ-2 VCC **만** |
| **3V3** | ESP32 3V3 | KY-026 VCC, 부저 VCC |
| **ADC GND** | ESP32 GND | 센서 GND, 분압 하단저항, 부저 GND |
| **히터 GND** | 🔴 **벅 GND 직결** | MQ 히터 리턴 — ADC GND와는 **스타포인트에서만** 만난다 |

**🔴 MQ VCC를 ESP32 5V/VIN에서 뽑지 않는다.** `만능기판_이전_가이드.md` §4.5가 금지한 데이지체인이다.

- MQ 히터 합산 **상시 ~330mA** (135:150 + 2:180). ESP32 VIN 경유 시 USB 시험에서 250+330 = **580mA**가
  devkit 폴리퓨즈(통상 500mA)와 노트북 USB 포트를 통과한다 → 브라운아웃·리셋
- 히터 리턴이 ADC GND와 같은 레일이면 **MQ를 읽는 그 자리에 히터 전류가 그라운드 바운스를 얹는다**

> §4.5 원문: *"ENV 보드는 XL4015 **출력 단자에서 별도 한 쌍**을 뽑는다. **데이지체인 금지** —
> MQ 히터 상시 300mA 가 DRIVE 쪽 5V 를 흔든다."*

### 1.2 신호

| 센서 | 신호 | 핀 | 비고 |
|---|---|---|---|
| MQ-135 | AO → 분압 | **G34** | 입력 전용 · ADC1_CH6 |
| MQ-2 | AO → 분압 | **G35** | 입력 전용 · ADC1_CH7 · **V10 코드 확인 완료 (8/14)** |
| KY-026 | DO | **G27** | 🔴 **LOW active** (화염 감지 시 LOW) |
| 능동 부저 | I/O | **G26** | 3핀 모듈 직결 |

### 1.3 MQ 분압 — 10k / 10k

```
MQ-135 AO ──[10k]──┬── G34 ──┐
                   │         └── 0.1µF ── GND   (있으면)
                  [10k]
                   │
                  GND

MQ-2   AO ──[10k]──┬── G35 ──┐
                   │         └── 0.1µF ── GND   (있으면)
                  [10k]
                   │
                  GND
```

| | ADC 최대 | 판정 |
|---|---|---|
| 10k / **20k** | 3.33V | 🔴 3.3V 초과 · 상단 포화 — **금지** |
| 10k / **15k** | 3.00V | ⚠ 상단 22%가 ADC 비선형 구간 (15kΩ 재고 없음) |
| **10k / 10k** | **2.50V** | ✅ **채택** |
| 20k / 20k | 2.50V | ✅ 차선 — 10kΩ이 모자랄 때만 |

**채택 근거**

- ESP32 ADC1(11dB)의 선형 구간은 **150~2450mV**. 2.50V는 사실상 이 안에 들어온다.
  3.00V·3.33V는 상단이 휘거나 잘려서 **가스 농도가 올라가도 값이 안 올라가는 구간**이 생긴다 —
  촬영에서 가스를 뿌리는 장면이 정확히 그 구간이다
- 강희 배선 정본 안전규칙 9: *"G34와 G33의 ADC 노드에서 **3.3V가 넘으면 즉시 전원을 끈다**."*
  10k/20k(3.33V)는 **설계상 이 중단 조건을 스스로 위반한다**
- 10k/10k의 분압기 출력 임피던스 = **5kΩ**으로 Espressif 권고(ADC 소스 임피던스 ≤10kΩ) 안쪽.
  20k/20k는 10kΩ으로 경계선이라, 이쪽을 택할 경우 **0.1µF을 반드시 단다**

> 🔴 **임계값은 전량 재측정한다.** 분압을 새로 다는 순간 v9 임계는 무효다 (`센서_지도.md` §2).
> 촬영 조명·환경에서 다시 잡는다. MQ는 촬영 전날부터 통전해 드리프트를 줄인다.

### 1.4 능동 부저 (3핀 모듈)

| 핀 | 연결 |
|---|---|
| VCC | **ESP32 3V3** |
| GND | ADC GND |
| I/O (S) | **G26** |

- 모듈에 구동단이 들어 있으므로 **트랜지스터 불필요**
- **VCC는 3.3V로 한다.** 5V로 주면 일부 저가 모듈이 I/O로 5V를 되밀어 GPIO를 때린다.
  소리가 부족하면 그때 5V로 올리되 **I/O 핀 전압을 멀티미터로 확인한 뒤** 확정한다
- 소비 ~30mA → AMS1117에서 51mW. 무시 가능

### 1.5 연결하지 않는 것

| 항목 | 사유 |
|---|---|
| MQ-135 DO · MQ-2 DO | 아날로그만 사용 |
| KY-026 AO | 디지털만 사용 |
| **VL53L1X 일체** | 🔴 **DRIVE로 이관** (§4-①) |
| **WS2812B 일체** | 🔴 **미사용 확정** (§4-④) |
| G33 | 여유. 라벨만 남긴다 |

### 2.1 전원

| 레일 | 공급원 | 부하 |
|---|---|---|
| **5V** | XL4015 #B → **SS34** | ESP32 VIN **한 곳만** |
| **3V3** | ESP32 3V3 | TB6612 VCC, 라인센서 VCC, `J_TOF` 1번 핀 |
| **로직 GND** | ESP32 GND | TB6612 로직 GND(1개), 라인센서 GND, 커넥터 2번 핀, **배터리 분압 하단**, 12V(−) 스타포인트로 가는 가는 선 1가닥 |
| **전력 GND** | 12V(−) 터미널 | TB6612 GND 2개(VM·모터출력 줄, 각각 직결·데이지체인 금지), 470µF(−), XL4015 GND — **굵은 선** |
| **12V(+)** | 12V(+) 터미널 | TB6612 VM, 470µF(+), 배터리 분압 상단 — **굵은 선** |

### 2.2 신호 — ✅ `esp32_line_pid.ino`와 대조 완료

|---|---|---|---|
| PWMA | **G25** | S1 | **G13** |
| AIN1 | **G26** | S2 | **G18** |
| AIN2 | **G27** | S3 | **G19** |
| PWMB | **G14** | S4 | **G23** |

🔴 **라인센서 VCC는 3V3 전용.** 5V를 주면 출력도 5V가 되어 ESP32 GPIO가 손상된다 (`README.md` §1).

### 2.3 추가 부품 5건

#### ① STBY 풀다운 10kΩ — 필수

```
G4 ──┬── TB6612 STBY
    [10k]
     │
    GND
```

ESP32는 리셋 직후 GPIO가 **입력(하이임피던스)**이다. 펌웨어가 `pinMode(OUTPUT)`을 실행할 때까지
**수백 ms 동안 G4가 뜨고**, TB6612 STBY에는 내부 풀다운이 없다. STBY가 뜬 채 AIN/BIN도 뜨면
드라이버가 활성 + 입력 불정 → **모터가 튄다.** 촬영 때는 로봇을 바닥에 놓고 전원을 켠다.

🔵 **STBY 하나만 잡으면 IN 4개는 안 잡아도 된다** — STBY=LOW면 출력이 Hi-Z다. 저항 1개로 끝.

> 강희 PDF 검사 30번이 *"TB6612FNG STBY 신호가 LOW인지 확인"*을 요구한다. 그 LOW를 보장하는 부품이 이것이다.

#### ② 배터리 분압 40k / 10k = ×5.0 → G39 — 필수

```
12V(+) ──[20k]──[20k]──┬── G39 ──┐              ← 메인 스위치 후단에서
                       │         └── 0.1µF ── GND (있으면)
                     [10k]
                       │
                     로직 GND
```

| 배터리 상태 | 실제 | ADC |
|---|---|---|
| 만충 | 12.6V | **2.52V** |
| 공칭 | 11.1V | 2.22V |
| cutoff | 9.9V | 1.98V |

사용 구간 **1.98~2.52V**가 ADC 선형 구간에 통째로 들어온다. 종전 33k/10k(×4.3)는 만충에서 2.93V로
비선형 구간에 걸쳤다. 계수가 정확히 **5.0**이라 코드도 깔끔하다.

- 🔴 **하단 저항은 로직 GND에 붙인다.** 전력 GND에 붙이면 모터 전류에 의한 GND 강하가 측정에 섞인다
- 🔴 **메인 스위치 후단에서 뽑는다.** 전단이면 스위치 OFF에도 0.25mA가 상시 흘러 팩을 서서히 방전시킨다
- 멀티미터로 실측 보정. 보상 계수는 0.8~1.5로 클램프

**왜 필수인가** — 이건 곁가지가 아니라 **엔코더를 두 번 기각한 근거 그 자체**다.

> `센서_지도.md` §5.1: *"실익이 속도 일정성 하나인데, 그 원인의 대부분(배터리 강하)은
> **전압 피드포워드가 이미 처리**하고…"*

3S는 12.6V→9.9V까지 쓴다. **같은 듀티로 속도가 21% 변한다.** 그리고 ACT에 직접 걸린다 —
접근 속도가 배터리 잔량에 따라 변하면 **정지 산포가 회차마다 달라진다.** 학습은 만충으로,
촬영은 반쯤 쓴 팩으로 하면 그대로 도메인 시프트다. 과방전 감시(cutoff 9.9V)도 겸한다.

#### ③ SS34 쇼트키 — 필수

```
XL4015 5V ──>|── ESP32 VIN
              SS34
```

USB 역급전 차단. **D-9에 펌웨어를 고치며 USB 꽂은 채 로봇 전원을 켜는 일은 반드시 생긴다.**
절차로 막는다는 계획은 실패한다.

- 대체품: 1N5819 (1A, Vf 0.45V)
- ⚠ Vf 0.35~0.5V → VIN에 4.5~4.65V. AMS1117 드롭아웃 1.1V라 여유가 얇다.
  **XL4015를 5.0~5.2V로 트리밍하고 실측한다** (§4.5)
- 🔴 **부품이 없으면 5V→VIN을 아예 연결하지 않고 USB 전용으로 시험한다.** 미연결은 안전하다

#### ④ 470µF/25V 전해 — 강권

12V(+) / 전력 GND 사이. **극성 주의.**

없어도 당장 주행은 된다. 로직은 벅이 지킨다 (§4.5: *"배터리가 10V까지 처져도 5V는 안 흔들린다"*).
실제 역할은 **모터 역기전력 흡수**다. 라인 PD가 20ms마다 좌우 듀티를 바꾸므로 방향 전환이 매우 잦고,
그때마다 VM에 스파이크가 올라간다. TB6612 내부 다이오드만으로 받는 건 누적 스트레스다.

⚠ 만충 12.6V이므로 **16V 정격은 마진이 얇다. 25V로.** 470µF이 없으면 220µF 이상.

#### ⑤ `J_TOF` 4핀 커넥터 — 필수

| 핀 | 신호 |
|---|---|
| 1 | 3V3 |
| 2 | GND |
| 3 | SDA → G21 |
| 4 | SCL → G22 |

**직납이 아니라 커넥터로 한다.** VL53L1X는 위치를 반드시 다시 만진다 — FOV 27°에 코너 벽 감지 문제가 있고,
*"무광 검정 표면은 940nm를 흡수해 유효 거리가 준다"*(`센서_지도.md` 스펙 메모)라서 **소품 색까지 보고
각도를 조정**해야 한다. 직납하면 조정할 때마다 인두를 댄다.

### 2.4 `J_ENC_L` / `J_ENC_R` — 커넥터 생략

**G33 / G36 옆 패드 2쌍을 비워두고 실크펜으로 `ENC_L` `ENC_R` 라벨만 적는다.**

엔코더는 두 번 기각됐다(7/25, 8/02). 재검토 조건이 *"산포 실측 ±8cm 수준"*인데, 그때조차 대책 순서가
① APPROACH 속도↓(코드 한 줄) → ② 감속 마커 3단(테이프 한 줄) → ③ 엔코더다. D-9에 ③까지 갈 일은 없다 —
*"라인 PD 와 커플링된 루프를 하나 더 튜닝하는 일"*(§5.1)이다. 필요해지면 선 2가닥 직납.

### 2.5 변경하지 않는 것

VM 12V · 전력 GND · A01/A02 · B01/B02 — **기존 모터 직접 배선 유지.** 로직 레일에 넣지 않는다.
🔴 왼쪽 모터는 **교차 연결이 정방향**이다 (7/22 확정).

## 3. VL53L1X — DRIVE 배치 (§4-① 결정의 구현)

| 항목 | 값 |
|---|---|
| 인터페이스 | I2C 0x29 · **100kHz** |
| 핀 | G21(SDA) / G22(SCL) · `J_TOF` |
| 전원 | **3V3** |
| 풀업 | 🔴 **외부 풀업 금지** — Adafruit 보드 내장 |
| 배선 | 모터선과 **평행하게 길게 가지 않게** · 20cm 이내 |
| 임계 | 🔴 **구간별** — 직선 1000mm / 코너 300mm (`구역_마커_설계.md` §6.1) |

### 🔴 논블로킹 읽기 필수

Adafruit 라이브러리의 blocking `readRange()`는 타이밍 버짓만큼 막는다 — 롱 모드면 **최대 50ms**.
**20ms 조향 루프가 50ms 멈추면 라인에서 이탈한다.**

```cpp
// setup()
tof.startRanging();

// loop() — 매 주기
if (tof.dataReady()) {
    distance_mm = tof.distance();
    tof.clearInterrupt();
}
// dataReady()가 false면 그냥 지나간다. 절대 기다리지 않는다.
```

이것이 DRIVE 배치의 **유일한 실질 비용**이며, 코드 5줄 문제다.

### 스펙 메모

940nm VCSEL · 유효 ~4m(롱 모드) · FOV 27° · 3V3.
⚠ **무광 검정 표면은 940nm를 흡수해 유효 거리가 준다** — 장애물 소품은 밝은 색으로. 직사광에서도 성능 저하.

## 4. 결정 기록

### ① VL53L1X → DRIVE

7/31 결정(`센서_지도.md` §4) 유지. **8/14에 근거가 하나 더 강해졌다.**

🔴 **판정에 필요한 입력이 두 개인데, 둘 다 DRIVE에 있다.**

ToF 임계는 고정이 아니라 **구간 종속**이다(직선 1000mm / 코너 300mm). 순회 링의 코너에서는
진행 방향 1m 이내에 반드시 벽이 있어 고정 임계로는 코너마다 멈춘다. 그런데 **현재 구간을 정하는 것은
정지점 마커 순번**이고, **마커를 읽는 것은 DRIVE의 라인센서다.**

| | |
|---|---|
| **DRIVE** | 거리·구간이 한 칩 안에 있다 → `if (구간==코너) 임계=300;` 로컬 판정 끝 |
| **ENV** | 거리는 ENV, 구간은 DRIVE → **판정하려면 반드시 RPi를 경유해야 한다** |

7/31 근거 1이 "2홉 지연이 크다"였다면(*"1초 끊기면 30cm 전진"*), 지금은
**"ENV 단독으로는 판정 자체가 불가능하다"**이다.

**부차 근거**

- ENV가 부저를 갖게 되면서 역할이 갈렸다 — DRIVE = 읽고 **즉시 모터를 움직인다**(20ms),
  ENV = 읽어서 **보내고 알린다**(100ms). ToF는 전자다
- 라인센서 하네스가 이미 전방 하단으로 가 있어 ToF 케이블이 같은 경로를 탄다. I2C는 짧을수록 유리
- ADC 격리 논리는 적용되지 않는다 — VL53L1X는 디지털이라 모터 옆이어도 잃는 게 없다
- 강희 v9 자산(0x29 · 외부 풀업 금지 · INIT 에러 처리 · 700/350/150mm 검증 절차)은 코드·절차라 그대로 이관

**정직한 반대 논거**: CPU 여유는 ENV가 많다. DRIVE는 20ms PD + 마커 검출 + 하트비트로 이미 바쁘다.
→ §3의 논블로킹 읽기로 해소한다.

### ② MQ 분압 10k / 10k

§1.3 참조. 15kΩ 재고가 없어 10k·20k로만 구성 가능했고, **결과적으로 원래 정본(15k)보다 나은 값이 나왔다.**

### ③ MQ-2 = G35

강희 PDF(생성기 `SENSOR_NETS`)와 배선 정본(`amr_v9_...md`)이 서로 달랐다.
**AMR V10 스케치 확인 결과 PDF가 맞다 (2026-08-14).** → 배선을 G35로 하고 **배선 정본 문서를 갱신**한다.

부수 이점: G35는 입력 전용 핀이라 내부 풀업/풀다운 회로가 없어 ADC 누설 경로가 없고,
G33이 일부 보드에서 32.768kHz 크리스털과 겹치는 문제도 피한다.

### ④ WS2812B 미사용

**정리되는 것**

| 항목 | 결과 |
|---|---|
| 5V_LED 별도 한 쌍 | 불필요 |
| 🔴 경보 점등 시 MQ ADC 흔들림 (480mA 순간 부하) | **문제 자체가 소멸** |
| 레벨 정합(3.3V 데이터 vs 임계 3.5V)·330Ω·1000µF·다이오드 | 전부 불필요 |
| RMT 800kHz 타이밍 | 소멸 |
| **수집 게이트 「WS2812B 점등 시나리오 확정」** | **항목 제거** |

**⚠ 대가** — 시각적 경보 표시가 사라진다. 남는 경보 수단은 **부저(소리)**뿐이고,
"위험을 감지했다"를 화면으로 보여줄 수단은 **진우의 RPi 대시보드**만 남는다.
🔲 시나리오에 대시보드 인서트가 있는지 진우와 확인할 것 (연출 문제이며 납땜을 막지 않는다).

### ⑤ 능동 부저 → ENV G26

3핀 모듈로 확정되어 트랜지스터가 불필요해졌다. G26은 강희 배선 정본이 이미
*"GPIO26 예약 — 주변에 다른 신호를 배치하지 않고 라벨을 남긴다"*로 비워둔 핀이라, 예약을 그대로 채운다.

### ⑥ 배터리 분압 ×5.0

§2.3-② 참조. 33kΩ 없이 보유 저항만으로 구성되며, 선형성도 33k/10k보다 낫다.

## 9. 검증 절차 — 전원 투입 전/후

### 전원 투입 전 (멀티미터, 모듈·ESP32 전부 분리)

- [ ] 5V–GND 단락 없음
- [ ] 3V3–GND 단락 없음
- [ ] **5V–3V3 단락 없음**
- [ ] 인접 패드 납 다리 없음 (휴대폰 카메라 확대)
- [ ] 저항값 확인 — 분압 10k/10k, 배터리 40k/10k, STBY 풀다운 10k
- [ ] **STBY–GND 저항이 10kΩ으로 읽히는지**
- [ ] SS34 방향 (5V → VIN)
- [ ] 470µF 극성

### ENV 전원 투입 후

- [ ] XL4015 출력 **5.0~5.2V** 실측
- [ ] 🔴 **G34·G35 ADC 노드 전압 ≤ 3.3V** (배선 정본 안전규칙 9)
- [ ] 센서 **하나씩** 추가 — KY-026 → MQ-135 → MQ-2, 각 단계에서 이상 열·냄새·연기 확인
- [ ] KY-026: 화염 접근 시 G27이 **LOW로 떨어지는지**
- [ ] 부저: G26 HIGH에서 울리는지
- [ ] MQ 예열 3분 후 기준값 기록 (임계 재측정의 출발점)

### DRIVE 전원 투입 후 (🔴 바퀴를 바닥에서 띄우고)

- [ ] 🔴 **부팅 순간 모터가 움직이지 않는지** (STBY 풀다운 검증)
- [ ] G39 ADC × 5.0 = 배터리 실측 전압과 일치하는지 (멀티미터 대조 → 보정 계수 확정)
- [ ] VL53L1X: 700 / 350 / 150mm 거리 검증 (v9 절차 이관)
- [ ] `'v'` 실측 모드에서 S1~S5 — **검정에서 HIGH**
- [ ] 조향 방향: `']'` → 오른쪽 바퀴가 느려지고 왼쪽이 빨라짐. 반대면 **KP 부호가 아니라 모터 좌우 배선**을 의심
- [ ] 20ms 루프 주기가 ToF 추가 후에도 유지되는지 (논블로킹 검증)
