# ESP32 펌웨어 — 배선·설정 기준

**`DRIVE` 보드**(주행)의 배선과 확정값을 모아둔 문서. **핀을 바꾸면 여기부터 갱신할 것.**
보드는 **DOIT ESP32 DEVKIT V1** (ESP32-D0WD-V3), 포트 COM4, Arduino IDE 2.x + ESP32 코어 3.3.10.
**담당: 승환** (7/20 — AMR 주행이 강희에게서 이관됨. 환경 보드 `ENV` 는 강희).

> 🔵 **보드 호칭은 `DRIVE`/`ENV` 로 통일한다** 〔2026-08-01 확정〕.
> 번호(#1/#2)는 문서마다 반대로 쓰여 있어 쓰지 않는다 — 강희의 `amr_v9_4sensor_*` 문서가
> 말하는 「ESP32 #1 AMR」은 **이 문서의 보드가 아니라 `ENV`** 다.

## 1. 배선표

### 라인센서 — TCRT5000 5채널 (✅ 배선 완료)

| 모듈 | ESP32 | 보드 표기 |
|---|---|---|
| **VCC** | **3.3V** | `3V3` |
| GND | GND | `GND` |
| S1 (왼쪽) | GPIO 13 | `G13` |
| S2 | GPIO 18 | `G18` |
| S3 (중앙) | GPIO 19 | `G19` |
| S4 | GPIO 23 | `G23` |
| S5 (오른쪽) | GPIO 32 | `G32` |
| Near (선택·미연결) | GPIO 34 | `G34` |
| CLP (선택·미연결) | GPIO 35 | `G35` |

> 🔴 **VCC 를 5V 에 연결하지 말 것.** 모듈은 5V 사양이지만 출력이 5V 가 되어
> 5V 를 못 견디는 ESP32 GPIO 를 손상시킨다. TCRT5000 은 3.3V 에서 정상 동작한다.
>
> Near(IR 장애물)는 VL53L1X ToF 와 기능이 겹쳐 조달 계획상 불필요하다 (§4).
> CLP(범퍼 스위치)는 물리 충돌 백업으로 나중에 판단.

### 모터 — TB6612FNG (✅ 배선·방향 확인 2026-07-22)

- **모터 6가닥 중 빨강(+)·흰색(−)만 사용** — 모터 전원. 나머지는 엔코더로,
  파랑=엔코더 VCC(3.3V) · 검정=엔코더 GND · 노랑/초록=A/B 신호(1회전 11펄스)
- 🔵 **엔코더 미사용 확정 (2026-07-25).** 라인센서가 이미 폐루프를 닫고 있어 중복이고,
  엔코더의 주 이득(배터리 소모에 따른 속도 저하 보정)은 **배터리 전압 피드포워드**로 대체한다:
  `실제듀티 = 목표듀티 × (12.0 / 측정전압)` — 이미 계획된 G39 분압 회로만으로 구현된다.
  → 엔코더 4가닥은 **절연 후 모터에 결속**(수축튜브 + 케이블타이). 나중에 뜯어 쓸 수 있게 짧게 자르지 말 것
- 🔵 **단, 스톨 검출 슬라이스는 열어둔다 (2026-07-25).** 만능기판에 **JST-XH 3P 커넥터 `J_ENC_L`(G33 좌)·`J_ENC_R`(G36 우) 예약** (7/25 — 확장 6P 핀헤더에서 변경).
  「듀티를 주는데 200ms 동안 A상 펄스 없음 → 바퀴 걸림 → 정지·경고」— 속도 루프가 아니라 안전 진단이라
  **조향 PID 와 간섭하지 않고 튜닝 파라미터도 없다.** 채택 시 모터당 파랑(VCC **3V3**)·검정(GND)·노랑(A상) 3가닥.
  v5 의 안전 계층(팔 = Load 클램프 / 주행 = 스톨 검출)과 대칭을 이룬다
- **좌측 모터는 빨강·흰색을 교차 연결한 상태가 정방향** (7/22 확정 — 배선으로 해결, 코드 반전 없음)
- 모터 구동 중 라인센서 값 안정 확인 — 스타 그라운드 배선이 유효함
- 🔴 **캐패시터 사고 이력**: 역극성으로 장착됐던 220µF 가 VM 을 7V 로 끌어내렸다 (누설 전류
  + 브레드보드 접촉 저항). 해당 캐패시터는 폐기
- 🔵 **무캡 바닥 주행 정상 동작 확인** 〔2026-08-06 실측〕. **「캡 없이는 바닥 주행 금지」 규칙은 해제한다.**
  §3.1 의 전류 여유가 근거를 뒷받침한다 — JGA25-371 12V 권선은 **지속 스톨조차 1.0~1.2A** 로
  TB6612 연속 정격 안이다. 전원·배선 임피던스가 낮아 VM 강하가 여유 안에 들어왔다는 뜻이다.
  🔴 **단, 확인된 범위는 「모터만 물린 전원」 조건이다.** 같은 12V 레일에 **STS3215 ×6(피크 8~12A)**
  가 붙는 통합 구성은 아직 시험된 적이 없다 — 캐패시터의 세 번째 역할(공용 레일 출렁임 완충,
  v5 §3 근거 2)이 그대로 남아 있으므로 **통합 후 재확인**한다 (§3)

| TB6612 | ESP32 | 보드 표기 |
|---|---|---|
| PWMA | GPIO 25 | `G25` |
| AIN1 / AIN2 | GPIO 26 / 27 | `G26` `G27` |
| PWMB | GPIO 14 | `G14` |
| BIN1 / BIN2 | GPIO 16 / 17 | ⚠ **`RX2` / `TX2`** 로 인쇄된 보드가 많다 |
| STBY | GPIO 4 | `G4` |
| VCC (로직) | 3.3V | `3V3` |
| **GND — 로직 쪽 ×1** | GND | VCC·제어핀 줄. 로직 GND 레일로 |
| **GND — 전력 쪽 ×2** | — | VM·모터출력 줄. **12V (−) 로 직결** (벤치는 예외, 아래) |
| VM (모터) | **별도 12V** | ESP32 에서 뽑지 말 것 |
| A01/A02 | **왼쪽 모터** 빨강·흰색 (**교차 연결이 정방향**) | — |
| B01/B02 | **오른쪽 모터** 빨강·흰색 | — |

> 🔵 **GND 패드는 3개다. 3개 전부 연결한다** 〔2026-08-06 실측 확정〕.
> 7/22 에는 "2개"로 적었으나 실물은 3개였다. IC 안에 접지 네트가 셋이기 때문이다 —
> 데이터시트상 **PGND1(3·4핀)·PGND2(9·10핀)** 는 출력단 전력 접지, **GND(18핀)** 는 로직 접지.
> 보드가 이 구분을 그대로 노출하면 세 패드가 서로 안 이어져 있는 것이 정상이다.
>
> | 빠뜨린 것 | 증상 |
> |---|---|
> | 로직 GND | 제어 신호의 기준점이 없어 **방향·PWM 이 제멋대로** |
> | 전력 GND 둘 다 | 모터 전류의 귀환 경로가 없어 **모터가 안 돈다** |
> | 🔴 전력 GND 한쪽만 | **한쪽 채널만 안 돈다.** 배선을 몇 번 봐도 안 보이는 유형 — `q`/`r` 로 좌우를 따로 돌려 보면 잡힌다 |
>
> ✅ **벤치 검증 (2026-08-06)** — 3개를 전부 브레드보드 (−) 레일에 연결해 **정상 동작 확인.**
> 🔴 **단, 무부하 벤치 구성에서만 유효하다.** 바닥 주행에서는 전력 GND 2개를 굵은 선으로
> **12V (−) 터미널에 직결**해야 한다. 이유는 아래 「전원 분배」 — 브레드보드 접점 정격이
> 약 1A 인데 모터 스톨은 합산 2.4A 다. 벤치에서 되는 것이 바닥에서 되는 근거가 아니다.
>
> 어느 구성이든 두 접지가 만나는 점은 **12V (−) 한 곳뿐**이어야 한다 (스타 그라운드).
>
> **로직/전력 판별법** (모듈을 뽑고 무전원 상태에서) — ① 부저 모드로 세 패드를 서로 짚어
> 붙어 있는 것끼리 묶는다. ② 다이오드 모드로 **빨강=GND 패드 / 검정=A01** 을 대어
> **0.4~0.7V 강하가 나오면 전력 GND**(하측 FET 바디 다이오드가 PGND→출력 방향), `OL` 이면 로직이다.
> B 채널은 `B01` 로 같은 방법. PGND1 은 A01/A02 에, PGND2 는 B01/B02 에 반응한다.

- VM 입구에 **전해 캐패시터 ≥220µF/25V** — 🟡 **주행 필수 조건은 아님이 확인됨(8/6). 통합 구성 대비 권장.**
  흰 띠(−)가 GND 쪽 — 거꾸로 꽂으면 터진다
- 🔴 **13.5V 초과 금지** — 절대최대 15V, 4S 만충(16.8V)이면 즉사
- 적합성 판정은 §3.1 참조 (지속 스톨 1.2A 도 연속 정격 내)

### 전원 분배 — 브레드보드는 로직 전용

3V3 은 라인센서와 TB6612 VCC 가 함께 쓴다. TB6612 의 VCC 소비는 **1.8mA 이하**
(데이터시트 Icc, 3V 조건) 라 라인센서(약 60~90mA)에 비하면 없는 것과 같다.
모터 전류는 전부 VM→출력 경로로 흐르므로 3V3 부담과 무관하다.

### ① 벤치 구성 — ✅ 현재 상태 (2026-08-06 동작 확인)

```
ESP32 3V3 ──→ 브레드보드 (+) 레일 ──→ 라인센서 VCC · TB6612 VCC

12V (+) ─── 굵은 선 직결 ──→ TB6612 VM              🔴 브레드보드 경유 금지
12V (−) ─── 가는 선 ──→ 브레드보드 (−) 레일 ─┬─→ TB6612 GND ×3 (전력 2 + 로직 1)
                                            ├─→ ESP32 GND
                                            └─→ 라인센서 GND
TB6612 A01/A02 · B01/B02 ─── 직결 ──→ 모터          🔴 브레드보드 경유 금지
```

**GND 3개를 전부 레일에 꽂는 것으로 동작한다.** 바퀴를 띄운 무부하 시험에서는 모터 전류가
채널당 수백 mA 라 브레드보드 접점이 이를 감당한다. 방향 확인·라인센서 값 확인은 이 구성으로 끝난다.

### ② 바닥 주행 구성 — 🔴 아직 미적용 (§3)

```
ESP32 3V3 ──→ 3V3 레일 ──→ 라인센서 VCC · TB6612 VCC

12V (+) ─── 굵은 선 직결 ──→ TB6612 VM
12V (−) ─┬─ 굵은 선 직결 ──→ TB6612 전력 GND ①      ← 모터 귀환 전류
         ├─ 굵은 선 직결 ──→ TB6612 전력 GND ②      ← 데이지체인 금지, 터미널에서 만난다
         └─ 가는 선 ──→ 로직 GND 레일 ─┬─→ TB6612 로직 GND
                                       ├─→ ESP32 GND
                                       └─→ 라인센서 GND
TB6612 A01/A02 · B01/B02 ─── 직결 ──→ 모터
```

12V (−) 가 **스타 그라운드**다. 모터의 큰 전류는 굵은 선으로만 흐르고 로직 기준선에는
타지 않으므로, 모터 회전 시 라인센서 값이 흔들리는 것을 줄인다.

> 🔴 **①에서 ②로 넘어가는 것은 선택이 아니다.** 바닥에서는 마찰·경사·기동 전류가 붙어
> 스톨 합산 2.4A 까지 간다. 브레드보드 접점 정격은 약 1A 이고 접점당 접촉 저항이
> 수십~수백 mΩ 라 전압 강하로 나타난다 — **7/22 VM=7V 사건의 한 요인이 이것이었다.**

> 🔴 **12V 와 모터 출력은 브레드보드에 올리지 않는다.** 모터 전류가 스톨 시 2.4A 인데
> 브레드보드 접점 정격은 약 1A 라 발열·전압강하가 생긴다. 더 큰 이유는 안전으로,
> 12V 가 3V3 레일과 만나면 ESP32 와 라인센서가 동시에 파손된다.

### 배터리 감시 (미배선)

| | ESP32 | 보드 표기 |
|---|---|---|
| 33k/10k 분압 중점 | GPIO 39 | ⚠ **`SN`** (또는 `VN`) — EN 버튼 옆 |

전압 계수는 이론값 ×4.3 이므로 **멀티미터와 대조해 보정할 것.**

### 핀 배치 근거

- WiFi 사용 중 **ADC2 사용 불가** → 아날로그 입력은 전부 ADC1 (32~39)
- GPIO 34~39 는 **입력 전용** → 센서 입력에만 쓰고 출력 핀을 아낀다
- 스트래핑 핀 **0, 2, 5, 12, 15** 는 출력으로 쓰지 않는다 (부팅 모드 변경)
- GPIO **6~11 은 내장 플래시 전용** — 절대 사용 금지
- I2C (VL53L1X) 용으로 **GPIO 21/22 를 비워둠**

### 보드 표기 함정

| GPIO | 실크스크린 |
|---|---|
| 36 | `SP` / `VP` / `SVP` |
| 39 | `SN` / `VN` / `SVN` |
| 16 / 17 | `RX2` / `TX2` |
| 그 외 | `G13` 처럼 `G`+숫자 (`G` 하나만 = **GND**) |

  **지금 단계에서 캐패시터는 주행의 전제가 아니다.**
  ✅ 부품은 이미 있다 (`470µF/25V`, 8/3 조달 확인) — 아래 재확인 시점에 쓴다.
  🔴 **흰 띠(−)가 GND 쪽.** 거꾸로 꽂으면 터진다 — 지난번 사고가 정확히 이것이었다
  > 별도로 **`2200µF/25V`** 도 보유 중인데 그건 **RPi 쪽 DFR0753 출력용**이다 (v5 §1 ⑦). 여기 쓰지 말 것.
- 12V·모터 배선을 브레드보드 경유에서 **직결(22AWG 이상)** 로 교체
- **전력 GND 2개를 브레드보드 레일에서 떼어 12V(−) 터미널로 직결**, 로직 GND 1개만 레일에 남긴다
  > 🔵 두 항목 모두 **주행 차단 조건이 아님이 확인됐다 (2026-08-06)** — GND 3개를 전부 브레드보드
  > 레일에 꽂은 채로 바닥 주행이 정상 동작했다. 그래도 옮기는 이유는 전류가 아니라 **진동**이다:
  > Dupont 유지력은 20회 삽입 후 1.5N → 0.5N 이하로 영구 변형되고, 3분 원테이크 중 한 번 빠지면
  > 재촬영이다 (`만능기판_이전_가이드.md` 「왜 옮기는가」). 급한 항목은 아니지만 **촬영 전에는 한다**
- 배터리 감시 분압(33k/10k → SN) 연결 + 계수(×4.3) 멀티미터 보정

### 🟡 통합 구성에서 재확인할 것 (팔·RPi 가 같은 배터리에 붙은 뒤)

지금까지의 확인은 전부 **모터만 물린 전원**에서 이뤄졌다. 아래는 그 조건이 깨질 때 다시 봐야 한다.

| 항목 | 재확인 이유 |
|---|---|
| **VM 캐패시터 470µF** | STS3215 ×6 피크 **8~12A** 가 같은 레일에서 만드는 전압 출렁임 (v5 §3 근거 2). 모터 단독 시험으로는 재현되지 않는 조건 |
| **VM 실측 (`TP_VM`)** | 팔이 움직이는 순간의 최저값을 본다. v5 는 서보 피크 시 배터리가 **9.1V** 까지 처지는 것으로 잡고 있다 |
| **ESP32 리셋 여부** | 주행 중 재부팅은 테이크 폐기다. 팔 동작과 모터 기동이 겹치는 순간이 최악 조건 |

**판단 기준** — 팔 동작 중 VM 강하나 ESP32 리셋이 관측되면 그때 캐패시터를 단다. 부품은 이미 있다.

### 섀시 장착 후에

**라인센서 감도(가변저항) 최종 조절.** 지금 벤치에서 맞춘 값은 임시다.

TCRT5000 은 바닥과의 거리가 **3~10mm** 일 때만 제대로 동작하고 15mm 를 넘으면 둔해진다.
손으로 들고 맞춘 높이와 섀시 장착 높이가 다르면 임계값이 전부 어긋난다.

| # | 조건 | 이유 |
|---|---|---|
| 1 | **섀시에 고정한 뒤** 실제 주행 높이에서 조절 | 거리가 임계값을 지배한다 |
| 2 | 센서면이 **바닥과 평행**하게 장착 | 기울면 채널별 거리가 달라진다 |
| 3 | **촬영할 조명 아래에서** 조절 | 주변 적외선 영향 (§5.9 와 같은 이유) |
| 4 | 흰 바닥에서 `raw=0` 이 되는 지점 + 여유 | 검정은 어차피 잡힌다. 흰색 오검출이 기준 |

> 로봇암에서 **카메라 장착 후 손목을 재측정해야 했던 것과 같은 구조**다.
> 순서를 어기면 두 번 일하게 된다.

## 4. 운영 규칙

- **모든 펌웨어에 WiFi + ArduinoOTA 블록을 유지할 것.** OTA 없는 펌웨어를 한 번이라도
  올리면 무선 경로가 끊겨 USB 를 다시 꽂아야 한다.
- OTA `onStart` 콜백에서 **반드시 모터를 정지**시킨다 (STBY LOW). 업로드 중 마지막 PWM 으로
  계속 도는 것을 막는다.
- **USB 와 VIN 에 동시에 전원을 넣지 말 것.** DevKit V1 은 두 경로가 보드 내부에서 만나
  레귤레이터가 손상될 수 있다. 브레드보드 상태에서는 USB 를 먼저 뽑는다.
  → 🔵 **만능기판에서는 5V→VIN 사이에 SS34 쇼트키를 넣어 하드웨어로 막는다** (2026-07-29,
  `만능기판_이전_가이드.md` §4.5). 다이오드 시험을 통과하면 이 규칙은 지킬 필요가 없어진다.
- 🔵 **주행 시 ESP32 전원 = XL4015 #B 의 5.0V → SS34 → VIN** (2026-06-17 확정).
  12V 를 VIN 에 직결하면 온보드 AMS1117 이 2.2W 를 태워 열보호로 떨어진다.
  벅을 거치면 배터리가 10V 까지 처져도 5V 가 유지되어 **모터 기동 전류로 ESP32 가 리셋되지 않는다**.
- 🔴 **XL4015 는 2대. 용도를 고정하고 재조정하지 않는다** (2026-07-29).
  `#A = 7.4V 리더암 전용` / `#B = 5.0V AMR 전용` — 라벨을 붙이고 트리머를 매니큐어로 잠근다.
  7.4V ↔ 5V 왕복 트리밍은 **절차 자체가 위험하다** (한 번 잊으면 서보 6개 전멸, ₩178,315).
  리더암 연결 전에는 **매번** 출력이 7.4V 인지 멀티미터로 확인할 것.
- 벤치에서 모터를 돌릴 때는 **바퀴를 띄운다.**
- 시리얼 모니터는 **USB 로만** 된다. 무선 상태에서 로그가 필요하면 텔넷 로거나
  RPi TCP 브리지(`sensor_bridge`, §4)를 쓴다.

## 6. 트러블슈팅 — 7/21~22 실제 겪은 것

| 증상 | 원인 · 해결 |
|---|---|
| USB 업로드가 `Connecting....` 에서 멈춤 | **BOOT 버튼을 누른 채** 재시도 (DevKit V1 고질) |
| 시리얼 모니터 "Not connected" 인데 COM4 는 존재 | IDE 의 `serial-monitor` 프로세스가 포트를 점유한 채 UI 와 끊긴 것. 포트를 다른 것으로 바꿨다 되돌리거나 **IDE 재시작** |
| OTA 마지막에 `Unexpected response from device: '720'` | 전송 완료 후 ACK 파싱 문제 — **무해.** `100% Done` 이 떴으면 성공 |
| 무선 업로드가 조용히 실패 | Windows 방화벽. 핫스팟은 **공용 네트워크**로 잡히므로 허용 팝업에서 공용까지 체크 |
| IDE 에 네트워크 포트가 안 뜸 | mDNS 탐색 불안정 — IDE 재시작. 그래도 안 되면 espota 직접 호출 |
| ESP32 가 핫스팟에 재접속 안 됨 | 유휴 시 iPhone 이 핫스팟 광고를 멈춤 — **핫스팟 설정 화면을 한 번 열면** 재개. 펌웨어의 5초 재접속 루프가 대부분 흡수 |
| 전 서보/전 채널 무응답 (팔 쪽 경험) | 버스가 아니라 **전원·첫 커넥터**부터 볼 것. 뒤쪽 ID 만 죽으면 그 앞 연결부가 원인 |
| VM 전압이 12V 가 아니라 7V | ①역극성 캐패시터 누설 ②브레드보드 연선 접촉 저항 ③XL4015 **출력**(7.4V)을 잘못 가져옴 — 케이블 끝 개방 전압부터 재서 구분 |
