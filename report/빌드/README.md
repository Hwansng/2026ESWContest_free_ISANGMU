# 덱 빌드 스크립트

`HazardBot_개발완료보고서_2026-09-01.pptx` 를 만든 코드다. 파일을 직접 고치는 대신
여기를 고치고 다시 돌리면, design.md 규격(프레임 좌표·타입·색)이 전 장에 그대로 유지된다.

## 몇 장인가 — 22장이지만 본문은 20p

대회는 **표지와 인사 페이지(Thank you 등)를 20p 산정에서 제외**한다
(`PPT/양식/` 참조). 그래서 물리적 슬라이드는

```
표지(분량 제외) + 본문 20p + 마무리 인사(분량 제외) = 22장
```

쪽번호(`footer`)는 본문에만 붙는다. `build_deck.py` 의 `s_cover()` · `s_close()` 는
푸터를 부르지 않고, 본문은 `BODY_PAGES` 리스트 순서대로 `p01`~`p20` 이다.
**본문에 페이지를 더하거나 빼면 20p 를 넘기게 되니, 반드시 다른 페이지와 맞바꾼다.**

## 제출 직전에 채우는 값

`build_deck.py` 맨 위 세 줄이다. 비워 두면 슬라이드에 「확정 후 삽입」으로 찍히고,
빌드 끝에 무엇이 비었는지 알려준다.

```python
TEAM        = ""   # "<팀번호>_<팀명>"  — 표지 · 마무리
GITHUB_URL  = ""   # 04p — 대회 필수 항목
YOUTUBE_URL = ""   # 04p — 대회 필수 항목
```

## 09p 는 비워 둔 페이지다

`p09()` (파일 구성 · 주요 함수)는 **소스코드 최종 커밋 뒤에** 실제 트리와 함수로
채운다. 심사위원이 GitHub 저장소를 열어 대조하는 페이지라, 커밋 전에 채우면
실제 구조와 어긋난다. 쪽번호가 밀리지 않도록 자리만 잡아 두었다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `deck_lib.py` | design.md 를 python-pptx 도형으로 옮긴 프리미티브·컴포넌트. **어떻게 보이는가**만 있다 |
| `build_deck.py` | 22장의 내용과 배치. **무엇을 말하는가**가 여기 있다 |
| `prep_images.py` | `사진/`·`영상/` 원본에서 슬라이드용 이미지 7장을 뽑아 `img/` 에 넣는다 |
| `build_review.py` | 렌더 PNG 22장을 한 페이지 프루프 시트로 묶는다 (검토용). `python build_review.py <PNG폴더>` — PowerPoint에서 `s01.png`~`s22.png` 로 먼저 내보내야 한다 |
| `img/` | 위에서 뽑아둔 이미지. 원본이 안 바뀌면 다시 뽑을 필요 없다 |

## 다시 만들기

```powershell
cd "$env:USERPROFILE\OneDrive\바탕 화면\HazardBot\PPT\빌드"
python build_deck.py          # → ../HazardBot_개발완료보고서_2026-09-01.pptx
```

이미지 원본을 바꿨을 때만 `python prep_images.py` 를 먼저 돌린다
(`pip install imageio-ffmpeg pillow` 필요).

## 빌드가 스스로 잡아주는 것

`build_deck.py` 는 끝에 경고 목록을 찍는다. 글자가 상자 밖으로 넘칠 것 같으면
`[overflow]`, 한 줄 상자에서 가로로 넘치면 `[wide]` 로 알려준다.
**`no layout warnings` 가 나와야 정상이다.**

## 사본을 만들지 말 것

`build_deck.py` · `deck_lib.py` 의 **원본은 이 폴더 하나뿐이다.** 다른 곳에 복사해 두고
양쪽을 오가며 고치면, 오래된 사본이 새 사본을 덮어써서 수정이 조용히 되돌아간다.
(실제로 한 번 그렇게 날렸다 — pptx는 이미 새 내용으로 빌드돼 있는데 스크립트만
옛 내용이라, 다음 빌드에서 되돌아가는 상태였다.)

## 손대면 안 되는 것

- `deck_lib.py` 의 `BODY_X/Y/W/H`, `header()`, `footer()` 좌표 — design.md §3 프레임이다.
  본문 20장의 챕터명·제목·부제 위치가 픽셀 단위로 같은 이유가 이것뿐이다.
- `face()` — Pretendard 600은 윈도우에서 `Pretendard SemiBold` 라는 **별도 패밀리**이고
  700만 Bold 비트를 쓴다. 이걸 합치면 굵기가 무너진다.
- 상태색 배경(`HAZARD_BG` 등) — PowerPoint 도형 채움에는 알파가 없어서 14% 틴트를
  바탕색 위에 미리 합성해 둔 값이다. 바탕이 바뀌면 같이 계산해야 한다.

## 제출 형식

대회는 **PDF 로 변환해서** 낸다. 파일명은
`2026ESWContest_자유공모_<팀명>_개발완료보고서.pdf`.
PDF 변환 뒤 **04p 의 GitHub · YouTube 링크가 실제로 눌리는지** 반드시 확인할 것.

## 서체

Pretendard 4종(300/400/600/700)이 **설치되어 있어야** 제대로 열린다.
다른 PC에서 열거나 남에게 보낼 때는 PowerPoint에서
`파일 → 옵션 → 저장 → 파일에 폰트 포함` 을 켜고 다시 저장하는 편이 안전하다.
