## 목적과 범위

이 문서는 ESP32 #1 AMR v9에 다음 네 센서를 브레드보드로 한꺼번에 연결하고
Serial Monitor에서 동작을 확인하기 위한 작업용 가이드다.

- MQ-135 가스 센서
- KY-026 화염 센서
- Adafruit VL53L1X ToF 거리 센서
- MQ-2 가스·연기 센서

현재 Raspberry Pi 실물이 없어도 센서값 검증은 가능하다. RPi 메시지가
3초 동안 들어오지 않으면 v9 안전 로직에 의해 `RPI_TIMEOUT` 정지가
발생하지만, Serial Monitor의 네 센서값은 계속 갱신된다.

이 배선은 책상 위 정지 시험용이다. 브레드보드와 일반 점퍼선은 진동에
약하므로 주행 또는 반복 이동용 최종 배선으로 사용하지 않는다.

## 먼저 확인할 핵심 경고

1. 배선을 꽂거나 뺄 때는 ESP32 USB와 외부 5V 전원을 모두 끈다.
2. MQ-135와 MQ-2의 `AO`를 ESP32 GPIO에 직접 연결하지 않는다.
   반드시 이 문서의 `10kΩ/15kΩ` 분압 회로를 거친다.
3. MQ-135와 MQ-2의 히터를 ESP32 `3V3` 핀에서 공급하지 않는다.
4. ESP32, 센서 및 외부 센서 전원의 GND는 반드시 공통으로 연결한다.
5. 외부 전원의 `+5V`와 USB에서 들어오는 ESP32 `5V`를 임의로 서로
   직결하지 않는다. USB를 사용하는 동안에는 외부 5V를 두 MQ 센서의
   전원으로만 사용하고 GND만 ESP32와 공통으로 연결하는 구성이 가장
   단순하다.
6. 전원을 켜기 전에 멀티미터로 5V-GND와 3.3V-GND 단락 여부를 확인한다.
7. ESP32 ADC 입력에서 3.3V를 넘는 전압이 측정되면 즉시 전원을 끈다.

## 준비물

| 항목 | 수량 | 용도 |
|---|---:|---|
| ESP32 개발 보드 | 1 | ESP32 #1 AMR |
| 큰 브레드보드 또는 서로 연결한 브레드보드 | 1세트 | 전원·센서 배선 |
| MQ-135 모듈 | 1 | GPIO34 아날로그 입력 |
| KY-026 모듈 | 1 | GPIO27 디지털 입력 |
| Adafruit VL53L1X | 1 | GPIO21/22 I2C |
| MQ-2 모듈 | 1 | GPIO33 아날로그 입력 |
| 10kΩ 저항 | 2 | 두 MQ 센서 분압의 상단 저항 |
| 15kΩ 저항 | 2 | 두 MQ 센서 분압의 하단 저항 |
| 안정적인 정전압 5V 전원 | 1 | 두 MQ 센서의 히터 전원 |
| USB 데이터 케이블 | 1 | ESP32 전원·업로드·Serial |
| 디지털 멀티미터 | 1 | 단락, 전압 및 분압점 확인 |
| 점퍼선 | 충분히 | 전원과 신호 연결 |

두 MQ 센서를 동시에 켜면 히터 때문에 5V 전류 소모가 커진다. ESP32의 USB
또는 5V 핀이 두 MQ 센서를 안정적으로 공급할 수 있다고 가정하지 않는다.
두 번째 MQ 센서를 연결한 뒤 ESP32 재부팅, USB 끊김 또는 센서값 급변이
발생하면 코드보다 5V 전원 부족을 먼저 의심한다.

## 필요한 점퍼선

점퍼선은 양쪽 단자의 형태에 따라 선택한다.

| 연결 상황 | 점퍼선 |
|---|---|
| ESP32와 센서가 모두 브레드보드에 꽂힌 경우 | 수-수 |
| 센서의 수 핀을 브레드보드 밖에서 연결하는 경우 | 암-수 |
| 두 암 커넥터 사이를 연결하는 경우 | 수-수 또는 중간 헤더 |

- MQ-135, MQ-2 및 KY-026에 수 핀이 이미 납땜되어 있으면 센서를
  브레드보드에 직접 꽂거나 암-수 점퍼선을 사용한다.
- VL53L1X의 별도 6핀 헤더는 먼저 납땜해야 한다. 수 헤더를 납땜해
  브레드보드에 꽂으면 수-수 점퍼선을 사용할 수 있다.
- 전원선은 빨강, GND는 검정, 신호선은 다른 색으로 통일하면 오배선을
  줄일 수 있다.

## 브레드보드 전원 구성

브레드보드 전원 레일을 다음 세 종류로 구분한다.

```text
5V 센서 레일  ── MQ-135 VCC, MQ-2 VCC
3.3V 레일     ── KY-026 VCC, VL53L1X VIN
공통 GND 레일 ── ESP32 GND, 외부 5V GND, 센서 4개의 GND
```

권장 책상 시험 구성:

```text
USB PC ─────────────── ESP32 USB
                           │
ESP32 3V3 ──────────── 3.3V 브레드보드 레일
ESP32 GND ───────┬──── 공통 GND 레일
                 │
외부 5V GND ─────┘
외부 5V + ──────────── 5V 센서 레일
```

이 구성에서는 외부 전원의 `+5V`를 ESP32의 `5V` 핀과 연결하지 않는다.
일부 브레드보드는 긴 전원 레일이 가운데에서 끊어져 있으므로 멀티미터의
도통 모드로 양 끝이 실제로 이어져 있는지 확인한다.

## 센서별 배선

### 1. KY-026부터 연결

KY-026은 가장 간단한 디지털 센서이므로 첫 번째로 연결한다.

| KY-026 | 연결 |
|---|---|
| VCC | ESP32 3V3 |
| GND | 공통 GND |
| DO | GPIO27 |
| AO | 연결하지 않음 |

v9는 GPIO27이 `LOW`일 때 화염 감지로 판정한다. 모듈의 가변저항은 실제
시험 중 DO 표시 LED와 Serial의 `FLAME=YES/NO`를 보면서 조절한다.

### 2. MQ-135 연결

| MQ-135 | 연결 |
|---|---|
| VCC | 외부 5V 센서 레일 |
| GND | 공통 GND |
| AO | 분압 회로를 거쳐 GPIO34 |
| DO | 연결하지 않음 |

분압 회로:

```text
MQ-135 AO ── 10kΩ ──┬── GPIO34
                     │
                    15kΩ
                     │
공통 GND ────────────┘
```

브레드보드에서 `10kΩ의 끝`, `15kΩ의 위쪽 끝`, `GPIO34 점퍼선` 세 개가
반드시 같은 행에서 만나야 한다. 15kΩ의 나머지 끝은 공통 GND에 연결한다.

5V AO가 최대로 올라가도 이 분압점은 이론상 약 3.0V가 된다. 전원을 켠 뒤
GPIO34 분압점을 멀티미터로 측정해 3.3V를 넘지 않는지 확인한다.

기존에 MQ-135를 다른 전압 또는 분압 조건으로 시험했다면 ADC 값의 범위가
달라질 수 있다. v9의 `GAS` 값이 정상적으로 변하더라도 기존 임계값은 실제
촬영 환경에서 다시 확인해야 한다.

### 3. Adafruit VL53L1X 연결

VL53L1X의 6핀 헤더를 납땜한 뒤 다음 네 선만 연결한다.

| VL53L1X | 연결 |
|---|---|
| VIN | ESP32 3V3 |
| GND | 공통 GND |
| SCL | GPIO22 |
| SDA | GPIO21 |
| GPIO | 연결하지 않음 |
| XSHUT | 연결하지 않음 |

- v9의 I2C 주소는 `0x29`다.
- Adafruit 보드의 I2C 풀업을 사용하므로 별도 SDA/SCL 풀업 저항은
  추가하지 않는다.
- SDA와 SCL을 서로 바꾸지 않는다.
- 센서 전면의 작은 광학 창을 손가락이나 점퍼선으로 가리지 않는다.

### 4. MQ-2를 마지막에 연결

| MQ-2 | 연결 |
|---|---|
| VCC | 외부 5V 센서 레일 |
| GND | 공통 GND |
| AO | 분압 회로를 거쳐 GPIO33 |
| DO | 연결하지 않음 |

분압 회로:

```text
MQ-2 AO ── 10kΩ ──┬── GPIO33
                   │
                  15kΩ
                   │
공통 GND ──────────┘
```

MQ-135 회로와 마찬가지로 `10kΩ의 끝`, `15kΩ의 위쪽 끝`,
`GPIO33 점퍼선`이 같은 브레드보드 행에서 만나야 한다. 전원을 켠 뒤
GPIO33 분압점이 3.3V를 넘지 않는지 측정한다.

MQ-2의 DO는 v9에서 사용하지 않는다. DO를 연결하면 모듈 가변저항 설정과
5V 논리 레벨 때문에 불필요한 문제가 생길 수 있다.

## 전원을 켜기 전 검사

다음 검사는 ESP32 USB와 외부 5V 전원이 모두 분리된 상태에서 한다.

1. 5V 센서 레일과 공통 GND 사이가 단락되지 않았는지 확인한다.
2. 3.3V 레일과 공통 GND 사이가 단락되지 않았는지 확인한다.
3. 5V 레일과 3.3V 레일이 서로 연결되지 않았는지 확인한다.
4. MQ-135 AO에서 GPIO34까지 10kΩ을 거치는지 확인한다.
5. GPIO34에서 GND까지 15kΩ을 거치는지 확인한다.
6. MQ-2 AO에서 GPIO33까지 10kΩ을 거치는지 확인한다.
7. GPIO33에서 GND까지 15kΩ을 거치는지 확인한다.
8. VL53L1X SDA는 GPIO21, SCL은 GPIO22로 연결됐는지 확인한다.
9. GPIO26과 GPIO35에 이번 센서선이 연결되지 않았는지 확인한다.

## 단계별 전원 투입과 검증

한 번에 네 센서를 모두 꽂은 뒤 처음 전원을 넣지 않는다. 다음 순서로
하나씩 추가하면 오배선을 빠르게 찾을 수 있다.

### 1단계: 빈 전원 레일

1. 센서 네 개를 모두 분리한다.
2. ESP32를 USB에 연결한다.
3. 3.3V 레일이 약 3.3V인지 측정한다.
4. 외부 5V 전원을 켠다.
5. 5V 센서 레일이 약 5V인지 측정한다.
6. 외부 5V `+`와 ESP32 `5V`가 연결되지 않았는지 다시 확인한다.

### 2단계: KY-026

1. 모든 전원을 끈다.
2. KY-026을 연결하고 전원을 켠다.
3. Serial Monitor에서 `FLAME=NO`가 기본 상태인지 확인한다.
4. 안전한 광원 반응 시험으로 `FLAME=YES` 변화를 확인한다.

### 3단계: MQ-135

1. 전원을 끄고 MQ-135를 연결한다.
2. 전원을 켠 뒤 GPIO34 분압점이 3.3V 이하인지 측정한다.
3. Serial Monitor의 `GAS=<값>`과 `GAS_SENSOR=OK`를 확인한다.

### 4단계: VL53L1X

1. 전원을 끄고 VL53L1X를 연결한다.
2. 전원을 켜고 부팅 메시지에서 `[VL53L1X] READY`를 확인한다.
3. 물체를 약 700mm, 350mm, 150mm 위치에 놓고 `RAW_DIST`와 `DIST`가
   따라 변하는지 확인한다.

### 5단계: MQ-2와 네 센서 동시 동작

1. 전원을 끄고 MQ-2를 연결한다.
2. 전원을 켠 뒤 GPIO33 분압점이 3.3V 이하인지 측정한다.
3. ESP32가 재부팅되거나 USB 연결이 끊기지 않는지 확인한다.
4. 깨끗한 공기에서 MQ-2를 최소 3분간 예열한다.
5. ESP32 Reset 버튼을 누른다.
6. 약 12초 동안 기준값 보정이 끝날 때까지 기다린다.
7. Serial Monitor에서 `MQ2_CAL=READY`를 확인한다.
8. `GAS`, `FLAME`, `DIST`, `MQ2` 네 값이 동시에 계속 갱신되는지
   확인한다.

## Serial Monitor 확인 기준

v9 Debug 한 줄에는 다음 항목이 나타난다.

| 항목 | 의미 |
|---|---|
| `GAS` | MQ-135 이동평균 ADC 값 |
| `FLAME` | KY-026 감지 여부 |
| `GAS_SENSOR` | MQ-135 입력 유효 상태 |
| `RAW_DIST` | VL53L1X 최신 원시 거리 |
| `DIST` | 마지막 유효 거리 |
| `DIST_SENSOR` | VL53L1X 유효 상태 |
| `MQ2` | MQ-2 이동평균 ADC 값 |
| `MQ2_BASE` | 깨끗한 공기 기준값 |
| `MQ2_DELTA` | 현재 평균과 기준값의 차이 |
| `MQ2_CAL` | `CALIBRATING` 또는 `READY` |
| `MQ2_SENSOR` | MQ-2 입력 유효 상태 |
| `STATE`, `ACTION`, `FAULT` | 종합 안전 판정 |

RPi가 없으면 약 3000ms 뒤 `STATE=STOP`과 RPi timeout fault가 발생하는
것이 정상이다. 이때도 위 네 센서값은 계속 변해야 한다.

현재 `BAT=12.00V`는 실제 배터리 측정값이 아니라 v9에 남아 있는 고정
소프트웨어 값이다. 네 센서 완료 여부에 포함하지 않는다.

송신 메시지 형식:

```text
<SENS,gas,flame,battCv,stateCode,actionCode,faultCode,distanceMm,mq2Raw,checksum>
```

## 센서별 최소 반응 시험

| 센서 | 시험 | 성공 기준 |
|---|---|---|
| MQ-135 | 주변 공기 변화에 노출 | `GAS`가 고정되지 않고 변화 |
| KY-026 | 감지 방향에 안전한 광원 접근 | `FLAME=NO/YES` 전환 |
| VL53L1X | 물체를 700/350/150mm로 이동 | `DIST`가 거리에 맞춰 변화 |
| MQ-2 | 충분히 예열한 뒤 통제된 소량 연기 반응 확인 | `MQ2_DELTA` 증가 |

위 시험은 센서 반응 확인용이며 정량 농도 측정이나 안전 인증을 의미하지
않는다. 인화성 가스나 실제 위험물을 만들거나 밀폐 공간에 분사하지 않는다.

## 문제 해결

### 두 번째 MQ 센서를 연결하면 ESP32가 재부팅되거나 USB가 끊김

- 외부 5V 전원의 전류 여유를 확인한다.
- 5V 레일이 센서 연결 전후에 크게 떨어지는지 측정한다.
- 두 MQ 센서를 ESP32 3V3에서 공급하지 않았는지 확인한다.
- USB 5V와 외부 5V를 잘못 직결하지 않았는지 확인한다.
- 공통 GND는 유지하되 5V 전원 경로를 다시 분리한다.

### MQ ADC 값이 0 부근에 고정됨

- AO, 10kΩ, 분압 중간점 및 GPIO 연결이 한 행에 맞는지 확인한다.
- 15kΩ이 GND가 아닌 다른 레일에 연결되지 않았는지 확인한다.
- 센서 VCC와 GND를 확인한다.

### MQ ADC 값이 계속 최대치 부근임

- AO가 GPIO34 또는 GPIO33에 직접 연결되지 않았는지 즉시 확인한다.
- 분압 중간점 전압을 멀티미터로 측정한다.
- 15kΩ 하단 저항이 공통 GND에 실제로 연결됐는지 확인한다.

### KY-026이 항상 감지 또는 항상 미감지

- v9가 LOW active로 해석한다는 점을 확인한다.
- 모듈 가변저항을 천천히 조절한다.
- AO가 아니라 DO를 GPIO27에 연결했는지 확인한다.
- VCC가 3.3V인지 확인한다.

### VL53L1X가 `INIT_ERROR` 또는 `RANGE_START_ERROR`를 출력

- VIN=3.3V, GND=공통 GND인지 확인한다.
- SDA=GPIO21, SCL=GPIO22인지 확인한다.
- 6핀 헤더 납땜 불량이나 핀 간 브리지를 확인한다.
- GPIO와 XSHUT이 다른 레일에 닿지 않았는지 확인한다.
- 전원을 껐다가 배선을 수정한 뒤 다시 켠다.

### MQ-2가 `MQ2_CAL=READY`로 바뀌지 않음

- 먼저 깨끗한 공기에서 최소 3분간 예열한다.
- 예열 후 ESP32 Reset 버튼을 누른다.
- 약 12초 동안 기다린다.
- `MQ2_SENSOR=ERROR`라면 AO 분압 회로와 GPIO33을 확인한다.

### 센서값은 변하지만 `RPI_TIMEOUT`이 표시됨

현재 RPi가 없기 때문에 정상적인 안전 fallback이다. 센서 검증은
`GAS`, `FLAME`, `DIST`, `MQ2` 필드가 계속 갱신되는지로 판단한다.

## 촬영 전 최종 체크리스트

- [ ] 5V 센서 레일과 3.3V 레일의 실제 전압을 측정했다.
- [ ] ESP32, 외부 5V 전원 및 센서 네 개의 GND가 공통이다.
- [ ] 외부 5V `+`와 USB 5V를 임의로 직결하지 않았다.
- [ ] MQ-135 AO는 10kΩ/15kΩ 분압 후 GPIO34로 들어간다.
- [ ] MQ-2 AO는 10kΩ/15kΩ 분압 후 GPIO33으로 들어간다.
- [ ] GPIO34와 GPIO33 분압점이 모두 3.3V 이하이다.
- [ ] KY-026 DO는 GPIO27이고 AO는 비어 있다.
- [ ] VL53L1X SDA는 GPIO21, SCL은 GPIO22다.
- [ ] VL53L1X GPIO와 XSHUT은 비어 있다.
- [ ] GPIO26과 GPIO35를 센서 배선에 사용하지 않았다.
- [ ] VL53L1X가 `[VL53L1X] READY`를 출력한다.
- [ ] MQ-2 예열 후 `MQ2_CAL=READY`를 확인했다.
- [ ] 네 센서값이 한 Debug 줄에서 계속 갱신된다.
- [ ] 두 MQ 센서를 동시에 켜도 ESP32와 USB가 안정적이다.
- [ ] `RPI_TIMEOUT`과 실제 센서 오류를 구분할 수 있다.
